# 魔兽管家拾取记录 1.1.1

适用正式服 12.1.5。本版须搭配 REQ-199 网站版本（资源版本 20261117.144）及 SQL 47/48；网站尚未部署时不要把新版导出包提交到旧版页面。插件原生界面、国服观察 API 与真实交易仍待统一真机验收。

## 日常使用

1. 启用插件后默认自动记录。点击小地图背包图标，或 ESC → 设置 → 插件 → 魔兽管家拾取记录；可勾选暂停/开启，不需宏。
2. 团本结束、等待物品信息计数归零后，点“导出到网站”并复制。无需 reload，也无需找本地文件。
3. 网站 → 团队管理 → 装备分配 → 拾取记录 → 导入拾取。粘贴并解析，查看观察清单差异；可先提交有效拾取，晚拾取后重新导出并提交。
4. 所有公会成员可提交，管理者可单件或批量核对、分配。最终获得者必须明确确认；拾取人可能是代拿者。
5. 保存前逐件选择待分配、已分配或无人需求。已有分配通过“查看分配”修改；本批成功项不重建，失败项可修正后重试。
6. 确认云端保存后才考虑清空本机记录。清空会同时删除本机拾取和观察/交易证据，有二次确认；不会删除网站记录。

## 掉落与晚拾取

- 仅普通/英雄/史诗团队副本。随机团、野外、地下城与未知难度不采集。
- 按完整物品链接读取装等和绑定；战团绑定排除。绑定/装等不全最多重试10秒，仍不全保留待核对，不纳入有效拾取导出。
- C_LootHistory 提供本机观察清单；Roll获胜不等于实际拾取。未知总数明确显示未知，数量一致不证明全团已捡齐。
- 晚拾取仅在同副本/难度、24小时内完整链接和剩余清单唯一匹配时关联原首领；多个首领候选时留空。清单缺失时保留原180秒击杀窗口候选，需管理者核对。
- 不从未来掉落池推算实际掉落数量；不同难度、变体、真实多件分开保留。

## 交易边界

- 仅记录本机亲自参与、且本机过去24小时内已有相同完整链接拾取记录的装备交易。不会监听全团其他人的交易，也不采集金币或附魔服务。
- 双方接受且收到交易完成提示才记成功；明确取消记取消；仅关闭窗口记结果未确认。缺失证据时人工确认。
- 网站按同变体、团本/难度和24小时范围展示参考，可能存在相同变体多件或多方重复观察，不能据此自动指定最终获得者。
- 成功交易不是分配指令；不会自动变更公会装备记录或心愿单。

## 保存与兼容

- 导出为 schemaVersion 2（rows + evidence），网站继续兼容旧数组；1.0.4/1.0.5/1.0.6已核验的旧记录可继续导出。1.0.3及以前缺原链接记录不自动修复。
- 原链接中的 `\u007c` 是合法 JSON 转义，网站自动恢复，不要手动替换。
- 拾取最多2000条；观察/交易最多500条，超额淘汰最旧并提示。请及时导入；不能补回安装前、暂停或漏收事件。
- 导出复制读取内存；SavedVariables 仍由游戏在重载、退出登录或正常退出时落盘。没有自动上传程序。
- `/wbc` 打开面板；`/wbc export` 导出；`/wbc count` 查看计数；`/wbc clear` 二次确认清空。
