# 运营测试步骤卡 · WoWButler Data Exporter（任务书 #26 WP1 验收）

> 目的：验证插件在真实游戏内可用。预计 15 分钟。每步做完在「结果」栏打 ✅/❌，❌ 请截图并反馈顾问侧。

## 准备

| # | 步骤 | 预期 | 结果 |
|---|---|---|---|
| 1 | 把 `WoWButlerExporter` 文件夹复制到 `_retail_\Interface\AddOns\` | 文件夹内含 .toc / .lua / README | ☐ |
| 2 | 登录界面「插件」里勾选本插件（必要时勾「加载过期插件」） | 列表可见「魔兽管家数据导出器」 | ☐ |
| 3 | 进入游戏输入 `/wjdc` 回车 | 聊天框显示用法提示 | ☐ |

## 主链路实测

| # | 步骤 | 预期 | 结果 |
|---|---|---|---|
| 4 | 输入 `/wjdc all`，等待进度滚完 | 聊天框逐副本提示「团本：xxx（N 个 BOSS，M 件掉落）」「大秘境：…」，最后提示「已导出，请 /reload」；1.0.7 起团本段会先提示「四难度档采集已启用」并逐 BOSS 提示「四档重扫完成（N/M 件带档）」，**总时长约为旧版 4 倍（15–20 分钟量级）属预期**；若出现红字「N 件物品未缓存记 failed」，/reload 后重跑一次再判定；若出现红字「四档采集通道不可用」，属自动回退单档，文件照常可用但请截图反馈 | ☐ |
| 5 | 输入 `/reload` | 界面重载，无报错弹窗 | ☐ |
| 6 | 打开 `WTF\Account\<账号名>\SavedVariables\WoWButlerExporter.lua` | 文件存在，开头为 `WJDCDump = {`，含 `meta`、`raids`、`dungeons` 段（1.0.4 起不再含 `tier` 段；1.0.6 起 loot 行含 `primary_values`/`secondary_values` 数值字段，如 `["secondary_values"] = { ["爆击"] = 300, ["急速"] = 100 }`；1.0.7 起**团本** loot 行另含 `primary_tiers`/`secondary_tiers` 四档字段，如 `["secondary_tiers"] = { ["lfr"] = { ["爆击"] = 280 }, ["normal"] = { ["爆击"] = 300 }, … }`，只记存在的档；大秘境 loot 行无 tiers 字段） | ☐ |
| 7 | **抽查 BOSS ①**：游戏内打开副本手册（冒险指南）→ 任选一个当前团本 BOSS → 对掉文件里同名 BOSS 的掉落列表 | 件数一致（正常量级每 BOSS 6–12 件），抽查 3 件装备名称与手册一致 | ☐ |
| 8 | **抽查 BOSS ②**：换一个大秘境副本 BOSS 同上核对 | 件数一致，名称一致 | ☐ |
| 9 | **数据质量抽查**：文件中任选 3 件装备，核对 `ilvl` 与游戏内手册显示装等一致（应为当前赛季真实装等量级，不是 44 之类小数字）；文件内不应出现 `type = ""` 的空类型行 | ilvl 一致、无空 type 行；若 BOSS 条目带 `failed` 列表，聊天框应有对应红字报告（两者必须同时出现，缺一即 ❌） | ☐ |
| 10 | 输入 `/wjdc me` → `/reload` → 重新打开导出文件 | 文件只含 `meta` 和 `me`，角色名/服务器/职业/专精/等级/装等/公会名与本人角色面板一致（装等允许 ±1 的四舍五入差） | ☐ |
| 11 | 把第 6 步（/wjdc all）与第 10 步（/wjdc me）两次文件分别发给顾问侧 | 注意：`/wjdc me` 会覆盖文件，**请先备份 all 产物再跑 me**，或跑完 me 再跑一次 all | ☐ |

## 判定

- 全部 ✅ → WP1 游戏内验收通过，管道进入 WP2 实文件端到端（WP3 彩排）。
- 任何 ❌ → 截图 + 导出文件（若已生成）发顾问侧，注明步骤编号。

## 注意事项

- 测试期间**不要**用记事本编辑导出文件。
- 大秘境内、战斗中跑命令不影响结果，但建议在主城空闲时跑，避免卡顿。
- 插件不联网、不读账号数据，只读游戏自带副本手册，可放心常驻。
