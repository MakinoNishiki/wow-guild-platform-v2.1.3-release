# PRD 评审

按 7 个维度评分 PRD 文档，输出结构化评审报告。

## When to Activate

- 用户提供 PRD 文件路径或目录，要求进行评审
- 用户说"评审"、"review"、"检查需求文档"、"完备性检查"
- `/prd-review <path>`

## Workflow

### Step 1: 确认入参

**无论用户是否在命令中提供了路径，都必须强制询问：**

> 请提供要评审的 PRD 文件路径或目录（如 `docs/prd/需求.pdf` 或 `docs/prd/`）

等待用户明确输入路径后再继续，不得跳过此步骤、不得自动猜测路径。

- 单个文件：直接 Read
- 目录：Glob 列出 `.md` / `.pdf` / `.txt`，跳过 `cr-report-*.md`，逐一读取
- PDF 超过 10 页时分批读取（每次最多 20 页）

### Step 2: 读取评审规则，按维度评审

Read `review-criteria.md` 获取完整评审规则（7 个维度的检查项、评分标准、缺口定级）。

对每个维度打分（0-10），记录发现的缺口。

### Step 3: 计算综合分

```
加权综合分 = Σ（各维度得分 × 权重）
```

**结论判定**

| 条件 | 结论 |
|------|------|
| 综合分 ≥ 7 且无高风险缺口 | **通过** |
| 其余情况但高风险缺口 ≤ 2 | **有条件通过** |
| 综合分 < 5 或高风险缺口 > 2 | **不通过** |

### Step 4: 写入报告

1. 确认 `docs/prd/` 存在，不存在则 `mkdir -p docs/prd/`
2. **文件命名规则**：
   - 单文件：`cr-report-{原始文件名（不含扩展名）}.md`
     - 例：`仓库主数据改造需求及产品方案.pdf` → `cr-report-仓库主数据改造需求及产品方案.md`
   - 多文件：每个文件按上述规则生成独立报告，另生成 `cr-report-index.md` 汇总索引
   - 已存在同名报告则追加日期后缀 `_YYYYMMDD`
3. **多文件时额外生成 `cr-report-index.md`**，格式：

```markdown
# PRD 评审索引

**评审日期**：YYYY-MM-DD

| 文件名 | 需求名称 | 结论 | 综合分 | 高风险 | 报告链接 |
|--------|---------|------|:-----:|:-----:|---------|
| {原始文件名} | {需求名称} | {结论} | {分数} | {n} | [查看]({报告文件名}) |
```

4. 报告结构：

```markdown
# PRD 评审意见

**需求名称**：{从 PRD 中提取}
**评审日期**：{YYYY-MM-DD}
**评审人**：AI 草稿，待人工复核
**评审结论**：通过 / 有条件通过 / 不通过

> {一句话总结}

**核心问题速览（评审会 30 秒）**
1. {高风险问题1的简要描述，标注缺口编号如 H1/H2}
2. {高风险问题2...}
（无高风险缺口时此块写"无高风险缺口，建议关注中风险项"）

---

## 高风险缺口（必须补充，否则不可开发）

| 序号 | 维度 | 问题描述 | 建议补充内容 |
|------|------|---------|------------|

## 中风险缺口（建议开发前补充）

| 序号 | 维度 | 问题描述 | 建议补充内容 |
|------|------|---------|------------|

## 低风险问题（可后置）

| 序号 | 维度 | 问题描述 |
|------|------|---------|

---

## 综合评分

| 维度 | 权重 | 得分（/10） | 加权分 |
|------|:---:|:---:|:---:|
| 业务背景       | 10% | - | - |
| 页面/模块说明  | 15% | - | - |
| 核心流程       | 20% | - | - |
| 关键字段说明   | 20% | - | - |
| 校验规则       | 15% | - | - |
| 异常场景       | 10% | - | - |
| 状态流转规则   | 10% | - | - |
| **加权综合分** | 100% | — | **-** |

## 各维度评分说明

### 业务背景（x 分）
...
```

### Step 5: 输出摘要

报告写入后，在对话中输出：

```
评审完成：{需求名称}
结论：{结论}（综合分 {x.xx}/10）
高风险 {n} 项 | 中风险 {n} 项 | 低风险 {n} 项
最低分维度：{维度名}（{x} 分）
报告：docs/prd/cr-report-{原始文件名}.md
```

### Step 6: 流程图建议（按需）

若评审过程中发现以下任一情况，在摘要末尾追加建议：

- 流程图以截图/图片形式嵌入，文字不可读
- 核心流程、状态流转仅有文字描述，无可视化图示
- 流程图存在与文字规则不一致的风险

**追加内容**：

```
💡 流程图建议：当前流程图为图片格式，建议改用 Mermaid 语法编写，
   可直接在文档中维护并保持可读性。
   在线编辑器：https://mermaid.live/
   支持：流程图（flowchart）、时序图（sequenceDiagram）、状态图（stateDiagram）
```
