# prd-prep 经验吸收：接口/任务/函数模块使用原则

**来源项目**: sample 非现金支付比例管控
**吸收日期**: 2026-03-26
**适用文档**: prd-prep SKILL.md

---

## 说明

接口、任务、函数三个模块的主要目的：提醒产品经理不要遗漏相关内容评估。
不是让产品经理完成具体的接口定义或函数声明，那是 TRD 阶段研发的工作。

---

## 正确粒度定义

**达到的程度**：

- 接口：识别“此流程应当有这段后端交互，大致用于什么场景”
- 任务：识别“需求涉及定时任务，需要分别说明具体用途和调度顺序”
- 函数：识别“应该有此功能，大致用于什么场景”

**不应达到的程度**：

- 具体接口路径、请求参数、返回字段定义
- 函数声明、入参类型、返回值类型
- 调度表达式（cron 表达式等）

内容应贴近自然语言描述，而非技术语言。

---

## 进行个人确认和交互的规则

这三个模块未必存在。在 prd-prep 收集信息时，或在 prd-write 输出时，
skill 应主动向产品经理确认：

- 是否需要预留/补充/跳过接口说明
- 是否需要预留/补充/跳过任务调度说明
- 是否需要预留/补充/跳过可复用函数说明

直接代为生成会导致 PRD 冗余、丢失重点。

---

## 函数/脚本模块的正确范围

仅收录满足以下全部条件的逻辑单元：

1. **无前端页面承载**：不在任何 PRD 功能章节中独立描述
2. **可跨功能复用**：不绑定在单一功能流程内，可被多个场景调用
3. **主数据查询类 / 参数解析类 / 工具性质**：常见形态

计费/业务引擎内部步骤应在主 PRD 功能章节描述，不放入此模块。
