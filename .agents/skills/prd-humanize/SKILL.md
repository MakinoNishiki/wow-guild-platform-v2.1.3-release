# Part 1 · 内容构建

> 解决①：从完整版做**信息提炼**与**结构降维**——抓主干、删噪音、按读者重组。

## 1.1 快速开始

**何时用**：已有一份完整版 PRD（字段/接口/交互全细节），读者反馈"太长、没重点、噪音多、读不懂"，需要一份面向人读的导读版。

**输入**：① 完整版 PRD 路径（必备）；② 其章结构 / 锚点（供人类版索引回跳）。

**产物**：一份人类版（导读）PRD（`.md`），与完整版**章级 / 目录 1-1 映射**；自然语言为主；默认只呈现改动后与改动点，细节索引完整版。**它是初稿**，交人类裁颗粒度后定稿。

## 1.2 Skill 定位

| 维度 | 完整版（上游产出） | 人类版（本 Skill 产出） |
|------|------------------|----------------------|
| 读者 | 开发、其他 Agent、联调、测试 | 评审、决策、业务沟通 |
| 语言 | 含字段/接口/代码/标记 | 自然语言为主，避免代码/黑话/标记 |
| 内容 | 现状 + 对比 + 动作 + 影响面 + 回归用例 全细节 | 只看改动后与改动点，细节索引完整版 |
| 权威 | **规格权威** | 导读，不作规格依据 |
| 生成 | 主写 | **由完整版派生 + 人工润色** |

> 本 Skill **不**做需求澄清、现状梳理、方案设计——这些已由完整版承载。它只做"翻译降维"。

## 1.3 启动检测

动手前确认：

1. **完整版路径**已知、可读。缺失则本 Skill 不适用（先用 `prd-incremental-on-asis` / `prd-write` 产完整版）。
2. **输入类型与目录映射**：
   - 输入**是 PRD** → 应符合**九章结构**；人类版章节与之 **1-1 映射**。
   - 输入**非 PRD** → 允许 skill / 模型自行解读、获取其目录；人类版在**目录层面 1-1 映射**。
   > 本技能**聚焦 PRD**。非 PRD 仅作最简兜底，不在此展开"任何文档通用解读"；若需长期处理非 PRD 场景，应基于本技能**另演化新技能**，而非在此抽象。
3. **改动点清单**：完整版 §5（方案详情）下有哪些改动点（5.1 / 5.2 …），人类版逐点对应。
4. **锚点**：完整版各章/各改动点有稳定可引用的标题或编号，供人类版索引。
5. **辅助素材盘点（v1.3 必做）**：识别完整版**引用 / 关联的辅助说明素材**——原型图（HTML 文件 / 截图）、可信来源文件（外部链接 + 可引全文）等。列"素材清单 + 对应章节"，供派生时**直接引入**（见 §1.4 步骤 5）。**有现成素材却不收集是大问题**——会逼着人类版全盘自写，失去降维意义。

检测后向用户简述："将基于 <完整版路径> 派生人类版，目录映射如下 <列章>，改动点 <列点>。"，再开始。

## 1.4 派生步骤

1. **建骨架（目录 1-1）**：人类版章名/目录对齐完整版。每章占位，先不填。
2. **写摘要（§一）**：用 3~8 行讲清"本期做哪几件事"。**只讲做什么**——**默认不写"本期不做 / 不支持 / 不需要"等负面排除项**（非特别强调不写；PRD 是讲做什么）、不写开放问题（这些留完整版）。
3. **背景（§二）**：一段话讲**触发动机（为什么迁 / 为什么做）+ 目标**（要实现什么）；**可大体一提"做了哪些改动"、也可不提**（不强求铺或不铺，影响不大）。统一收在背景，不铺到各改动点。
4. **逐节写"现状规则 + 说明"（§五）**：完整版 §5 有 N 个子节，对应 §五的 N 节，每节——
   - **标题用简短功能名**（如"OA 账本调整表单""审批流""账务处理"）；**禁用"A：B"结构**（"功能名：一句说明"——人类不这么说明一件事）；
   - **正文讲现状规则**：用**主谓宾端到端**描述——**谁（人或某个系统）在什么环节、按什么规则做什么**，把这件事讲完整；**不写"从 X 改成 Y"的 diff 式**（如"三层→两层""取消金额矩阵"——读者不需要知道旧版，只讲现在怎么运作）；逐条清单叫"**规则说明 / 特殊场景说明**"，不叫"改动点"；
   - **正例为主**即可（目的是说明情况）；**反例仅当边界易模糊 / 反例不显然时才给**（标注"不应当发生"），否则可省；
   - 默认**不写**标签、不写现状对比、不写连带 / 红线、不写回归、**不写"不做 / 不支持"等负面排除项**（均按需才补，见 1.5）。
5. **改动后形态 = 引入现成素材优先（v1.3 核心）**：人类化**不能只读 PRD 原文**——完整版引用 / 关联的辅助素材（§1.3 步骤 5 盘点的原型 HTML / 截图 / 可信来源文件链接）**该引入就直接引入**，不要自己重写描述：
   - **原型 / 表格**：飞书 `<view><file>` 嵌原型 HTML、`<sheet>` 嵌在线表；.md 载体则给"见原型 xxx.html（某 tab）"+ 路径。
   - **可信来源文件**：参考链接 + 可引全文（如对账函外部 docx）；标清来源对应，便于跳转溯源。
   - **截图**：飞书可嵌图；.md 放图片路径 / 链接（形态随载体）。
   - 实在没有现成素材，才自己描述。**有现成素材却不引入 = 失去人类化意义**（只能全盘自写）；引用对不对、要不要，留人类确认时调。
   > 🔴 **硬约束（贴文本时禁止省略）**：贴正文类内容（模板 / 邮件 / 对账函）**必须完整原文**，禁止删节 / "……"省略 / 自行精简；读者要能直接复制使用。
6. **塌缩其余章**：竞品 / 迭代 / 运营若无内容写"无"；主逻辑一句话指向 §五；沟通记录、参考资料**仅索引完整版对应章**。
7. **术语表取子集**：只收频繁 / 多处引用的概念，每条一句话；偶发概念用正文自然语言说清，不入表。
8. **过 Part 2**：出初稿后，按 Part 2 的语言规范清单 + 评分过一遍，去 AI 腔、保可读性，再交人工定稿。

## 1.5 派生规则速查（结构 / 取舍）

- **目录 1-1 映射**，内部结构可不同（不强行统一，否则人类版为对齐而臃肿）。
- **颗粒度默认从简**：现状 / 改动前**默认省略，直接给改动后**；仅当"不看现状无法理解改动"或"现状无法从原型 / 演示获得"时才补现状与对比。
- **不写"从旧版改成新版"的对照**（三层→两层、取消 X、改 Y 等）——人类版只讲现在怎么运作，读者不需要知道旧版；逐条清单用"规则说明 / 特殊场景说明"，不用"改动点"。
- **改动后形态优先引入现成素材**（嵌原型 / 在线表 / sheet、引用可信文件+全文、放截图），其次才自写；贴文本不得自行省略。**有素材不引入是 v1.3 头号反面**。
- **默认省略负面排除项**：「不做 / 不支持 / 不需要 X」等排除 / 免责表述，非特别强调默认不写——PRD 是讲做什么，不是讲不做什么。
- **未定 / 待确认项如实标注**"仍在确认中 / 后续补充"并指向来源（收集表等），**不硬凑表格、不编造默认值**。
- **纯"不变 / 沿用"不写**。红线 + 原因、连带影响 / 连带改动**按需保留**（非每篇必含）。**回归测试默认不进人类版**（完整版保留用例；人类确需再补一句话场景）。
- **细节外包**：字段规范、交互细节外包给原型图 + 演示；后端调度 / 函数只说"有这东西 + 解决什么问题"；深读处**索引完整版**。

## 1.6 一致性与权威

- 人类版与完整版**各自概括应得出相同的对象、概念、范围、逻辑结论**。
- 一致性靠"同源派生"构造保证——人类版所有内容须可在完整版找到出处，**不得引入完整版没有的新事实**。
- 冲突时**以完整版为准**。完整版更新后，人类版需重新派生 / 同步。

## 1.7 派生 ≠ 免人工

本 Skill 产出的是**人类版初稿**。颗粒度的最终边界由**人类按需判断**。流程：派生初稿 → 人类给修订意见 → 定稿。

## 1.8 文件命名与上下游

- **命名**：完整版 `PRD_<feature>_v{N}.md` → 人类版 `PRD_<feature>_v{N}_human.md`（同名加 `_human` 后缀，版本号与完整版一致）。
- **上游**：完整版 PRD（`prd-incremental-on-asis` / `prd-write` 产出）。**下游**：评审 / 业务沟通 / 决策（不作开发与测试的规格依据）。
- **同步要求**：完整版变更后重新派生人类版；两版同提交。changelog（元指令 #15）对人类版单列条目。

# Part 2 · 语言规范性与可读性

> 解决②：人类版初稿出来后、定稿前，按本部分过一遍——**去掉 AI 写作腔，保证读起来像人写的**。下列 28 项清单已内化（源自 `humanizer`/`humanizer-zh`，**运行时不依赖该技能**）；**逐字示例与范本以 `reference.md` 的样例（§三/§六）为准**。

## 2.1 待治理的写作腔清单（28 项 = humanizer 精选 27 + 本地补充 1）

> 用法：对照逐项排查人类版文本；命中即按"改写方向"修订。**改写而非删除**——保留信息、只去腔调。

**内容类**

1. **浮夸意义 / 遗产**：删"标志着 / 见证了 / 至关重要的作用 / 奠定基础 / 不可磨灭"等拔高定性，只陈述事实。
2. **知名度 / 媒体渲染**：删"广受认可 / 备受关注 / 被广泛采用"等无来源的知名度主张。
3. **-ing 肤浅分析**：删句尾"从而提升…… / 旨在体现…… / 反映了……"的虚假深度尾巴。
4. **宣传 / 广告语言**：删"赋能 / 打造 / 坐落于 / 一站式 / 无缝 / 强大"营销腔。
5. **模糊归因**："业界普遍 / 相关方认为"→ 给明确出处（评审 / 会议 / 干系人 / 现状 PRD）。
6. **"挑战与未来展望"套路段**：迭代计划只写具体计划，不写"尽管存在挑战……仍将蓬勃发展"空话。

**语言 / 语法类**

7. **AI 高频词**：清"此外 / 然而 / 值得注意的是 / 至关重要 / 深入 / 赋能 / 复杂的 / 关键的 / 格局 / 织锦"。
8. **系动词回避**："作为 / 充当 / 承担……的角色"→ 直接用"是"。
9. **否定式排比**："不仅……而且 / 这不仅仅是……而是……"→ 拆成直陈句。
10. **三段式法则**：不强凑三点；两项或四项更自然。
11. **同义词循环**：同一概念 / 术语**全文用同一词**（PRD 术语一致性是硬要求），不为避免重复而换词。
12. **虚假范围**："从 X 到 Y"仅在 X、Y 处于同一有意义尺度时用，防范围偏离。
13. **被动语态藏主语**："余额被自动冻结"→ 点明主体"系统自动冻结账本"（呼应 Part 1 主谓宾）。
27. **权威套路**：删"真正的问题在于 / 归根结底"等不增信息的权威腔。
32. **格言公式**：删"X 是 Y 的基石 / X 是 Y 的关键"式造句。

**风格类**

18. **emoji 装饰**：PRD 标题 / 列表不用 emoji。

**沟通类**

20. **协作腔**：删"希望这对您有帮助 / 如需我可以…… / 请告诉我"等对话残留。
21. **知识截止免责**：删"截至我所知 / 根据现有信息"等 AI 免责。
22. **谄媚腔**：删"好问题 / 您说得对"等讨好语。
28. **信号词开场**：删"话不多说 / 让我们深入了解 / 下面我们来看"等导语。
29. **碎片标题**：标题下一行不复述标题（呼应 Part 1"标题即需求"）。
33. **口语反问开场**：删"说实话？ / 真的吗？"等戏剧化反问。
34. **口语 → 书面化（本地补充）**：定稿把口语词转书面——"拍板 → 确认 / 敲定""一句话 → 释义 / 解析"。

**填充 / 对冲类**

23. **填充短语**："为了实现这一目标 / 在这个时间点 / 值得注意的是"→ 删，或换"现在"等。
24. **过度限定 / 对冲**：删"可能 / 或许 / 大概"叠用——PRD 是规格，能确定就确定。
25. **通用积极结论**：删"未来可期 / 激动人心 / 迈出重要一步"空泛结尾。
31. **人造金句 / 戏剧断句**：不刻意制造短句金句、不堆断句营造戏剧感。

**跨 ①② 类**

30. **diff 锚定写作**：除"逐行改动点"外，**优先给改动后的最终态 / 完整形态**，而非通篇围绕"改了什么"绕——与 Part 1「改动后形态直接呈现」联动。

## 2.2 不纳入治理的 6 项（边界声明）

以下 humanizer 模式**不在本技能治理范围**，避免误伤 PRD 可读性：

- **格式需要、不限制**：破折号、粗体、内联加粗竖列表、弯引号——PRD / 格式性文档靠适度的结构化粗体与清单**快速扫读**，这是优点，不照搬 humanizer 的"硬删 / 禁用"。
- **语种无关**：标题大写（中文无大小写）、连字符配对（英文专属）。

## 2.3 可读性评分（定稿前自检，改自 humanizer-zh 50 分制）

| 维度 | 评估 | 分 |
|------|------|----|
| 直接性 | 直接陈述还是绕圈宣告 | /10 |
| 节奏 | 句长是否有变化、不机械 | /10 |
| 读者信任 | 是否尊重读者、不手把手 | /10 |
| 真实（去 AI 腔） | 上面 27 项是否基本清干净 | /10 |
| 精炼 | 还有可删的填充 / 重复吗 | /10 |
| **总分** | | **/50** |

标准：45–50 优秀；35–44 良好；<35 重修。

# 质量自检清单（两部分合并）

| # | 自检项 | 通过标准 |
