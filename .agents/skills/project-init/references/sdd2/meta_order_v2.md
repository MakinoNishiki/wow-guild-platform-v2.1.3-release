## 2. 冲突裁定规则

1. 节点优先级不变：**Tool 描述 > Skill 描述 > 元指令**（更具体 > 更通用）。
2. **2.0 优先条款**：已声明 2.0 的项目内，`references/sdd2/` 治理内核 > 1.0 同名文件 / 用户级平台基线 / 平台适配器；project owner 当次明确指令仍优先。
3. 同级冲突：维持冲突前状态并向 project owner 告警，等待人工裁定；方法论结论以写入文档为准（口头确认不算数）。

## 3. 新 Agent 启动协议（2 步版）

```
步骤 1  确认项目根与 worktree；读取 agent_quickstart.md + task_registry.md（两件，其余按需）
        → 更换 Agent/设备、状态矛盾或 project owner 要求从 Git 恢复时，改走 recovery_protocol.md

步骤 2  向 project owner 汇报（≤ 3 行）：项目名与阶段 / 进行中任务与状态 / 异常项（如有）
        → 首条消息已含明确任务：汇报后直接开工，不停等
        → 无任务：停等待命
```

- `model_switch_checkpoint.md` 不再主动询问；发现明显风格 / 能力断点且 Git/状态文档无法解释时才按恢复协议定向读取。
- 识别到项目继承关系时，在汇报中一并说明。
