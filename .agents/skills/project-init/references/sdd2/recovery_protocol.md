# SDD 2.0 Git 优先恢复协议

## 1. 恢复权威顺序

1. 项目真实根路径、当前 worktree、分支和 Git 提交图。
2. Git 管理的 `agent_quickstart.md`、`task_registry.md`、`decision_log.md` 与产出文件。
3. 本地未提交 diff、未合并分支和其他已登记 worktree。
4. 平台会话历史或原始导出，仅作异常兜底证据。

远端不是无条件覆盖源。本地领先、分叉或有未提交内容时，必须先保护本地现场。

## 2. 正常冷启动

正常新会话仍按 `meta_order_v2.md §3`：读取 quickstart + task_registry，三行汇报后继续。没有异常时不要求每次联网 fetch。

以下任一情况进入恢复模式：更换主要 Agent、换设备、项目长时间未打开、状态文档互相矛盾、用户明确要求从 Git 恢复、怀疑本地或远端缺失。

## 3. 恢复模式

### 3.1 路径与现场确认

- 确认项目权威绝对路径与目标 worktree 一致。
- 读取 `git status --short --branch`、当前分支、HEAD、remote 和 `git worktree list`。
- dirty 内容、未跟踪文件和未合并分支先登记；禁止 reset、clean、checkout 覆盖或 prune。

### 3.2 提交图比较

在允许网络访问时先 `git fetch`，再比较本地目标分支与远端：

| 状态 | 动作 |
|------|------|
| SHA 相同 | 不 pull，直接读取 Git 内状态文档 |
| 本地干净且仅落后 | 只允许 fast-forward 更新 |
| 本地仅领先 | 保留本地提交，先确认是否应 push |
| 双方分叉 | 停止自动合并，登记 A 类冲突并报告双方提交 |
| 工作树 dirty | 先识别改动归属；不以远端覆盖 |
| 无 remote | 以本地 Git 为权威，显式标记无云端灾备 |

### 3.3 状态恢复

1. 读取 Git 中的 `agent_quickstart.md` 与 `task_registry.md`。
2. 用 `decision_log.md` 与 `important_conclusion.md`核对 A 类决策。
3. 用产出文件、commit 和 diff 验证“已完成”是否真实落盘。
4. 将未提交 diff、未合并分支和其他 worktree 与任务条目对应。
5. 能由 Git 和状态文档解释时，到此结束，不读取会话。

## 4. 会话历史兜底边界

只有以下情况才读取平台会话或原始导出：

- Git 与状态文档互相矛盾，无法判断哪一方更新；
- 明确存在未落盘的 A 类决策、待办或外部动作；
- worktree/分支来源不明，需要找回任务归属；
- project owner 明确要求核对过程。

读取时按项目、日期和会话 ID 定向检索，不批量灌入上下文；结论必须再与 Git 和文件交叉验证。会话内容不是项目状态权威。

## 5. 停止线

- dirty 改动归属不明；
- 本地与远端分叉；
- 需要删除、覆盖、强推或处理 push 冲突；
- 会话材料含凭据、员工个人信息或内部源码且尚未确认处理边界；
- 当前路径与目标 worktree 不一致。

触发即登记 A 类，保持现场，继续做不受影响的只读工作。

## 6. 恢复验收

- [ ] 能指明项目根、worktree、分支、本地/远端 SHA 和提交图关系。
- [ ] 能从 Git 内文件恢复项目阶段、当前任务、A 类决策和下一步。
- [ ] 所有 dirty/未合并/worktree 项均有归属或阻塞记录。
- [ ] 未执行覆盖、删除、强推或未经授权的冲突处理。
- [ ] 若读取会话，已说明触发原因和 Git 交叉验证结果。
