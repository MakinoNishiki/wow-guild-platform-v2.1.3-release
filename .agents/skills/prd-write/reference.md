## PRD 标准 9 章结构

```
一、文档概要
  1.1 版本记录
  1.2 需求范围/功能范围概述
  1.3 名词解释

二、背景及目标
  2.1 项目资料
  2.2 背景与综述（痛点 → 解决方向 → 效果）
  2.3 项目计划（todo 占位，人工维护）

三、竞品分析（人工维护占位）

四、主逻辑
  4.1 核心场景矩阵
  4.2 端到端流程概述（ASCII 流程图）
  4.3 规模要求

五、方案详情
  5.x [子模块名]
    5.x.1 页面原型（若有，置于节首）
    5.x.2 业务流/信息流
    #### 任务/调度（若有）
    #### 函数/脚本（若有）
    #### 接口（若有）
    #### 配置（若有）
    5.x.3 正向案例
    5.x.4 边界场景处理规则
    5.x.5 逆向流程

六、迭代计划（todo 占位，人工维护）

七、运营计划
  7.1 权限类
  7.2 埋点类
  7.3 数仓类

八、沟通记录
  8.1 TBD 待解析汇总表
  8.2 外部依赖跟踪表

九、参考资料
```

## 5.x 节固定结构速查

### 5.x.1 页面原型（有前端页面则必写，置于节首；无则跳过）

按以下顺序依次写出：

**① ASCII 线框图**（代码块包裹）

**② 菜单路径**
```
菜单路径：{一级} > {二级} > {页面名}
权限可见性：{条件或"不涉及"}
```

**③ 字段规格表**（7属性）

| 字段名 | 含义 | 类型 | 取值来源 | 校验规则 | 示例 | 备注 |
|--------|------|------|---------|---------|------|------|

**④ 查询条件**（有则写，无则注明"本页面无查询条件"）

| 条件名 | 交互方式 | 来源 | 默认值 | 分页/排序规则 |
|--------|---------|------|--------|------------|

**⑤ 静态文案**（有则写，无则注明）
- 显式文案：…
- 气泡文案：`{字段名}` → `{文案}`

**⑥ 交互点规格**

| 交互点 | 后端处理逻辑（分步端到端） | 状态机/流转 | 触发校验规则 | 边界与异常 | 动效说明 |
|--------|----------------------|-----------|-----------|---------|---------|

**⑦ 【状态/空态】**
- 加载中 / 无数据 / 有数据 / 错误

**⑧ 【边界态】**
- 超长文本 / 大数量数据 / 批量操作上限

---

### 5.x.2 业务流/信息流（必写）

代码块包裹，缩进+箭头表示层级，显式写出 yes/no 分支。

---

### 类型专属节（#### 标题，有则写，无则跳过）

**#### 任务/调度**：任务基础信息 / 任务逻辑（分步）/ 执行条件和调度顺序 / 状态机和状态流转图 / 数据量级预估&超时阈值 / 任务异常和告警机制

**#### 函数/脚本**：基础信息 / 逻辑（输入→处理→输出）/ 使用场景和触发条件 / 边界与异常场景

**#### 接口**：接口信息 / 接口字段 / 入参和示例 / 返参和示例（成功/失败）/ 幂等性与重试策略 / 预期QPS&响应时间

**#### 配置**：配置对象（名称/含义/类型/取值范围/默认值）/ 配置步骤（操作者/步骤/生效时延）

---

### 5.x.3–5.x.5（固定在节末）

**5.x.3 正向案例**：≥2 正向案例 + ≥1 边界场景案例，叙述体，含人名/步骤/系统响应/结果

**5.x.4 边界场景处理规则**（4列表格）

| 场景 | 触发条件 | 系统行为 | 用户提示 |
|------|---------|---------|---------|

**5.x.5 逆向流程**（4列表格）

| 逆向场景 | 触发条件 | 处理路径 | 回滚/补偿机制 |
|---------|---------|---------|-------------|

### 二、背景及目标

**2.1 项目资料**：贴 MRD 路径+章节号，表格列出立项人/时间线/优先级（若有）

**2.2 背景与综述**：痛点（2-3条+拟真场景）+ 模块定位 + 解决思路，用"痛点→解决方案→效果"3列表格总结

**2.3 项目计划**：标题下空一行，不填充

---

### 四、主逻辑

**4.1 核心场景矩阵**：表格，行为用户角色/场景，列为操作/触发方式/核心动作（来源：prd_prep §3）

**4.2 端到端流程概述**：ASCII 流程图，展示各模块间数据流向和触发关系

**4.3 规模要求**：来自 prd_prep §9，4列表格（指标/预估值/说明/来源）

---

### 七、运营计划

**7.1 权限类**：初始化权限矩阵（角色×操作，✓/×）+ 权限回收触发规则表

**7.2 埋点类**：埋点清单表（事件名/触发时机/携带参数/下游用途）；无则写"本期不涉及"

**7.3 数仓类**：字段口径表（字段名/数据来源/口径说明/更新频率）+ 数据流向说明；无则写"本期不涉及"

## 写作约束清单

### 内容层面

- [ ] 每个功能流程配至少 1 个正向案例（含具体人物、数值、流程步骤）
- [ ] 关键设计决策后，配反向案例（说明"不这样做的代价"）
- [ ] 所有流程描述从用户/业务视角出发，不描述数据库操作、API 调用等实现细节
- [ ] 用自然语言描述字段含义，不使用字段代码
- [ ] 后端逻辑描述"系统做了什么判断/步骤"，而不是"调用了哪个接口/表"

### 状态机层面

- [ ] 状态码使用 4 位数字编码（如 1100、2000、9000）
- [ ] 状态名和描述全用中文
- [ ] 状态转换表中"当前状态""目标状态"均用中文状态名
- [ ] 明确列出哪些转换是自动触发、哪些需要人工操作

### 错误码层面

- [ ] 错误码使用 6xxx 纯数字格式（如 6001、6002）
- [ ] 不含 HTTP 状态码列
- [ ] 含"含义"和"处理建议"两列

### 页面原型层面

- [ ] 5.x.1 页面原型置于节首（若有前端页面）
- [ ] ASCII 线框图使用代码块包裹
- [ ] 字段规格表包含全部 7 属性
- [ ] 交互点规格包含：后端逻辑（分步）/ 状态机 / 触发校验 / 边界异常 / 动效
- [ ] 【状态/空态】和【边界态】已填写

### 章节层面

- [ ] 空章节（竞品分析、迭代计划、项目计划）：标题下留空行，不补充内容
- [ ] 七、运营计划的 7.2/7.3 若无内容：写"本期不涉及"，不留空白
- [ ] 八、沟通记录包含 8.1 TBD 汇总表和 8.2 外部依赖跟踪表
- [ ] 九、参考资料：只贴链接，不贴原文
- [ ] 不写互斥约束（若项目共识为本期不实现）
- [ ] 不写幂等性规则和并发处理（属于技术设计范畴）

### 文档头层面

- [ ] 包含：文档名称、所属项目、版本、Owner、最后更新
- [ ] 包含：上游基线说明（对应 MRD 章节 + prd_prep 路径）
- [ ] 若 PRD 与 MRD 有差异（如 TBD 变更），在文档头显式标注差异说明

## 完成质量自检（8 项核心）

生成完成后，Agent 自行检查：

1. 是否每个功能流程都有至少 1 个正向案例？
2. 有前端页面的子模块，页面原型是否置于 5.x 节首（不在文末堆积）？
3. 字段规格表是否包含全部 7 属性（含义/取值来源/示例/备注已补全）？
4. 状态机是否使用 4 位数字编码？
5. 错误码是否为 6xxx 格式且无 HTTP 状态列？
6. 逆向流程是否嵌入各子模块节末（5.x.5）而非汇总表？
7. 八、沟通记录是否包含 8.2 外部依赖跟踪表（来自 prd_prep §7）？
8. 关联文档（discussion_record、agent_handoff）是否已更新？
