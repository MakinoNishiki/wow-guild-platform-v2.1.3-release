## 整合版 MRD 结构模板

```
> Header（文档元信息）
>   文档名称 / 所属项目 / 用途 / Owner / 最后更新 / 内容概述
>   整合来源（列出所有源 MRD 文件名，声明"原始文件保留不动"）

# 标题

## 目录

## 1. 项目概述与核心模型设计 ← 核心增量
  ### 1.1 业务现状与痛点
  ### 1.2 驱动力与战略定位
  ### 1.3 核心模型设计（架构框架图 + 模型-章节对应表 + 端到端数据流）
  ### 1.4 分期策略
  ### 1.5 本文档结构导读

## 2. 目标与成功指标 ← 合并章节
  ### 2.1 项目目标（按模块分组，含正反例）
  ### 2.2 可量化的成功指标（统一表格，含"模块"列）

## 3. 用户与场景 ← 合并章节
  ### 3.1 用户角色（去重合并）
  ### 3.2 核心场景（跨模块端到端场景 + 模块专属场景）

## 4~N. 解决方案 — 模块 X ← 独立章节（每模块一个）
  > 标注来源：本章节内容源自 MRD_xxx.md §Y
  各模块完整解决方案

## N+1. 范围与边界 ← 合并章节
  ### 本期纳入（按模块分组）
  ### 显式排除项（去重合并）
  ### 架构预留项（去重合并）

## N+2. 风险与依赖 ← 合并章节
  ### 关键依赖（去重，标注跨模块依赖）
  ### 已知风险与缓解措施（去重）

## 文档关联关系 ← 尾部
  包含所有源 MRD + 项目文档 + 上下游文档
```

## §1 概述章节写作指南

### 1.1 业务现状与痛点

**格式**：用表格呈现"同一痛点在不同层面的表现"。

```markdown
| 痛点 | 在 A 模块层的表现 | 在 B 模块层的表现 |
|------|...              |...              |
```

结尾附一个统一的反例（展示不做整个项目的代价），增强说服力。

### 1.3 核心模型设计

**必须包含的 4 个要素**：

1. **架构框架图**（ASCII）：展示所有模型/模块的层级关系和数据流
2. **模型-章节对应表**：每个模型覆盖情况 + 对应的章节编号
3. **端到端数据流图**（ASCII）：从上游系统到最终业务系统的完整数据路径
4. **端到端正例**（引用块）：用一个具体场景走完全流程，每步标注所在章节

### 1.5 结构导读

**格式**：

```markdown
| 章节 | 内容 | 读者关切 |
|------|------|---------|
| §1   | ...  | "这个项目做什么" |
```

## 场景合并决策流

```
对每对跨模块场景执行判定：

1. 是否描述同一用户旅程的不同环节？
   → 是 → 合并为端到端场景
   → 否 → 继续

2. 是否涉及同一触发事件？
   → 是 → 合并（如"入职"触发账号创建和权限分配）
   → 否 → 保留为独立场景

合并后的场景结构：
  - 流程图：展示跨模块的完整步骤
  - 正例：按时间顺序，标注每步发生在哪个模块
  - 反例：展示模块间不联动的代价
```

## 质量检查清单

### 内容完整性

- [ ] 每份源 MRD 的核心内容均已在整合版中体现
- [ ] §1 概述包含：痛点、驱动力、核心模型架构图、端到端数据流、分期策略、结构导读
- [ ] 至少 1 个跨越所有模块的端到端正例
- [ ] 解决方案章节标注了内容来源

### 合并质量

- [ ] 目标无遗漏、无重复
- [ ] 用户角色已去重合并，同义角色统一
- [ ] 场景中可串联的跨模块场景已合并
- [ ] 范围纳入项完整（逐项比对源 MRD）
- [ ] 排除项完整（逐项比对源 MRD）
- [ ] 预留项完整（逐项比对源 MRD）
- [ ] 风险/依赖无遗漏，跨模块依赖已标注

### 一致性

- [ ] 跨模块术语统一（同一概念使用相同术语）
- [ ] 章节交叉引用准确
- [ ] 正反例中的人物/数据/角色名称一致
- [ ] 分期策略与各模块的范围边界一致

### 文档规范

- [ ] Header 包含整合来源说明
- [ ] Tail 包含完整的文档关联关系表
- [ ] 正反例使用引用块格式
- [ ] 架构图使用 ASCII 格式
- [ ] 关联文档已全部更新
