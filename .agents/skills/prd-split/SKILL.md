## 快速开始

本 Skill 将一个大型整合 PRD（通常 1000–3000 行）拆解为可独立消费的章节片段集合。下游 Agent（TRD 编写、测试用例生成等）通过读取索引文件 `00_index.md` 快速定位目标章节，无需加载全文。

```
上游（prd-write）              本 Skill（prd-split）                                下游
  PRD_{module}.md  →   00_index.md（含功能垂直切片索引）+ 章节片段 MD   →   TRD 编写 / 测试用例生成
```

## 触发与前置条件

**触发**：用户说"拆解PRD"、"PRD拆分"、"prd-split"、"把PRD拆开"、"生成PRD索引"等，或有下游工作（TRD/测试用例）需要按章节消费 PRD 时。

**前置条件**：
1. 目标 PRD 文件存在（通常为 `docs/PRD_{module}_v1.md`）
2. 该 PRD 由 prd-write 生成，具有标准的 §一～§九 章节结构

**启动前确认两项**：
- 目标 PRD 文件路径
- 拆解日期（用于输出目录命名，格式 YYYYMMDD）

## 六步执行流程

### Step 1：扫描结构，确定行范围

```bash
grep -n "^#" docs/PRD_{module}_v1.md
wc -l docs/PRD_{module}_v1.md
```

从输出中提取每个章节的起始行号。结束行 = 下一章节起始行 - 1。PRD 通常包含：
- Header/TOC（行 1–约34）
- §一～§九（逐章段落）
- §五 方案详情内含 §5.1～§5.7 各子模块

### Step 2：确定拆分粒度

**首要判据（功能垂直切片）**：拆分的第一目标是让**每个片段成为下游（TRD 编写 / 测试用例生成）可独立消费的完整功能单元**，而非为拆而拆的机械切分。对按功能组织的 PRD（§五 5.x 按功能 / 页面分节），优先保证**单个功能的端到端规格**（页面原型 + 业务流 + 接口 + 状态机 + 逆向 / 异常）落在同一片段，使下游拿到一个片段即可独立为该功能写 TRD / 测试，不必跨多片段拼接。

**物理切分原则（在垂直切片判据下执行）：**
- 每个顶级章节（§一～§九）独立一个文件；§五的每个子模块（§5.1～§5.7）也各自独立
- **超大节规则**：单个功能片段超过 500 行时，才按小节（####级标题）进一步拆分，保持每文件 ≤ 500 行
- §五 章头（"## 五、方案详情"的1-2行）并入 §5.1 文件，无需单独拆分

> **跨章节归并说明**：当某功能的规格散落在多个物理章节（如 §五页面 + §六接口 + §八异常）时，**不强行物理合并**（保持行数守恒与溯源不破坏），而是在 `00_index.md` 的「功能垂直切片索引」中按功能聚合登记相关片段，供下游按功能垂直读取。见 §索引文件格式 §5。

### Step 3：编写 Python 拆解脚本

使用 Python 脚本执行所有文件写入（`encoding='utf-8'`），不使用手动复制粘贴。

脚本核心逻辑：
1. 读取 PRD 全文为行列表
2. 定义章节 dict 数组（file, title, start, end, desc, subsections, key_concepts, prev_file, next_file）
3. **行数预验证**：`sum(end-start+1 for all sections) + header_lines == TOTAL_LINES`，不通过则报错终止
4. 循环生成每个章节文件（页首 + 原始内容 + 溯源关系 + 导航尾部）
5. 生成 `00_index.md`（含原始 PRD 头部原文 + 章节索引表 + 层级树 + 自检记录）

> **参考实现**：见案例文件 `case_sample_nonCash_20260410.md` 中的脚本结构。

### Step 4：执行脚本，确认输出

```bash
python docs/prd_split_script.py
```

确认控制台输出：
- `[CHECK] 章节内容行数合计: X | 含Header: Y | PRD实际: Y` → 相等则通过
- 每个文件的 `[OK]` 日志
- `[DONE] 共生成文件: N 个`

### Step 5：语义自检（每章节必做）

对每个拆分文件，从其「关键概念锚点」中选 1–2 个问题，验证：
1. 该文件是否能独立回答此问题
2. 答案的语义与 PRD 整体描述是否一致（无概念漂移）

自检结论更新至 `00_index.md §4.2 语义抽检` 表格，状态改为 `✅ 通过` 或记录偏差。

### Step 6：清理脚本文件

拆解完成后，删除或归档临时脚本文件（`prd_split_script.py`），避免污染项目目录。

```
docs/PRD_split/{prd_filename_without_ext}_{YYYYMMDD}/
```

示例：
- PRD 文件：`PRD_billing_system_v1.md`
- 拆解日期：2026-04-10

不同日期的拆解结果独立目录，互不覆盖，天然版本隔离。

## 拆分文件格式

每个章节片段文件结构如下：

```
[页首 frontmatter block]
***
[原始 PRD 内容（逐行复制，不修改）]
---
## 溯源关系
| 字段 | 值 |
| 原始文件 | docs/PRD_{module}_v1.md |
| 原始行范围 | start–end |
| 内容行数 | N 行 |
| 拆解基线索引 | docs/PRD_split/…/00_index.md |
| 上一章节 | …/prev_file.md |
| 下一章节 | …/next_file.md |
### 本章节包含的小节
  - §x.x 小节名 (行范围)
### 本章节关键概念（语义自检锚点）
  - 概念1
  - 概念2
---
## 导航尾部
| 如果你需要了解… | 查阅文档 | 定位 |
```

**页首 frontmatter block 模板**：

```
> **文档名称**: {章节标题} — PRD 拆解片段
> **所属项目**: {项目名}
> **来源文档**: `docs/PRD_{module}_v1.md`（原始行 start–end，共 N 行）
> **拆解基线**: `docs/PRD_split/…/00_index.md`
> **拆解日期**: YYYY-MM-DD
> **用途**: PRD 内容拆解片段，供 TRD 编写、测试用例生成使用
> **Owner**: {owner}
```

## 索引文件格式（00_index.md）

`00_index.md` 是下游 Agent 的入口文件，包含以下四节：

### §1 原始 PRD 头部与目录（原文复制）
将 PRD 文件的前 N 行（含 frontmatter + 目录）原文复制，让读者无需打开原文即可了解 PRD 全貌。

### §2 章节索引表
表格格式：`文件名 | 章节标题 | 原始行范围 | 内容行数 | 章节描述`

供快速定位：确定目标章节 → 记录文件名 → 直接打开该文件。

### §3 PRD 层级树
ASCII 树形图，展示 PRD 章节嵌套结构 + 每节的原始行范围 + 对应文件名：

```
PRD_{module}_v1.md（N行）
├── [header/TOC]  行 1-34
├── §一  文档概要  行 35-79  → 01_doc_overview.md
├── §五  方案详情
│   ├── §5.1  …  行 207-551 → 05_1_M1_raw_data.md
│   └── §5.7  …  行 …      → 05_7_external_interfaces.md
└── §九  参考资料  行 …      → 09_references_nav.md
```

### §4 自检记录
- **4.1 行数核对**：Header行 + 各章节行数 = PRD 总行数，显示核对结果
- **4.2 语义抽检**：每章节一行，记录抽检问题、预期能回答的位置、通过状态

### §5 功能垂直切片索引

按**功能**（而非章节）聚合登记，供下游按功能垂直读取"一个功能的完整规格所需的全部片段"。当某功能规格散落在多个物理片段时，在此建立"功能 → 片段"的聚合视图，落实 Step 2 的垂直切片判据。

表格格式：`功能名 | 涉及片段（文件名列表）| 端到端完整性（页面/业务流/接口/状态/异常 是否齐全）| 备注`

示例：

| 功能 | 涉及片段 | 端到端完整性 | 备注 |
|------|---------|------------|------|
| 账单生成 | 05_1_billing.md, 06_3_interfaces.md, 08_exceptions.md | 页面✓ 业务流✓ 接口✓ 状态✓ 异常✓ | 下游写 TRD/测试读此三片段即可 |
| 对账核销 | 05_2_reconcile.md | 页面✓ 业务流✓ 接口—(无) 状态✓ 异常✓ | 单片段自包含 |

**若 PRD 本身按功能高内聚组织**（单功能规格已集中在单一片段），本节标注"各功能规格已高内聚于对应片段，无需跨片段聚合"并保留空表。

## 自检标准

完成拆解后，必须满足以下全部条件方可视为通过：

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 行数守恒 | `sum(各章节行数) + header行数 == PRD总行数`，误差为零 |
| 2 | 文件完整性 | 每个章节均有对应文件，无遗漏、无重叠行范围 |
| 3 | 语义抽检 | 每个拆分文件至少通过 1 个关键概念问题的独立回答验证 |
| 4 | 溯源关系 | 每个文件的溯源关系表中，原始行范围与实际内容一致 |
| 5 | 导航完整性 | 上一章节/下一章节链接正确（首章节上一为"无"，末章节下一为"无"）|
| 6 | 垂直切片完整性 | `00_index.md §5` 功能垂直切片索引已填；每个功能可通过所列片段获得端到端完整规格（或已标注高内聚无需聚合）|

## 质量门

以下情形应暂停并告知用户：

| 情形 | 处理方式 |
|------|---------|
| PRD 不具备标准章节结构 | 向用户展示 grep 结构扫描结果，协商拆分边界后再执行 |
| 行数预验证不通过 | 排查章节边界错误，修正后重新运行，不跳过验证 |
| 某章节超过 500 行 | 按小节（####级）进一步拆分，保持单文件可读性 |
| 语义抽检发现概念漂移 | 记录偏差到 `00_index.md §4.2`，不自行修正内容（内容来自原文） |
