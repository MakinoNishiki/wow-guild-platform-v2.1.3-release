## 标题（交付 Code）

**任务书#84：家宅图鉴 12.1.5 新图标清晰度与金边统一**

## 描述（交付 Code）

请先完整阅读 `AGENTS.md`、`docs/开发规范.md`、`docs/问题与需求清单.md`、任务书 #82-WP2/#82-Patch1 及本调研报告。当前 Patch1 的 26 张图是按物品 `item_id` 找到的 64×64 物品图标，金色品质框烘焙在 PNG 内；同期 225 张是 Housing Catalog 专属 `iconTexture` 导出并缩为 128×128，因此不能用放大旧图解决。先用当前插件扫描探查这 26 条的 `iconTexture`/`iconAtlas`；存在真实 iconTexture FileDataID 时复用 CASC 管线。若目录没有可用独立图标，挑 3–5 个不同类别的 `asset_id` 用本机 wow.export 导出模型缩略图，统一视角、背景和输出尺寸，与既有图鉴卡并排验收。样本合格后再批量 26 条，并用按 record_id 的显式覆盖映射接入现有图鉴；禁止把模型渲染图伪装成原 FileDataID、禁止使用低清图上采样冒充高清。保留原物品图标作回退。本地完成，不提交、不推送、不部署。

## 现状证据

- #82-Patch1 26 个资产来自 Wowhead item tooltip 按 `item_id` 映射的 FileDataID；CASC 读取成功但原始纹理 64×64，图像内部带金色品质框。
- #82-WP2 225 个家宅图标直接来自插件收集的 Housing Catalog `iconTexture`；CASC 原图 400×400，使用项目既有规则缩至 128×128。
- `addon/WoWButlerDecor/WoWButlerDecor.lua` 当前白名单有 `iconTexture`、`asset`、`uiModelSceneID`，没有 `iconAtlas`。26 条原条目缺 `icon_file_id`，需要客户端诊断以确认该字段为空的原因。
- 26 条数据均有 `asset_id`，可作为模型导出候选；尚未在本任务环境逐条导出，不能保证每个模型有完整贴图或可正确 framing。

## 执行步骤

### WP0：图鉴视觉审计前置

- 如最终需改 `decorData.js`/`decorDict.js` 的卡片图标选择逻辑，开工前按 `AGENTS.md` 使用 `.agents/skills/improve-ui` 审计家宅图鉴卡片与详情图标，产出具体问题清单；仅涉及素材而不动渲染逻辑时，说明为何不触发页面改版审计。

### WP1：最小客户端诊断

1. 在插件采集字段中记录 `iconTexture` 的类型/值及 `iconAtlas` 类型/值，诊断范围限定为 Patch1 的 26 个 record_id；同时保留 `asset`、`uiModelSceneID` 便于模型核对。
2. 用用户当前 12.1.5 客户端只扫描一次：`/wbd scan`、`/reload`，读回 SavedVariables；按 REQ-121 工作流先比对插件目录版本与仓库，再校验导出文件。
3. 若任一目标返回数字型 `iconTexture`，按 CASC FileDataID 现有流程导出并验证 PNG；若仅有 `iconAtlas`，须找到 Atlas 底图/裁切信息且目视结果与 Housing Catalog 一致才采纳。

### WP2：3–5 个模型缩略图试点

1. 从有代表性的树木/植物、家具、节日物件和小型摆件中选 3–5 条，以其 `asset_id` 从本机当前 CASC 用 wow.export 导出 GLB/模型。
2. 在临时目录渲染 128×128 或更高分辨率的静态 PNG：无物品品质边框、统一取景与光照、透明背景或项目卡片兼容底色；避免裁掉模型边缘。逐张与游戏 Housing Catalog 及 WoWDB/Wowhead 3D 预览对照。
3. 记录源 asset_id、文件尺寸、图像像素尺寸、模型加载/贴图/朝向问题；三类代表样本中任一关键模型无法对应或画面明显逊于现有 128px 图标，则先停批量并报告失败类别。

### WP3：试点通过后批量 26 张

1. 只在 WP2 样本可用后批处理剩余条目；输出以 `record_id` 命名并单独存放（例如 `assets/decor-icons/model-previews/{record_id}.png`），不得重用 `{icon_file_id}.png` 命名谎称来源 FileDataID。
2. 通过 `decorDict.js` 的显式 `record_id → 本地缩略图路径` 映射供 `decorData.js` 使用；优先顺序为 Housing Catalog 专属 iconTexture、已验收模型缩略图、原 64px 物品图、项目 `_placeholder.png`。数据无覆盖时沿用既有路径。
3. 不改线上数据库或 schema。若要把模型缩略图作为公开部署素材，文件和映射均只留在本地改动，由运营审阅后自行 commit/push；推送可能自动部署。

## 安全与协作边界

- 不读取 `.env`、密钥、密码、令牌；不连服务器/数据库、不执行 SQL、不部署。
- 不访问外部图片 CDN 下载图像作绕行；Wowhead/WoWDB 仅作视觉比对证据。
- 临时 CASC/GLB、第三方工具代码和缓存不进仓库；仓库只接收验收通过的静态缩略图、明确映射、必要插件诊断改动与报告。
- 不提交、不推送；运营本人决定 commit/push 与线上发布时机。

## 验收标准

1. 26 条 iconTexture/iconAtlas 诊断有逐条结果；可导出的官方图标优先走现有 FileDataID 管线。
2. 3–5 样本静态缩略图通过逐张视觉对照：对象对应、清楚、无金边、透明/底色一致、无裁切；如未通过则报告并停批量。
3. 批量输出后 26/26 映射无重复/串项，PNG 完整解码，尺寸达到项目图鉴清晰度标准；原物品图作为可控回退。
4. 浏览器 `index.html#/house/decor` 检查 26 项目标卡及详情图片与至少 5 个既有 128px 图标，确认无布局变化、裂图、金边和错图；具体页面与交互写进修改报告。
5. `node --check` 所有改动 JS；若改动 js/css，按规范同步递增 `index.html` 版本串。报告记录真实浏览器验收对象、结果、失败和回退情况。

## 停止条件

- 样本模型无法导出、贴图缺失、与目录条目不符或视效不达标：只交付诊断和失败分类，不批量上采样/裁图，不覆盖现有 26 张图。
- 需要线上数据/schema/发布动作：先停，另交数据差异与 SQL 草案，等待运营明确授权；不可推送或部署。
