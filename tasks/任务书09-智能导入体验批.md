## 一、双宏教程（REQ-023 优化）

导入弹窗的"游戏内导出教程"升级为双宏制：

1. **团队宏（推荐，默认展示）**——先在游戏里组好团队/小队再执行，导出的是当前实际打团的人，不含公会闲杂成员：
```
/run for i=1,GetNumGroupMembers() do local n,_,_,_,_,c=GetRaidRosterInfo(i) if n then print(n..","..c) end end
```
2. **公会宏（兜底，折叠展示）**——导出整个公会花名册，适合整会导入场景（现有宏保留）；
3. 两个宏各配"一键复制"按钮；
4. 教程补充一句说明："魔兽原生聊天框不支持复制，需安装聊天增强插件（如自带复制功能的插件）后才能复制名单"；
5. 上线前请核对宏在当前游戏版本的 API 可用性（GetRaidRosterInfo / GetGuildRosterInfo 的返回值字段序），如字段序有变以实际为准并在报告中注明。

## 二、解析器升级

1. **时间戳清洗**：聊天复制的内容常带时间戳前缀，解析每行时自动剥离以下形态（含中括号/无括号、带秒/不带秒）：
   - `[12:34]`、`[12:34:56]`、`12:34`、`12:34:56`、以及前后可能有的空格
   - 剥离后再进入原有格式识别；扩充 scripts/verify-smart-import.js 用例（含时间戳行、时间戳+宏格式混合行）；
2. **已存在"名字-服务器"识别**：预览页查重时，对库中已存成员同时匹配"名字"与"名字-服务器"两种形态，避免带服务器后缀的重复导入；
3. 其余解析规则不变。

## 三、弹窗防误关（全局原则）

1. **原则**：任何包含未保存编辑内容的弹窗，点击遮罩层/按 ESC 时**不直接关闭**，弹出二次确认（"内容未保存，确定放弃吗？"）；无编辑内容的弹窗维持现状；
2. 本期至少覆盖：智能导入弹窗（粘贴/预览两步）、添加/编辑成员弹窗、创建活动弹窗、添加装备弹窗、公会设置弹窗；
3. 其余弹窗列出清单记入报告，标注是否已覆盖；
4. **将该原则写入 `docs/开发规范.md` 第四章**（代码风格与架构约定），作为以后所有新弹窗的强制要求。

## 运营验收步骤

1. 导入弹窗：看到双宏教程，两个"一键复制"都可用；
2. 粘贴带时间戳的名单（自己构造几行：`[12:34] 小明-金色平原,WARRIOR`）→ 预览页名字干净无时间戳；
3. 粘贴一个库中已存在的"名字-服务器"→ 预览页标黄提示；
4. 在导入弹窗输入内容后点击弹窗外部 → 出现二次确认而不是直接消失；创建活动弹窗同样验证；
5. `docs/开发规范.md` 中能看到防误关原则；
6. 全过后 GitHub Desktop 提交存档。
