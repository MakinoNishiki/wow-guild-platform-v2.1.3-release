## 一、需求

### 1.1 masterDataSnapshot.js 补 seasons 数据（根因修复）

**现状**：`masterDataSnapshot.js` 中 `seasons: []` 为空数组。

**修复**：补全 seasons 快照数据：

```js
seasons: [
  { id: 'f4d458b5-b4fb-4fdc-bdc8-721265b4a485', name: 'S1', is_current: false, start_date: '2026-01-01', end_date: '2026-08-19' },
  { id: '370c4590-5fa0-47ba-a97a-d8a4436cbeea', name: 'S2', is_current: true, start_date: '2026-08-20', end_date: null }
],
```

**约束**：
- `id` 必须与 DB `game_seasons.id` 一致（从线上 REST API 获取）。
- `name` 使用 `S1`/`S2` 格式（与 DB 一致）。
- `is_current` 反映当前赛季状态（S2）。
- `start_date`/`end_date` 为近似值，仅用于快照兜底排序，不影响功能逻辑。

### 1.2 渲染前等待 MasterData 加载（兜底增强）

**现状**：手动表单和 picker 的团本下拉在 `MasterData` 未加载完成时就渲染，走 `getGameRaidNames()` 快照回退路径。

**修复**：在以下三个渲染入口前加等待：

```js
// 手动表单 — 装备分配
async function lootOpenModal(...) {
  if (!MasterData.isLoaded()) await MasterData.init();
  // ... 原有逻辑
  raidSelect.innerHTML = buildRaidSeasonOptions(selectedRaid, true);
}

// 手动表单 — 心愿单
async function wishlistOpenModal(...) {
  if (!MasterData.isLoaded()) await MasterData.init();
  // ... 原有逻辑
  raidSelect.innerHTML = buildRaidSeasonOptions('', true);
}

// picker 弹窗
async function openItemDbPicker(...) {
  if (!MasterData.isLoaded()) await MasterData.init();
  // ... 原有逻辑
  renderItemDbList();
}
```

**约束**：
- `await MasterData.init()` 必须在任何依赖 `MasterData.getCurrentSeason()` 的代码之前。
- 如果 `init()` 失败（超时/网络异常），仍由快照兜底，不阻塞用户操作。
- 不改动 `MasterData.init()` 本身的超时逻辑（5 秒）。

### 1.3 UI 审计 — picker 空装等标签不渲染

**现状**：picker 装备卡片上显示「装等」文字但无数值，形成裸标签。

**修复**：在 picker 卡片渲染逻辑中，仅当 `item.ilvl` 有值时才渲染「装等」标签：

```js
// 修改前：
// <span class="picker-ilvl">装等 ${item.ilvl || ''}</span>

// 修改后：
${item.ilvl ? `<span class="picker-ilvl">装等 ${item.ilvl}</span>` : ''}
```

**约束**：
- 仅影响 picker 卡片渲染，不动装备分配/心愿单/公示页等其他链路。
- 装饰类物品（ilvl 为 null）不显示装等标签。

### 1.4 UI 审计 — picker 装备图标接真实物品图标

**现状**：picker 装备卡片图标恒为 📦 emoji 占位。

**修复**：
- 如果 `item.icon_id` 存在，渲染为 `<img src="https://wow.zamimg.com/images/wow/icons/medium/${item.icon_id}.jpg">`。
- 如果 `item.icon_id` 不存在，回退到现有 📦 emoji。

```js
const iconHtml = item.icon_id
  ? `<img src="https://wow.zamimg.com/images/wow/icons/medium/${item.icon_id}.jpg" class="picker-icon" loading="lazy" onerror="this.outerHTML='📦'">`
  : '📦';
```

**约束**：
- wow.zamimg.com 为 wowhead CDN，国内访问可能不稳定。加 `onerror` 回退到 📦。
- `loading="lazy"` 避免一次性加载全部图标拖慢 picker 打开速度。
- 仅 picker 卡片生效，不动其他页面图标。

### 1.5 缓存策略 — HTML 壳加 no-cache 响应头

**现状**：`index.html` / `data.html` / `decor.html` 被浏览器长期缓存，用户 push 后需手动 F5 才能获取新版。

**修复**：在 `server.js` 中，对三个 HTML 壳的响应添加缓存控制头：

```js
// server.js 中，对 HTML 文件的响应
if (req.url.endsWith('.html') || req.url === '/' || req.url === '/index.html') {
  res.setHeader('Cache-Control', 'no-cache, no-store, must-revalidate');
  res.setHeader('Pragma', 'no-cache');
  res.setHeader('Expires', '0');
}
```

**约束**：
- 仅 HTML 文件加 no-cache，JS/CSS 保持现有长期缓存策略（依赖 query string 版本串失效）。
- 如果使用 CDN（如 Cloudflare），同步检查 CDN 缓存规则，确保 HTML 文件不被 CDN 缓存。
