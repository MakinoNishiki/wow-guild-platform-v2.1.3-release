## 前置侦察（先出结论再施工，§1）

1. dashboard「最近活动」的数据源与刷新链：条目从哪读、何时 reload——删除活动后条目是否残留？残留则定位断环（DB-first 逐环：写入 → reload → 缓存 → render）。
2. 活动「取消」状态的字段现状：取消通知现在存在哪（哪张表哪个字段/哪条链路），dashboard 读不读得到。
3. 条目上现有操作按钮/交互清单（逐列，报告中附现状截图）。
侦察结论送审后施工（拿不准停手，禁止先改再说）。

## F1：状态徽标一级可见 + 删除联动

- 每个活动条目一级显示状态：**正常** / **已取消**（明显徽标，已取消条目整体灰化降饱和 + 「已取消」徽标高对比色；一眼可辨，不需点进活动）。
- 活动取消的判定来源 = 侦察项②的既有取消状态字段，**禁止新造状态语义**。
- 删除活动记录后，dashboard 条目**联动消失**（若现状残留，修刷新链断环而非打补丁遮掩）；活动取消后条目**仍在列表**但带「已取消」徽标。

## F2：只读预览 + 点击跳转考勤 tab

- 移除 dashboard「最近活动」条目上的全部操作按钮/编辑入口（清单以侦察项③为准）——该区域**纯预览**。
- 点击条目 → 跳转考勤记录 tab 并**定位该活动**（滚动到该活动卡片 + 短暂高亮 1.5-2s，复用站内 switchPage 既有模式；找不到该活动——如已删除——则落考勤 tab 顶部并 toast 提示「该活动已被删除」）。
