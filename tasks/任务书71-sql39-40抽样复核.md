## 一、问题背景

sql/39 和 sql/40 由 Code 声称通过 PostgREST+service_role 对自建实例执行：
- sql/39：36 件装饰物品补充 sources（jsonb 数组）和 source_text（text）
- sql/40：34 件修正 source_text 的英文翻译为中文

但顾问在返工排查中发现：此前未独立验证这些更新是否真实落到了生产库。**本次复核必须对生产自建实例 REST 实证。**

---

## 二、复核清单（5 条抽样）

### 2.1 抽样原则

从 36+34=70 件中，按来源类型分层抽样 5 条：

| 来源类型 | 代表 record_id | 检查项 |
|---------|---------------|--------|
| 商人(vendor) | 4172（瓦德拉肯吊灯） | sources.type="vendor" + source_text 含 NPC 名 |
| 掉落(drop) | 2523（舒哈鲁视角画作，注意 curly quote 陷阱） | sources.type="drop" + source_text 含 Boss 名 |
| 任务(quest) | 自行选 1 条 | sources.type="quest" + source_text 含任务名 |
| 成就(achievement) | 自行选 1 条 | sources.type="achievement" + source_text 含成就名 |
| 专业(profession) | 自行选 1 条 | sources.type="profession" + source_text 含专业名 |

### 2.2 查询方式

用 service_role key 调生产 REST（api.ddctl.com）：

```bash
curl -s "https://api.ddctl.com/rest/v1/decor_catalog?record_id=eq.<id>&select=record_id,name,sources,source_text" \
  -H "Authorization: Bearer <service_role_key>" \
  -H "apikey: <anon_key>"
```

### 2.3 通过标准（逐条）

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | sources 非空 | sources IS NOT NULL 且 sources != '[]'::jsonb |
| 2 | sources 结构正确 | sources 是 jsonb 数组（Array.isArray 语义），每项含 type + detail |
| 3 | sources.type 是英文 enum | type ∈ {vendor, drop, quest, achievement, profession} |
| 4 | source_text 非空 | source_text IS NOT NULL 且长度 > 0 |
| 5 | source_text 是中文 | source_text 不含纯英文 NPC/Quest/Boss 名（sql/40 修正项） |
