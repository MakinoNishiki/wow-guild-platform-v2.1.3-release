# 任务书 #12-补丁3：弹窗层级根治 + 出勤率列实时刷新 + 批量恢复聚合确认

## 0. 背景

补丁 2 验收通过后发现的三个问题。前两个是 BUG-026/假刷新家族的延伸，要求**根治而非打地鼠**。

## 1. BUG-033（P1）：弹窗层级——智能导入弹窗被考勤详情弹窗遮挡

**现象**：WCL 同步预览页点「添加为成员」→ 同步预览关闭 → **考勤详情弹窗**（同步预览的下层）露在最上面，智能导入弹窗开在更底下，用户需手动关闭考勤详情才能看到导入弹窗。

**根治要求**（不许再只调一对弹窗）：
1. 实现统一的**弹窗栈管理**：任何 openModal 都把该弹窗置顶（z-index 按打开顺序递增，或维护 modal-stack 数组统一计算层级）；
2. 全站所有弹窗走同一套 open/close 函数（若已有则修正其层级逻辑），禁止个别弹窗写死 z-index；
3. 回归检查三处已知叠加路径：①同步预览→导入弹窗（本条）；②活动详情→WCL 同步预览；③考勤详情→任何二级弹窗——修改报告逐条说明层级行为；
4. 防误关（modalDirtyChecks）逻辑不得受影响。

## 2. BUG-034（P1）：成员管理出勤率列不随考勤变更刷新

**现象**：修改某活动考勤保存后，统计报表已变化，但切到成员管理 tab，出勤率列仍是旧值。

**根因方向（以诊断为准）**：tab 切换时成员列表用了缓存的统计结果，未基于最新 appData 重跑 getAttendanceStats。

**要求**：
1. 切换到成员管理 tab 时出勤率列必须用**当前内存最新数据**重算重绘（不一定重新请求库，但禁止用过期缓存渲染）；
2. 顺带自查：仪表盘、统计报表、成员管理三处出勤相关数字在"改考勤→切换查看"路径下必须一致；
3. **检查项（写进报告）**：创建活动时预置考勤行的成员范围——**已离队成员不应被纳入新活动的考勤名单**（验收中出现过新活动考勤名单全员"已离队"的情况）；WCL 同步对照同样只针对活跃成员。若有漏洞一并修复。

## 3. REQ-048：批量导入遇同名离队成员——聚合确认代替逐个 confirm

**现象**：智能导入 20 人含多个同名已离队成员时，每个都弹一次浏览器原生 confirm，用户要点 20 遍。

**要求**：
1. 导入确认前**一次性聚合**：列出本批所有"同名已离队"成员（复选框默认全选），文案"以下 N 名成员同名已离队，勾选将恢复为正式成员（不新建）"，一次确认完成；
2. 未勾选的离队同名成员：跳过不导入（在预览页标出"已离队同名，未恢复"）；
3. 替换浏览器原生 confirm 为项目内弹窗组件（遵守防误关规范）；
4. 单个恢复路径（成员管理"恢复"按钮、新增成员撞离队同名）保持现有行为不变。

## 4. 验证与交付

1. `node --check` 全过；`verify-authz.js` 回归全绿；
2. 修改报告：BUG-033 层级方案说明、BUG-034 根因、创建活动预置考勤范围检查结果；
3. docs/问题与需求清单.md：BUG-033/034、REQ-048 登记；
4. **不提交 git**：运营验收后与补丁 2 合并提交。

## 5. 验收用例（运营侧）

| # | 场景 | 通过标准 |
|---|------|---------|
| 1 | 同步预览点「添加为成员」 | 导入弹窗直接在最上层，无需关任何弹窗 |
| 2 | 活动详情 → WCL 同步预览 → 导入弹窗三层路径 | 每层新弹窗都在最上 |
| 3 | 改一条考勤保存 → 切成员管理 tab | 出勤率列立即是新值，与统计报表一致 |
| 4 | 新建活动 | 考勤名单只含活跃成员，无"已离队"成员 |
| 5 | 智能导入含 3 个同名离队成员的名单 | 一次弹窗聚合确认（非 3 次），确认后 3 人恢复为正式 |
| 6 | 聚合确认中取消勾选 1 人 | 该人不恢复不导入，其余正常 |
