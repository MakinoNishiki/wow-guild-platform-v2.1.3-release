## 一、REQ-023：成员智能导入（核心）

目标：团长 2 分钟录完全团，手动录入降级为补录单个成员的兜底。

### 1. 批量导入面板升级

成员管理的"批量导入"升级为**智能粘贴导入**：

- 一个大文本框，用户粘贴任意来源的名单；
- 解析器兼容以下格式（自动识别，不让用户选格式）：
  - 游戏内宏输出：`名字-服务器,CLASS_FILENAME` 及 `名字,CLASS_FILENAME`（职业为英文类名，如 WARRIOR/PRIEST/EVOKER，映射到中文职业）
  - `名字,职业` / `名字-职业` / `名字 职业`（中文职业名）
  - 纯名字列表（每行一个，职业留空）
- 解析结果进入**预览确认页**：表格列出 名字/职业（下拉可改）/专精（默认"待补充"），标红无法识别的行让用户修正或剔除；
- 确认后批量入库（走 cloudCrud 规范 1.2.2 批处理例外：批量写 → 单次 reload → 单次 render）。

### 2. 规则

- 同公会重名成员：预览页标黄提示"已存在"，用户选择跳过或保留（REQ-002 约束：同服务器角色名唯一，导入时一并校验）；
- 专精统一默认"待补充"，导入后成员列表正常显示，由团长后续补录；
- 面板旁放"游戏内一键导出教程"折叠说明，含宏文本（可直接复制）：

```
/run for i=1,GetNumGuildMembers() do local n,_,_,_,_,_,_,_,_,_,c=GetGuildRosterInfo(i) if n then print(n..","..c) end end
```

### 3. 验证

- 用构造数据脚本验证三种格式的解析正确性（含中英文职业、异常行、重名）；
- 报告解析器支持的职业映射表。

## 二、REQ-025：公会资料字段（简介 + 分配制度 + 规则说明）

### 1. 数据层

产出增量 SQL `sql/06_req025_guild_profile.sql`（幂等、含回滚说明），`guilds` 表新增：

- `description`（text，可空）：公会简介
- `loot_rule_type`（text，可空）：分配制度枚举——`roll` / `yixuduotan`（一需多贪）/ `cl` / `custom`
- `loot_rule_text`（text，可空）：分配规则说明（自定义文本）

⚠️ SQL 先产出交运营执行，再继续后续开发验证。

### 2. 公会设置页

- 新增"公会资料"区：公会简介（多行）、分配制度（下拉：ROLL/一需多贪/CL/自定义）、规则说明（多行，自定义制度时必填提示）；
- 仅 owner 可编辑，editor/viewer 只读可见。

### 3. 装备分配联动（核心体验）

- 打开"添加装备分配"弹窗时，"规则说明"输入框**自动带出公会 loot_rule_text** 内容；
- 当场可修改（修改只影响本次分配，不回写公会设置）；
- 公会未设置规则时输入框为空，行为与现状一致。

## 纪律

- 修改前输出清单；修改后 node --check + 修改报告（逐编号）；
- 不触碰：考勤专项（REQ-001/017/018/020）、用户中心治理、主数据层、公会公开页（REQ-013）；
- 字段范围严格限于上述三个，字段清单中其余字段（团队类型/活动日/氛围标签等）不在本期。

## 运营验收步骤

1. 执行 `sql/06_req025_guild_profile.sql`；
2. 重启服务，公会设置页填写简介+分配制度+规则说明，保存刷新后仍在；
3. 打开添加装备弹窗：规则说明自动带出公会规则，改字不影响公会设置里的原文；
4. 成员批量导入：分别粘贴三种格式名单（各 3-5 行）→ 预览页解析正确 → 确认入库 → 列表即时显示，专精为"待补充"；
5. 导入含已存在成员时预览页有提示；
6. viewer 账号：公会资料只读、无导入入口；
7. 全过后 GitHub Desktop 提交存档。
