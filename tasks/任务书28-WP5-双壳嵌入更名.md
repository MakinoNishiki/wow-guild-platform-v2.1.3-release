# 任务书 #28-WP5：双壳嵌入 + 更名「副本掉落」

> REQ-086 收官 WP。PRD V2 §1/§2：①「数据公示」更名「副本掉落」（原名用户不理解、有信任成本）；②嵌入主应用——侧边栏点击像「考勤记录」「成员管理」一样**切 tab**，不再单独跳转页面。
> 形态定调（2026-08-10）：**双壳**——主应用内嵌 tab（登录壳）+ data.html 免登录公开页保留（公开壳，可分享场景不动），**同一套渲染层与数据通道，单一真源**。
> 红线提醒：本 WP 首次在 REQ-086 中触碰主应用（index.html / app.js）——其他页签、登录、权限**零回归**为硬门槛。

## F1 渲染层双宿主改造（js/dataPublic.js + css/data-public.css）

- 渲染初始化参数化：现有渲染逻辑改「挂载到指定容器」，公开页挂现容器、主应用 tab 挂新容器；**禁止复制第二份渲染代码**。
- 数据通道不变：双壳同走匿名 RPC `get_public_loot_detail`（数据本就公开，登录壳无需换通道）。
- 全局副作用清查（§1 副作用审计重点）：dataPublic.js 内对 `document.body`、`window` 滚动、`document.title` 的直接操作逐处列出并改为容器作用域；id 选择器在双壳同页时不得冲突（主应用 tab 容器内用作用域类名）。

## F2 主应用 tab 嵌入

- 侧边栏入口改造：原「数据公示」`window.open('data.html','_blank')` → 更名「副本掉落」、`switchPage('lootdrop')` 内切换（与其他 tab 同款行为、图标可沿用 📖 或换 🗡，由 Code 按图标规范选）。
- 新 page 容器：`page-lootdrop`，结构 = 原公开页内容区（赛季栏 + 筛选条 + 双池 + 套装区），引入 `css/data-public.css` + `js/dataPublic.js`（script/link 标签复用同文件，带版本串）。
- 滚动与吸顶侦察（**先侦察后动手**）：公示页筛选条 sticky 原以视口为上下文，嵌入后主应用 page 容器若是独立滚动上下文，sticky 行为会变化——侦察主应用滚动模型，给出「吸顶在 tab 内等效生效」的实现与断言；BUG-065 的「命中行恒可见零半裁」在 tab 内同样成立。
- 覆盖式生长 z-index 层级规约（筛选条10＞hover卡5）在 tab 容器内同效；主应用已有 z 层级（遮罩9999/弹窗1000/侧边栏100）不得被本 tab 干扰。

## F3 更名「副本掉落」全量清单

- 侧边栏入口文本；主应用 `pageTitles` 映射；公开页 `document.title` + h1「数据公示」→「副本掉落」（副标「魔兽管家 WoW Butler · 团本/大秘境掉落池与套装一览」保留）；
- 页面内所有「数据公示」文案出现处（含空态/提示/toast）；
- changelog + 文档（UI 规范、筛选规范、台账）。
- **URL 不变**：data.html 文件名不改（外链已分享场景不受损）。

## F4 公开壳保留验证

- data.html 免登录直开：渲染/筛选/吸顶/生长全套行为与嵌入前**逐像素一致**（双壳同源后公开壳零回退）。
