## 三、入库逻辑（Code 写脚本执行）

### 3.1 两步入库

**Step 1： bosses 表（先查后插）**

对每个 `(instance_name, boss_name, instance_type)`：
1. `GET /rest/v1/bosses?instance_name=eq.XXX&boss_name=eq.YYY&limit=1`
2. 如果返回空 → `POST /rest/v1/bosses` 插入新记录，获取返回的 `id`（UUID）
3. 如果返回有数据 → 复用现有 `id`

**Step 2： boss_loot 表（批量 upsert）**

用获取到的 `boss_id` 组装 `boss_loot` 记录：

```javascript
{
  boss_id: "<UUID>",
  official_item_id: 280799,
  item_name: "露瑟拉玛，圣光之裁",
  slot: "双手",
  item_type: "双手剑",
  ilvl: 219,
  icon_id: 7350841,
  effect: "装备：...",
  primary_stats: [],
  secondary_stats: [],
  primary_values: {},
  secondary_values: {},
  venomcurse: null,
  primary_tiers: null,
  secondary_tiers: null
}
```

批量 POST：
```
POST /rest/v1/boss_loot?on_conflict=official_item_id
Headers: apikey=<service_role>, Prefer: resolution=merge-duplicates
Body: [记录数组]
```

### 3.2 幂等护栏

- `on_conflict=official_item_id`：重复执行不翻倍
- `resolution=merge-duplicates`：已存在则更新

### 3.3 密钥

`service_role_key` 从环境变量 `SUPABASE_SERVICE_ROLE_KEY` 读取，不硬编码。
