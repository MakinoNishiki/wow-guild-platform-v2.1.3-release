## WP2：彻底删除放开 + 历史保全 + 垃圾桶（sql/17）

### 1. 历史保全（外键与快照）

1. `activity_attendance`、`loots`（装备分配）各加 `member_name text` 快照列；**回填** = 按 member_id 从 raid_members 复制现名；
2. 两表 `member_id` 外键约束重建为 **ON DELETE SET NULL**（DROP 旧约束 ADD 新约束，迁移注释写明）；写入路径此后保存考勤/分配时同步写 member_name 快照（app 层改，双写不替代快照读取）；
3. `wishlists`（心愿单）维持级联删除——心愿是成员私有数据，随人走（删除前在确认弹窗明示「其心愿单 N 条将一并删除」）。

### 2. 垃圾桶表 `deleted_raid_members`

列：id、原成员全字段快照（guild_id/name/class/spec/off_specs/role/status/join_date/notes/user_id）、`deleted_at`、`deleted_by`（操作者 uid）、`history_counts jsonb`（删除时考勤/装备/心愿条数）。RLS：公会成员可读所属公会、owner/editor 可写（经代理通用分支，无新权限分支）；用途=审计与误删反悔参考，一期不做恢复功能。

### 3. 删除流程改造（前端）

1. **解除 0 历史限制**：任何成员可「彻底删除」；确认弹窗分级——
   - 0 历史：现文案不变；
   - 有历史：红色警示「该成员有考勤 X 条 / 装备记录 Y 条 / 心愿 Z 条。彻底删除后：考勤与装备记录将保留并灰色显示「已删除」，心愿单将一并删除，成员数据进入垃圾桶可查。」需输入成员名确认（防误删，重复角色场景下必须输名才能区分）；
2. 删除执行（顺序）：写垃圾桶行 → 删 wishlists（级联自动）→ 删 raid_members 行（考勤/装备 member_id 被 SET NULL，member_name 快照保留）；
3. **历史灰色展示**：考勤详情/活动列表/装备分配/统计报表中，member_id 为空的行显示 member_name 灰色黯淡 + 「已删除」小徽标，统计口径不变（已删除成员的考勤仍计入历史出勤率，与离队成员同规则）；装备分配行同样灰色标记；心愿单随删除消失不展示。

### 4. 迁移纪律

备份（三表 JSON 导出）→ 执行 → NOTIFY pgrst → 回滚语句注释（含约束还原）→ SSH + docker exec（supabase_admin）。

### WP2 验收

- 重复角色场景端到端：建两个同名成员（一个手动一个模拟 WCL 导入带考勤）→ 删除带历史者 → 输名确认 → 考勤保留灰色「已删除」、心愿清空、垃圾桶行完整（含 history_counts）；
