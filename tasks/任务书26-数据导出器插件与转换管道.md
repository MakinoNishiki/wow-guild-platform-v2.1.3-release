> **优先级：插队在最前**（运营拍板，赶在 8.13 S2 翻牌前备好数据管道）。与网站主工程零文件冲突（独立产物，仓库 `addon/` 目录单独管理），**无排队红线**。

## WP1：导出插件「WoWButler Data Exporter」（`addon/WoWButlerExporter/`）

### 需求

1. **基本形态**：单文件夹插件，零外部依赖（不引 Ace 等库），TOC 接口号按当前正式服（12.x）；文件：`.toc` + 主 Lua（≤300 行）+ README（安装/使用说明，给运营看的）；
2. **命令**：`/wjdc all`（全量）/ `/wjdc raid`（团本）/ `/wjdc mplus`（大秘境）/ `/wjdc tier`（套装）/ **`/wjdc me`（本人角色档案）**；执行后提示「已导出，请 /reload 或退出游戏写入文件」；
   - `/wjdc me` 追加需求（2026-08-05 运营验收追加）：导出**当前登录角色**的档案——角色名、服务器（中文名）、区域、阵营、种族、职业、当前专精、等级、**实时装等**、所属公会名；这些数据游戏内 API 全部可读（英雄榜链接无法提供的字段靠此补齐，供用户中心「从插件导入角色」使用，见任务书 #24-补丁2）；
3. **导出内容**（写入 SavedVariables 全局表 `WJDCDump`）：
   - 元信息：客户端版本/build、导出时间、导出类型；
   - **团本掉落**：当前资料片全部团本实例 → 实例名/类型 → 逐 BOSS（encounter 名）→ 掉落列表（itemID、名称、部位、类型、物品等级、主属性/副属性、特效/使用说明）；
   - **大秘境掉落**：当前资料片副本地图 → 逐 BOSS（归属 dungeon_loot 的 boss_id 用）→ 掉落列表（同结构）；副本整体池由 BOSS 并集在转换器侧推导，插件只按 BOSS 导；
   - **套装效果**：当前版本各职业全专精套装名 + 2件/4件效果文本（tooltip 扫描法提取；提取失败的专精记录为 `failed` 并在聊天框报告，**禁止静默跳过**）；
4. **编码与格式**：SavedVariables Lua 表结构清晰（见 WP2 约定），中文原文不转义；非当前资料片实例一律不导（避免旧数据污染）；
5. **容错**：API 不可用的客户端（如怀旧服误装）给明确提示不报错炸屏；导出中聊天框进度提示。

### WP1 验收

- Lua 语法检查通过；README 含安装/使用/文件位置说明；
- **运营侧实测（游戏内）**：`/wjdc all` 跑通，SavedVariables 文件生成，抽查 2 个 BOSS 掉落与游戏内手册一致——此验收由运营执行，Kimi Code 交付后提供测试步骤卡。

## WP2：转换器 + 核对表管道（`scripts/wjdc_convert.py`）

### 需求

1. **输入**：SavedVariables 文件（运营提供）；**解析** Lua 表（手写迷你解析或用 lupa，二选一，零重型依赖）；
2. **输出三种产物**：
   - **核对表**（markdown，给运营审）：团本/大秘境分区，BOSS→装备行（名称/部位/类型/主副属性），统计行（N 团本/N BOSS/N 件；大秘境 N 副本/N 件）；异常行标黄（缺部位/缺类型/特效为空）；
   - **装载 JSON**：字段直接对齐 `boss_loot`（boss_id 由 BOSS 名→game_bosses 匹配）与 `dungeon_loot`（dungeon_id 由副本名→game_dungeons 匹配，boss_id 同理）；匹配不到游戏字典的行单列「待匹配清单」，**禁止自动创建字典条目**；
   - **角色档案 JSON**（`/wjdc me` 产物）：直接对齐用户中心「我的角色」字段（character_name/server_name/server_region/faction/race/class/spec/level/item_level/guild_name/armory_url 留空），供 #24-补丁2 的导入入口使用；
3. **对账模式**：读取数据中心现存数据，输出差异报告（新增/变更/缺失三类），供运营决定录入范围；
4. 转换器只产文件不落库；**录入动作由顾问侧执行**（服务通道 + 复核报告），脚本提供 `--load-json` 产物供其使用。

### WP2 验收

- 用 mock SavedVariables（含正常行+缺字段行+未知 BOSS 行）实测：核对表标黄正确、装载 JSON 对齐表结构、待匹配清单单列、对账三类差异正确；
- 真实导出文件（WP1 运营实测产物）端到端跑通一次；
- commit 规范：「任务书#26-WP1：…」「任务书#26-WP2：…」，三段式；不 push。

## WP3：S1 首跑验证（翻牌前彩排，顾问侧+运营）

1. 运营用插件导出 **S1（12.0）数据**发顾问侧；
2. 转换器跑核对表 + 与数据中心现存 S1 数据对账；
3. 判定标准：抽取准确率 ≥98%、差异全部可解释（字典未录/命名差异）；
4. 通过后管道正式备用：8.13 开服运营导出 S2 → 同流程录入。

### 红线

- 插件零外部依赖、不访问网络、不碰账号数据（只读副本手册）；
- 站点 js/css/html 一律不动（本任务书不产生版本号递增）；
- 匹配不到的字典条目只报告不创建；掉落数据以游戏内导出为准，禁止网络抓图/AI 编造补齐；
- 不动密钥与 .env。
