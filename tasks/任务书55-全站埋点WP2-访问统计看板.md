## WP1：数据层——聚合 RPC + 查询端点 + 90 天滚动清理（SQL 迁移 + server.js）

### 需求

**1. sql/34_task055_analytics_overview.sql（新迁移，幂等、含回滚注释、文末 `NOTIFY pgrst, 'reload schema';`）**

创建两个 SECURITY DEFINER 函数（只读/删 analytics_events，**不得 alter 表结构**）：

a) `analytics_overview(p_start timestamptz, p_end timestamptz, p_grain text, p_page text default 'all') returns jsonb`

- 参数校验（任一不满足即 raise exception，走 PostgREST 400）：
  - `p_grain ∈ ('hour','day','week','month')`；
  - `p_end > p_start` 且 `p_end - p_start ≤ interval '92 days'`（90 天保留 + 2 天余量）；
  - `p_page` 匹配 `^(all|index|decor|data|index:[a-z]+)$`。
- **时区钉死（易错点，必须照做）**：所有分桶按东八区——`date_trunc(p_grain, ts at time zone 'Asia/Shanghai')`，返回的 bucket 序列化为该桶起始时刻的 ISO 串（带 +08:00）；DAU、按日聚合同样按东八区日历日。
- p_page 过滤语义：`'all'`=不过滤；`'index'`=`page ~ '^index:'`（主站整壳）；`'decor'`/`'data'`=精确匹配；`'index:xxx'`=精确匹配单子页。
- 返回 jsonb 固定五键：
  - `series`：`[{bucket, pv, uv}, …]` 按 bucket 升序；pv=`count(*)`，uv=`count(distinct coalesce(uid::text, vid))`；范围内无事件的桶补零（generate_series 造全量桶再 left join，折线不能断）。
  - `cards`：`{pv, uv, dau_avg}`——范围内总 PV、总 UV（整段 distinct 人）、日均 DAU（先按东八区日分桶求每日 distinct 人，再取平均，四舍五入到整数）。
  - `nav`：`[{page, clicks, people}, …]`——`page ~ '^index:' AND page <> 'index:login'`（登录墙不是导航 TAB），clicks=count(*)、people=distinct 人，按 clicks 降序。**左栏全部页签逐项、次数/人数双口径**即由此出。
  - `pages`：`[{page, pv, uv}, …]`——全部 page 分组（含 decor/data），按 pv 降序。
  - `refs`：`[{ref_dom, pv, uv}, …]`——ref_dom 为 null 归并为 `'直接访问'`，按 pv 降序取前 10。
  - `events`：`[{event, cnt}, …]`——按 cnt 降序。

b) `analytics_purge_90d() returns bigint`
- `delete from public.analytics_events where ts < now() - interval '90 days'`，返回删除行数。

c) 权限：两个函数 `revoke all from public, anon, authenticated; grant execute to service_role;`（anon 直调必须 401/404，verify 要验）。

**2. server.js 新增查询端点 `POST /api/analytics/summary`**

- 鉴权两段式（先声明权限要求再实现，开发规范 §2.2）：① 复用现有用户 JWT 校验 helper，未登录/无效 → 401；② 从 token 取 uid，不在 `ANALYTICS_ADMIN_UIDS`（.env，逗号分隔的 uid 列表）→ 403 `{error:'仅管理员可见'}`。
- body `{start, end, grain, page}` 四项校验与 RPC 同规则，非法 → 400 中文错误 json；body 上限 8KB 复用 readBody。
- 通过则 `proxyToSupabase` POST `/rest/v1/rpc/analytics_overview`，原样透传 jsonb 响应；RPC 失败 → 502 `{error:'统计服务暂不可用'}` + console.error，**不泄露内部细节**。
- 限流：同 uid 30 次/分（复用滑窗 Map 写法，与 track 限流桶分离）。

**3. 90 天滚动清理调度（依侦察闸 3 结论二选一）**
- pg_cron 版：迁移文件内附 `select cron.schedule('analytics-purge-90d', '10 4 * * *', $$select public.analytics_purge_90d();$$);`（每天 04:10 服务器时区执行），回滚注释附 `cron.unschedule`。
- server.js 版：启动 10 分钟后首跑、之后每 24h 一次 `proxyToSupabase` 调 `/rpc/analytics_purge_90d`，console.log 删除行数，异常 console.error **不得崩进程**。

**4. .env 新增 `ANALYTICS_ADMIN_UIDS`**（运营 uid，走私聊；.env 本就在 .gitignore，确认不進 git；改完重启服务并回执「已配置」。）

b) **卡片行**：PV / UV / 日均DAU 三张大数字卡（数值取 cards 键；数字用字重强调，不堆字号）。

d) **面板区**（桌面两列、≤768px 单列）：
- 「导航 TAB 排行」：nav 键，CSS 条形，每项显示 `页签名 | 次数 | 人数`（双口径并列）；
- 「分页面」：pages 键，表格 `页面 | PV | UV`（主站各页签、decor、data 分列）；
- 「来源域 TOP10」：refs 键，条形 + `域名 | PV | UV`；
- 「事件 TOP」：events 键，`事件 | 次数`（当前只有 page_view，WP3 补挂后自然丰满，不做额外处理）。

**3. 状态四态齐全**：loading（骨架或「加载中…」）/ 正常 / 空数据（「该时间范围内暂无数据」占位）/ 错误——接口 4xx/5xx/超时 → 面板内错误提示条 + 「重试」按钮（禁止静默失败）；**403 → 整块看板替换为「访问统计仅管理员可见」占位**（不弹错、不闪屏、不反复请求）。
