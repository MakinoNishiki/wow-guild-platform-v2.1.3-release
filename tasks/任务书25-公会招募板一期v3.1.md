## WP1：数据模型（sql/18）

### 1. `guilds` 招募字段（模板化）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| recruiting | bool default false | — | 招募开关 |
| recruit_roles | text[] | 必 | 需求职责（坦克/治疗/输出子集） |
| recruit_specs | text[] | 可 | 需求职业/专精（空=不限） |
| recruit_days | text[] | 必 | 活动日（周一~周日多选） |
| recruit_start / recruit_end | text | 必 | 时段（如 20:00–23:00） |
| recruit_raid_id | uuid→game_raids | 可 | 当前进度团本 |
| recruit_pt / recruit_h / recruit_m | int default 0 | 可 | 三难度已过 BOSS 数 |
| recruit_goal | text | 必 | 团队目标（休闲伐木/H全通/M开荒/千钧一发/进度冲榜，枚举） |
| recruit_ilvl_req | int null | 可 | 装等要求 |
| recruit_wcl_req | text null | 可 | WCL 要求（如「蓝色以上」） |
| recruit_attend_req | text null | 可 | 出勤要求（如「每周≥2天」） |
| recruit_benefits | text[] | 可 | 团队福利多选（合剂大餐/公修/免费代工/爆发药水/新人指导/团建活动） |
| recruit_wcl_url | text null | 加分 | 公会 WCL 链接 |
| contact_type / contact_value / contact_note | text | **必** | 类型（微信/QQ/手机号/战网ID）+号码+备注 |
| recruit_note | text | 可 | 补充说明（兜底长文本） |
| recruit_completeness | int default 0 | — | 完整度快照 0–100（前端按权重表算好写入，排序用） |
| recruit_updated_at | timestamptz | — | 保存即刷新 |

### 2. `job_seeking` 求职表（模板化）

| 字段 | 必填 | 说明 |
|---|---|---|
| user_id / character_id | — | 本人 + 我的角色引用（职业/专精/装等/英雄榜链接自动带入） |
| active bool default true | — | 同一 user 仅一条 active（部分唯一索引） |
| seek_intents text[] | 必 | 求职意向多选（进度团/休闲团/PVP/大米车队/成就团/带新慈善团——与三期多场景同枚举） |
| seek_days text[] + seek_period text | 必 | 可打日多选 + 时段（工作日晚上/周末全天/下午/夜班不定，枚举） |
| seek_experience text | 必 | 副本经验一句话（如「12.0 H全通，M3/8」） |
| seek_wcl_url | 加分 | 个人 WCL 链接 |
| contact_type / contact_value | **必** | 类型+号码 |
| seek_bio text(≤60) | 可 | 一句话自我介绍 |
| seek_completeness int | — | 完整度快照 |
| created_at/updated_at | — | |

### 3. 埋点表 `recruit_events`（与 v2 相同）

id / guild_id null / seeker_id null / event_type CHECK in ('contact_copy','favorite_on','favorite_off') / actor_user_id=本人 / created_at。RLS：insert=authenticated 本人；select=仅超管。

### 4. 视图（anon+authenticated 可读，白名单字段）

- `guild_recruit_view`：recruiting=true，白名单字段（不含 owner_id/invite_code/claim_mode）；
- `job_seeking_view`：active=true，**不含联系方式列**（联系方式仅 authenticated 经表 RLS 读，anon 禁）；视图给 anon 看骨架卡片用——**求职区 anon 只显示骨架不露联系**；登录用户经表读全字段。
- `recruit_favorite_count`：按目标聚合净感兴趣人数（无用户身份）。

### 5. server.js 窄例外（照 #19/#21 风格）

- `job_seeking`：POST/PATCH/DELETE 仅本人行，字段白名单；
- `recruit_events`：仅 INSERT 单行、类型白名单、actor=本人；其余一律拒绝；
- 通用分支与既有逻辑一字不动。

### 6. 完整度权重表（定稿进迁移注释 + 前端实现）

各项权重合计 100：联系方式 25、需求/意向 20、活动时间（日+时段）15、进度/经验 15、团队目标（公会）/可打时段（个人）10、招收要求/福利（公会）或一句话介绍（个人）10、WCL/英雄榜链接 5。**开板上板门槛：必填项全填（完整度≠排序门槛，必填缺项不允许开开关）**；完整度仅影响排序与「优选」标识。

## WP2：双端模板化表单（完整度进度条引导）

### 需求

1. **公会设置「招募信息」区**（owner 编辑）：按 WP1 字段表出**结构化表单**——开关置顶（复用既有开关节控件，成员管理「显示已离队」同款，禁新造）；必填项带 \* 标与未填拦截；活动日星期多选 chips、时段两个时间框；进度=团本下拉+三难度数字（N=该团本 BOSS 数，越界拦截）；团队目标单选 chips；福利多选 chips；联系方式类型下拉+号码+备注；**顶部完整度进度条**（组件形态按规范 §4.10：按权重表实时计算，常态 --gold 金、100% 转 --success 绿，下方一行「资料越完整，推荐位越靠前」）；保存写 completeness 快照+updated_at，走底部吸附保存栏。
2. **用户中心「我的求职」区**：同款模板化表单——开关、选角色（带入职业/专精/装等/英雄榜链接展示）、意向多选、可打日 chips+时段单选、副本经验、WCL 链接、联系方式、一句话介绍（60 字计数）；顶部同款完整度进度条（§4.10）；无角色先引导添加。
3. 开关门槛：必填未齐点开关 → 逐项标红提示，不允许上板。

### WP2 验收

- 两端必填拦截逐项实测；完整度计算与权重表一致（抽 3 组填法对数）；
- 快照落库与 updated_at 刷新；进度越界拦截；
- 两档截图（两端表单+进度条三态）；测试数据自清理复核为零。

## WP3：公开页 recruit.html（模板化卡片 + 权重排序 + 埋点）

### 需求

1. **区块**：「公会招募」（anon 公开）+「团员求职」（anon 见骨架卡（无联系方式）+登录引导；登录见全字段）。
2. **排序（v1 权重机制）**：默认排序 = **完整度降序为主键，同分按 recruit_updated_at/updated_at 降序为次键**（无窗口分层）；完整度 ≥85 的卡片加「优选」金边 tag（卡片常态金边变体按规范 §4.4 增补）；卡片角落显示「资料完整度 xx%」小字。排序规则写成前端单一函数（后续三期换推荐模型时只改这一处）。
3. **招募卡片**：公会名+区域·服务器+团队目标 tag+完整度/优选标识；进度条三难度（x/N 填充，§4.10 迷你族）；需求职责/职业专精 tag（官方图标+职业色）；活动日+时段结构化展示；招收要求（装等/WCL/出勤，有才显示）；福利 chips；WCL 公会链接（可点）；说明展开（复用补丁4 覆盖层机制：展开=全文替换，禁拼接）；**「复制联系方式」（复制成功 toast 完成态反馈；记 contact_copy）+「感兴趣」（登录 toggle，显示 N 人）**。
4. **求职卡片**：职业图标+职业色 tag+专精+装等；意向 chips；可打时间；经验一句话；WCL/英雄榜链接（可点）；一句话介绍；联系方式（登录可见）；本人卡片带编辑/下板。
5. **筛选即时过滤**（招募区：区域/职责/职业/目标+关键词；求职区：职业/职责/意向+关键词），筛选与结果严格一致，清空还原；筛选与默认排序叠加不冲突。
6. 空态/免责/侧边栏/版本串/视觉：同 v2（空态文案、底部「信息由公会/用户自行发布」免责、侧边栏「公会招募」入口、版本串三头同步（index.html / data.html / recruit.html 同一常量）、公示页版式）。
