# 任务书 #12-补丁2：BUG-032 红区成员考勤联动 + REQ-047 取消活动关弹窗

## 0. 背景

任务书 #12 验收遗留两个已确认问题，本次修复后与 #12 未验用例一并验收提交。

## 1. BUG-032（P1）：WCL 同步预览页添加成员后，考勤不联动

**现象**：同步预览页③未匹配（红色）分区点「添加为成员」，成员成功入库并回标"已添加到成员管理"，但该行**仍停留在③分区**；③分区行不写入考勤（设计原定），导致这些实际参战的人考勤是"缺席"。

**预期行为**：添加成员成功后，该角色已成为成员管理名单的一员，**应重新参与对照匹配**——按匹配规则进入①自动出席分区（全勤）或②部分参战分区，随「确认写入考勤」一并写入。

**疑似根因方向（供参考，以实际诊断为准）**：添加成功后未 reload 成员列表（appData.members 是旧快照）就重开/刷新预览，对照匹配用的还是旧名单。

**修复要求**：
1. 添加成功 → **reload 成员列表 → 重跑对照匹配 → 原地刷新预览分区**（不要关闭再重开弹窗，原地更新分区位置即可，减少打扰）；
2. 连续添加多个未匹配角色时，每添加一个就原地更新一次，已添加的依次进入①/②分区；
3. 修复后回归：①②③三个分区计数（自动出席 N · 部分参战 N · 未匹配 N）随添加实时变化；
4. 「忽略」的 role 不受此改动影响（忽略=不添加也不写考勤，保持原样）；
5. 根因写入修改报告。

## 2. REQ-047：取消/恢复活动成功后自动关闭弹窗

**现象**：活动详情弹窗点「取消活动」，toast 成功但弹窗留着，用户不确定操作是否生效。

**修复要求**：
1. 「取消活动」成功（真实写库+reload 完成）→ toast → **自动关闭活动详情弹窗**（列表中该活动灰显+"已取消"徽标即为可视反馈）；
2. 「恢复活动」成功后同样关闭弹窗（行为对称）；
3. 失败时弹窗保持打开 + 错误 toast（与全站模式一致）。

## 4. 验收用例（运营侧）

| # | 场景 | 通过标准 |

| 1 | 同步预览页③红区点「添加为成员」 | 添加成功后该行**移入①自动出席分区**（弹窗原地刷新，不闪关重开） |
