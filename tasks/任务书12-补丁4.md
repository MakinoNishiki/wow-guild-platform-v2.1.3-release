# 任务书 #12-补丁4：导入唯一约束冲突 + 聚合确认行状态即时更新 + 状态列换行

## 0. 背景

补丁 3 验收发现：智能导入报"云端同步出错"（P1）、聚合确认后预览行状态延迟更新（误导）、状态列 2 字换行（难看）。

## 1. BUG-037（P1）：智能导入触发唯一约束 uq_raid_members_guild_name，报"云端同步出错"

**实证**（运营 console 截图）：`unique constraint "uq_raid_members_guild_name" at dbWrite (cloud.js:104) ← syncMember (cloud.js:742) ← saveCloudData (cloud.js:704) ← importExecute (app.js:2288) ← importConfirmRoster (app.js:2237)`。

**诊断要求（先查清楚再修，报告写结论）**：
1. 查 sql/04 建的唯一索引 `uq_raid_members_guild_name` 的**确切定义**：列组合是 (guild_id, name) 还是 (guild_id, name, server)？是否 partial index（是否排除 status='离队'）？
2. 回答三个问题：① 不同服务器同名是否被误拦（REQ-002 只要求同服唯一）？② 已离队成员是否占用唯一位（正确设计：离队成员不应阻挡同名新建，同名离队应走恢复链路）？③ 恢复链路（REQ-042/REQ-048）为何没拦住这次冲突——是判定条件（名字 trim/大小写/服务器比对）与索引不一致，还是索引把离队行也算进去了？
3. 修复方案按诊断结论选：
   - 若索引列组合不对 → 出 sql/09 重建索引（DROP + CREATE，建议 `CREATE UNIQUE INDEX ... ON raid_members(guild_id, name, COALESCE(server,'')) WHERE status <> '离队'`，最终以 REQ-002 语义：同服同名活跃成员唯一）；
   - 若恢复判定与索引口径不一致 → 对齐判定逻辑（名字 trim、服务器规范化）；
4. **用户提示分层**：唯一约束冲突不得再笼统报"云端同步出错"——识别 23505（unique_violation）错误码，给出具体中文提示（如"该成员已存在/与已离队成员重名，请检查"）；其他未知错误才走通用文案；
5. 回归：构造"离队同名→导入（走恢复）""活跃同名→导入（判重跳过）""跨服同名→导入（应允许）"三组用例写进 scripts/verify-smart-import.js。

## 2. BUG-035：聚合确认后预览行状态延迟更新

**现象**：聚合恢复弹窗取消勾选 3 人 → 返回预览页，这 3 行仍显示勾选+"新成员"，直到整个导入执行完才变"已离队同名，未恢复"——等待期误导用户。

**要求**：聚合弹窗确认/返回后**立即**更新预览页对应行：未勾选的行即时取消勾选 + 状态列标"已离队同名，未恢复"（标黄），不等导入执行。

## 3. BUG-036：智能导入预览页"状态"列 2 字换行

**现象**："已离队同名，未恢复"在状态列竖排 4 行，"待补充"也换行。

**要求**：状态列 `white-space: nowrap`（或调列宽/精简文案，如"离队未恢复"），表格无挤压换行；顺带检查同表"专精"列"待补充"换行问题一并处理。
