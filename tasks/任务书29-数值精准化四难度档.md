## WP1：四档数据链（插件 1.0.7 + 转换器 + sql/20 + S1 回填）｜ 8.12 前冻结

### 需求

1. **侦察（先出结论再动手）**：12.x 客户端 EJ 难度档切换可用性——`EJ_SetDifficulty` / `EJ_GetDifficulty`（或新等价 API）存在性与档位 ID 表（随机团队/普通/英雄/史诗）；不可用则回退方案（tooltip 难度行解析 / bonusID 通道）一并给结论。写进修改报告。
2. **插件 1.0.7**：掉落导出按难度档循环采集——逐件切档重扫 tooltip，产出 `primary_tiers` / `secondary_tiers`，结构 `{ lfr={名:值}, normal={…}, heroic={…}, mythic={…} }`（档位 key 用英文枚举，值=该档属性数值表）；**只记存在的档**（某装备无随机档则不出 lfr 键）。采集时长约为现 4 倍属预期，写进度提示。原字段（含 values 两列）格式零改动、向后兼容。
3. **大秘境口径定稿**：大秘境掉落**无四难度**（钥石层数缩放）——tiers 留 null，现 `primary_values/secondary_values`（预览口径）继续作为其唯一数值来源；任务书与转换器注释写明。
4. **转换器**：透传 tiers 两字段进装载 JSON；旧格式文件（无 tiers）转换不报错、tiers 留 null；**冻结声明 v2**（既有字段 + values + tiers，2026-08-12 冻结，S2 按此录入）。
5. **sql/20**：`boss_loot`、`dungeon_loot` 各加 `primary_tiers jsonb null`、`secondary_tiers jsonb null`（幂等 + 回滚注释 + NOTIFY pgrst，迁移纪律同 sql/19）。
6. **S1 回填**：运营上号 `/wjdc all`（1.0.7）→ 导出文件 → 转换 → **定向 PATCH 只写 tiers 两列**（键与幂等纪律同 WP1：boss_id+item_name / dungeon_id+boss_id+item_name），其余字段零触碰。
