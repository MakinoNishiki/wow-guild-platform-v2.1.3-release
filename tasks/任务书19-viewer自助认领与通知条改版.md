# 任务书 #19：viewer 自助认领（窄后门）+ 通知条（toast）改版

> 执行方：Kimi Code　｜　**前置：任务书 #18 已合并部署**（本任务在其代码之上）　｜　两个工作包分开提交　｜　密钥：不涉及

## 背景

- #18 落地了认领体系，但 server.js 代理要求 raid_members 的 PATCH 必须 owner/editor，普通成员（viewer）无法自助认领自己的角色——认领的真实场景是"会长建名单、团员自己领"，必须放开一条**窄后门**。
- 右上角绿色 toast 与用户面板重叠、背景半透明导致不明显，需要改版。

## WP1：viewer 自助认领/解绑（server.js 鉴权窄例外 + 前端入口）

### 后端（server.js authorizeProxyRequest，允许改）

在 raid_members 的通用业务表分支**之前**插入窄例外分支，规则：

1. 仅当 `table === "raid_members"` 且 `method === "PATCH"` 时进入；
2. 请求体字段集合 ⊆ `{user_id}`（多任何字段 → 落入通用分支，按原逻辑 owner/editor 才放行）；
3. 按 filters.id 取目标行（单行）；
4. **放行条件（任一）**：
   - 认领：`body.user_id === 当前用户uid` 且目标行 `user_id IS NULL`（只能认领未被认领的，防抢）；
   - 解绑：`body.user_id === null` 且目标行 `user_id === 当前用户uid`（只能解自己的）；
5. 满足 → 放行；**不满足 → 不要直接 403，落入通用分支**（owner/editor 的改派、编辑等原有权力必须原样保留，viewer 走到通用分支自然被 403）。

要点：这是"开口"不是"改规则"——通用分支逻辑一行不动，窄例外只是给 viewer 一条仅通向你自己的小路。

### 前端（成员管理成员行）

- 未认领成员：所有登录用户（含 viewer）可见「认领」；
- 认领人是自己：可见「解绑」；
- 认领人是他人：只读显示认领人标签（沿用 #18 R4 渲染），无按钮；
- 现有 .action-btns 内其他管理按钮对 viewer 的隐藏逻辑**不动**——认领/解绑入口需要独立于 .action-btns 做角色显隐。

### WP1 验证（curl 级 + 浏览器级）

准备三个账号：owner、viewer甲、viewer乙；成员 X（未认领）、成员 Y（user_id=乙）：

1. viewer甲 PATCH X `{user_id:甲}` → **200**；
2. viewer甲 PATCH X（已被乙认领）`{user_id:甲}` → **403**（防抢）；
3. viewer甲 PATCH X `{user_id:甲, name:"改名"}` → **403**（夹带字段必死）；
4. viewer甲 PATCH Y `{user_id:null}` → **403**（不能解别人）；
5. viewer乙 PATCH Y `{user_id:null}` → **200**（解绑自己）；
6. owner 对 X 做任意正常编辑/改派 → **200**（原权力无损）；
7. 浏览器端：viewer 账号登录，界面上完成一次认领+解绑，全程无 JS 报错。

## WP2：认领反馈 + 全局 toast 改版

### 认领即时反馈（感知层）

- 认领/解绑成功：toast 明确提示（"已认领：XXX"/"已解除认领"），成员行认领人标签**立即**就地更新，不等刷新；
- 失败（被抢/无权限）：toast 显示后端返回的具体原因；
- 在 docs/开发规范.md 的适当章节补一句设计说明：认领状态全系统单一真源（raid_members.user_id），其他端在刷新/切页时一致（刷新级一致，无双写分裂）。

### toast 改版（全站统一组件，不只认领用）

- **位置**：从右上角改为**顶部居中**（`position: fixed; top: 16px; left: 50%; transform: translateX(-50%)`），理由：右上角与用户面板、主操作按钮冲突；
- **背景**：不透明（alpha=1 或 ≥0.95），成功/失败/信息三类配色遵循 DESIGN.md 体系并加深色描边或阴影保证可读；
- **层级**：z-index 置顶，保证不被任何面板遮挡，也不遮挡用户面板与页面主按钮；
- 行为不变：自动消失（沿用现有时长）、多条堆叠不重叠。

### WP2 验收

- 触发一次保存成功、一次保存失败：toast 顶部居中出现，**不遮挡右上角用户面板与"创建活动"等按钮**，背景不透明可读，自动消失；
- 1366×768 与 1920×1080 两种宽度下位置正确；
- 认领/解绑的即时反馈符合上述三条。

标题：`任务书#19-WP2：认领即时反馈+toast 改顶部居中不透明`
