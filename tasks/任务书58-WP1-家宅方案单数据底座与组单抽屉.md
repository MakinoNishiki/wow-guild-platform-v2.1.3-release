## 一、数据底座（SQL 迁移：`sql/35_task058_decor_plans.sql`）

### 需求

1. **新表两张**（用户行级，无公会维度、无 anon 访问）：

```sql
-- ============================================================
-- 增量迁移 35：家宅方案单（任务书 #58-WP1）
-- 内容：decor_plans（方案单头）+ decor_plan_items（方案单明细）。
--   用户行级数据：RLS 全部按 user_id = auth.uid() 行级判定，
--   明细表经 plan_id JOIN 头表归属判定；anon 无任何权限。
--   多方案能力表级预留（WP2 才开放 UI），WP1 前端只用「每用户当前一个方案」。
-- 执行方式：SSH + docker exec psql（supabase_admin 角色），幂等可重复执行
-- 执行前：纯新增表，零触碰既有表，无需备份既有数据
-- 执行后：NOTIFY pgrst 重载 schema 缓存 + REST 复核（匿名 401/403、登录用户仅见己行）
-- 回滚说明：
--   DROP TABLE decor_plan_items;
--   DROP TABLE decor_plans;
--   NOTIFY pgrst, 'reload schema';
-- ============================================================

CREATE TABLE IF NOT EXISTS decor_plans (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  name        text NOT NULL DEFAULT '我的方案单',
  created_at  timestamptz DEFAULT now(),
  updated_at  timestamptz DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_decor_plans_user ON decor_plans(user_id);

CREATE TABLE IF NOT EXISTS decor_plan_items (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  plan_id     uuid NOT NULL REFERENCES decor_plans(id) ON DELETE CASCADE,
  record_id   integer NOT NULL REFERENCES decor_catalog(record_id),
  qty         smallint NOT NULL DEFAULT 1 CHECK (qty >= 1),
  added_at    timestamptz DEFAULT now(),
  UNIQUE (plan_id, record_id)
);
CREATE INDEX IF NOT EXISTS idx_decor_plan_items_plan ON decor_plan_items(plan_id);

ALTER TABLE decor_plans ENABLE ROW LEVEL SECURITY;
ALTER TABLE decor_plan_items ENABLE ROW LEVEL SECURITY;

-- decor_plans：属主全维度
CREATE POLICY select_own ON decor_plans FOR SELECT TO authenticated USING (user_id = auth.uid());
CREATE POLICY insert_own ON decor_plans FOR INSERT TO authenticated WITH CHECK (user_id = auth.uid());
CREATE POLICY update_own ON decor_plans FOR UPDATE TO authenticated USING (user_id = auth.uid()) WITH CHECK (user_id = auth.uid());
CREATE POLICY delete_own ON decor_plans FOR DELETE TO authenticated USING (user_id = auth.uid());

-- decor_plan_items：经头表归属判定
CREATE POLICY select_own ON decor_plan_items FOR SELECT TO authenticated
  USING (EXISTS (SELECT 1 FROM decor_plans p WHERE p.id = plan_id AND p.user_id = auth.uid()));
CREATE POLICY insert_own ON decor_plan_items FOR INSERT TO authenticated
  WITH CHECK (EXISTS (SELECT 1 FROM decor_plans p WHERE p.id = plan_id AND p.user_id = auth.uid()));
CREATE POLICY update_own ON decor_plan_items FOR UPDATE TO authenticated
  USING (EXISTS (SELECT 1 FROM decor_plans p WHERE p.id = plan_id AND p.user_id = auth.uid()));
CREATE POLICY delete_own ON decor_plan_items FOR DELETE TO authenticated
  USING (EXISTS (SELECT 1 FROM decor_plans p WHERE p.id = plan_id AND p.user_id = auth.uid()));

NOTIFY pgrst, 'reload schema';
```

2. **执行纪律**：先备份 → 执行 → `NOTIFY pgrst, 'reload schema';` → REST 复核，四步留输出：
   - 复核①：`\d decor_plans` / `\d decor_plan_items` 结构输出；
   - 复核②：anon key REST `GET /rest/v1/decor_plans` 应 401/403（无权限）；
   - 复核③：测试账号写入一条方案+两件明细 → 仅本人可读 → 删除自清理并复核为零。

### 一节验收

- 迁移文件入 `sql/` 目录（编号 35），含回滚说明；执行输出与三条复核结果齐全；测试数据自清理为零。

## 三、组单抽屉·形态A（双壳，渲染入 decorData.js）

### 需求

1. **图鉴卡片加「加入方案单」按钮**（双壳同渲染）：点击 → 该件入抽屉（已存在则 qty+1）→ 徽标与抽屉即时更新。按钮视觉从属卡片既有版式，不破坏卡片尺寸。
2. **抽屉结构**（对齐 D5 预览稿第 1 页）：
   - 右侧固定抽屉，宽约 380px；头部「我的方案单」+ 总件数；行 = 小图标 + 名称（品质色）+ 数量步进（−/＋）+ 移除；底部 = 容量合计「{sum} / 2,000」+「保存」+「导出文本清单」按钮。
   - 容量参考上限为常量 `DECOR_PLAN_CAPACITY_REF = 2000`（注释写明：游戏内实际预算随住宅等级变化，此处仅参考）；**超限仅合计数字标红警示，不阻断任何操作**。
   - 抽屉入口按钮带**总件数徽标**，实时更新；空态有引导文案（「从左侧图鉴挑装饰加入方案单」）。
   - 768px 窄屏：抽屉全宽覆盖，开合有 150–250ms transform/opacity 动效；暗色主题、CSS 变量、≤8px 圆角。
   - 抽屉非弹窗、内容自动暂存无丢失风险，**不登记 modalDirtyChecks**（报告说明此判定）。
3. **未登录暂存（D2 红线实现）**：
   - 组单内容全程自动写 localStorage 草稿，key = `wb_decor_plan_draft`，结构 `{ items: [{ record_id, qty }], updatedAt }`；两壳同域同 key。
   - **公示壳 decor.html 恒视为未登录**（anon 壳无登录态）：抽屉可用、导出可用；点「保存」→ 提示文案「保存方案单需要登录，登录后组单内容不丢」→ 跳主站 `index.html` 登录页。
   - 主站登录成功后：方案单模块检测草稿非空 → 还原进抽屉（图鉴页切入即可见）→ 用户确认后自行点「保存」写库。**登录跳转往返草稿不丢**为硬验收项。
4. **草稿与云端合并规则**（已登录进图鉴页时）：草稿为空 → 用云端；云端为空 → 用草稿；两者皆非空 → 草稿优先还原进抽屉（草稿是用户最近操作），并在抽屉顶部给一次性提示「已还原你上次未保存的组单，保存后覆盖云端」。保存成功后清空草稿。
5. **埋点挂点**（事件名回写 docs 埋点纪律章 + server.js `TRACK_EVENTS` 常量同步扩列，一处常量一处文档）：
   - `decor_plan_add`（props: `{ from: 'card' }`，不带 record_id 之外的任何内容——props ≤2KB 红线内，record_id 可带）
   - `decor_plan_save`（props: `{ items, capacity }` 计数）
   - `decor_plan_export_text`（props: `{ items }`）
   - 埋点静默兜底红线不变：任何异常不得影响业务。
6. **静态资源版本串**：index.html / decor.html 引用串按当日日期同步递增（开发规范第五章先例）。

### 三节验收

- 双壳截图：应用内壳 + decor.html 公示壳（桌面 + 768px 窄屏各一套），抽屉开合/步进/移除/徽标计数逐项过。

## 四、导出文字链路（弹窗·仅文字模式）

### 需求

1. **入口**：抽屉底部「导出文本清单」按钮；未登录也可用（导出不写库）。
2. **弹窗**（对齐 D5 预览稿第 4 页左弹窗，**WP1 不放图片模式 tab**）：
   - 标题「导出方案单」；正文为**可编辑 textarea**，默认填入生成的文字预览（所见即所得）；顶部提示条「改动只影响本次导出，不回写方案单数据」。
   - 「复制文本清单」主按钮（gold）→ 写剪贴板，成功 toast；`navigator.clipboard` 不可用时降级为选中 textarea 全文并提示手动复制。
   - **含未保存编辑内容，必须登记 modalDirtyChecks**：textarea 被改动后，遮罩点击/ESC 须二次确认（开发规范 4.6）。
3. **默认文本格式**（逐行规格，不得自由发挥）：

```
【魔兽管家 · 家宅方案单】{方案名}
{名称} ×{qty}（容量 {placement_cost}/件）
……（逐行）
——————————
合计 {总件数} 件 · 容量 {sum}
魔兽管家 · 家宅图鉴免费组单：https://wow.ddctl.com/decor.html
```

   - 方案名取当前方案 name（草稿态/未保存 = 「我的方案单」）。
   - 尾行链接固定 `https://wow.ddctl.com/decor.html`，不得在文本其他位置再插链接。
4. 埋点 `decor_plan_export_text` 挂「复制文本清单」点击（见第三节第 5 条）。

### 四节验收

- 弹窗截图（含编辑态）；复制成功 toast 与降级路径各验一次；textarea 改动后遮罩/ESC 二次确认生效截图；生成文本与抽屉内容逐行一致（报告附对照样例）。
