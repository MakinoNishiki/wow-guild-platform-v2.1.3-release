## 一、背景与目标

#15 后架构：后端+数据在国内（腾讯云上海 101.35.124.22），前端静态文件仍在美国服务器（ddctl.com）——用户每次打开网站，页面文件跨太平洋下载，首开慢且偶发抽风，是全站最后一段跨境链路。

**目标**：前端静态文件整体迁至国内服务器，与后端同机托管，全站纯国内：

1. 新访问地址：**`https://101.35.124.22:8080`**（Caddy 静态站点，复用 #15 的 Let's Encrypt IP 证书）；
2. ddctl.com 改为自动跳转页（运营/朋友另行上传，不在本任务书执行范围，但验收要查跳转效果）；
3. 美国服务器就此退役，今后前端更新一律发国内。

**非目标**：不换域名、不备案、不改任何业务代码与后端配置。

**红线**：cloud.js 当前已是指向 `https://101.35.124.22:8443` 的新配置——部署前必须核验，**严禁把旧配置（supabase.co）带上线**。

## 三、执行步骤

### S1 前端整包与配置核验
1. 打包前端（index.html / js / css / 素材文件全量）；
2. **部署前 grep 核验**：包内不得出现 `supabase.co`；cloud.js 指向必须为 `https://101.35.124.22:8443`；
3. 检查静态资源引用路径（相对/绝对）在新端口下不会 404。

### S2 Caddy 静态站点
1. Caddyfile 增加 8080 站点：静态文件服务 + 复用 IP 证书（与 8443 同一张）；
2. 单页应用如有多页路由，配 try_files 回退 index.html；
3. 配 gzip、合理的静态缓存头；
4. reload Caddy，确认 8443 业务零影响（先验证 API 仍正常再进入下一步）。

### S3 部署与自测
1. 整包上传至站点目录，权限正确；
2. curl 自测：首页 200、证书链有效、JS/CSS 加载 200；
3. 真浏览器实测：打开→登录→核心功能一轮→F12 Network 全绿。

### S4 收尾
1. 确认证书续期 cron 同时覆盖（同一张证书，8080 无需额外配置，但要在修改报告中实证续期后 8080 正常）；
2. 修改报告（实际改动点/Caddyfile 配置摘要/实测证据/台账登记/changelog 补录）；
3. **未经验收不提交 git**。
