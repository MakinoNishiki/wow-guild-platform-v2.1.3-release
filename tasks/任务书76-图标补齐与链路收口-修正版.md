## 二、icon 回补方案

### 2.1 数据来源（先查证）

**来源 A：Exporter 采集数据**
- WoWButlerExporter 在扫描副本掉落时已采集 `iconName`/`iconID`
- 位置：需确认（WTF SavedVariables / 导出 JSON / 其他）

**来源 B：Decor 采集数据**
- WoWButlerDecor 在扫描家宅图鉴时已采集 `icon_file_id`
- 但 decor_catalog 与 boss/dungeon 是不同数据域，大概率不重叠

**来源 C：Wowhead 反查**
- Exporter/Decor 覆盖不了的，从 Wowhead 手工查 `icon_name` → `icon_id`

### 2.2 回补步骤

```
Step 1: Code 从 Exporter 采集数据中提取 icon 映射
        格式：official_item_id → icon_id
        
Step 2: Code 比对现有缺失清单
        boss_loot 156 条缺失 → Exporter 能覆盖多少？
        dungeon_loot 221 条缺失 → Exporter 能覆盖多少？
        
Step 3: 运营从 Wowhead 补剩余缺失
        手工查 icon → 填入 CSV
        
Step 4: Code 生成 SQL 批次（同 sql/38 格式）
        UPDATE boss_loot SET icon_id = ? WHERE official_item_id = ? AND icon_id IS NULL;
        UPDATE dungeon_loot SET icon_id = ? WHERE official_item_id = ? AND icon_id IS NULL;
        
Step 5: 运营执行 SQL（自建 Supabase 实例）
        备份 → 单事务执行 → 复核 → 无问题 COMMIT
        
Step 6: 前端验证
        公示页装备卡片显示图标
```

### 2.3 SQL 批次格式（sql/43）

```sql
-- sql/43: icon_id 回补（boss_loot + dungeon_loot）
-- Generated: 2026-10-16

-- === 前置说明 ===
-- 1. 本批次仅 UPDATE icon_id，不 INSERT 新数据
-- 2. 仅更新 icon_id IS NULL 的记录
-- 3. 运营执行前必须备份

-- === Rollback ===
-- 无（UPDATE 无简单 rollback，执行前必须备份）

-- === boss_loot icon 回补 ===
UPDATE boss_loot SET icon_id = 5342966 WHERE official_item_id = 249922 AND icon_id IS NULL;
UPDATE boss_loot SET icon_id = 5342967 WHERE official_item_id = 249923 AND icon_id IS NULL;
-- ... 共 N 条

-- === dungeon_loot icon 回补 ===
UPDATE dungeon_loot SET icon_id = 5342968 WHERE official_item_id = 271680 AND icon_id IS NULL;
-- ... 共 N 条

-- === 复核 ===
SELECT 'boss_loot' AS table_name, COUNT(*) AS null_count FROM boss_loot WHERE icon_id IS NULL
UNION ALL
SELECT 'dungeon_loot', COUNT(*) FROM dungeon_loot WHERE icon_id IS NULL;
```
