# 任务书 #12-补丁：P0 紧急修复（BUG-026/029/030 + BUG-031 + 重置文案）

## 0. 背景

任务书 #12 浏览器验收发现 3 个 P0 问题，#12 暂缓提交 git，本补丁修复并验收通过后与 #12 内容一并提交。**本补丁所有修复必须先写清根因再动手**（开发规范：先诊断后动手）。

## 1. BUG-026（P0）：WCL 同步预览页「添加为成员」无响应且阻塞考勤写入

**现象**：同步预览页未匹配（红色）分区点击「添加为成员」，无任何反应、无 loading、无错误提示；并导致无法写入考勤。

**要求**：
1. 先诊断根因（事件绑定？异常被吞？鉴权？），写进修改报告；
2. 修复添加链路——按任务书 #11 设计，应复用智能导入预览链路（预填进导入预览页）；按钮加 loading"添加中..."+ 失败中文提示；
3. **添加失败/未处理不得阻塞主流程**：未匹配角色无论是否添加，「确认写入考勤」都必须可用（未匹配角色本就不写入考勤，这是设计原定行为）；检查当前是否因该按钮异常拖死了整个弹窗的写入链路；
4. 添加成功后该行从红色分区移除或标"已添加"，防重复点击。

## 2. BUG-029（P0）：批量删除活动"假成功"——toast 成功但列表不刷新

**现象**：批量删除活动后右上角 toast"活动已删除"，但列表项仍在，手动刷新浏览器才消失。

**要求**：
1. 这违反开发规范 1.2.2（写→reload→render，提示以真实结果为准），属于假成功家族复发。**根因必须写清**：是删除后没走 reload？reload 了但 render 漏了该列表？还是异常被 catch 吞掉照常 toast？
2. 修复后自查**本次 #12 所有新增写路径**（批量删成员、批量标记、取消/恢复活动、软删除恢复）是否同病——逐条在修改报告里列出"该路径 toast 前是否已完成真实 reload"；
3. 回归：scripts/ 补一条针对批量删除的"删除后列表真实消失"验证（可走接口层断言）。

## 3. BUG-030（P0）：偶发页面刷新后账号/数据模块加载不全

**现象**：刷新或打开网页时，偶发账号信息或部分数据模块加载不出来（非必现）。

**要求**：
1. **先加诊断再修复**：在登录态恢复、reloadData 各表拉取、render 的关键节点加 console.debug 计时与失败标记；对加载失败的模块在页面上给出可见提示（不要静默空白）；
2. 根据日志定位根因（token 恢复竞态？某表请求失败中断后续？），能修则修，不能立修则在报告里给出根因分析与方案；
3. 报告附诊断操作步骤（让运营下次遇到时如何抓取 console 日志）。

## 4. BUG-031：离队成员操作列按钮修正

**现象**：软删除后成员变灰显"离队"，但操作列删除按钮仍在（点了无意义，形成功能废件）。

**要求**：离队成员操作列**隐藏"删除"按钮，改为"恢复"按钮**（复用 REQ-042 恢复链路：update status='正式'，按钮 loading + 成功 toast）；活跃成员操作列不变。

## 5. 文案修正：「重置」→「重置筛选」

考勤筛选条右侧「重置」按钮文案改为「重置筛选」，并加 title="清空全部筛选条件"。

1. `node --check` 全过；`verify-authz.js` 回归全绿；

3. 修改报告列出 #12 全部新增写路径的"toast 前真实 reload"自查表；
4. docs/问题与需求清单.md：BUG-026/029/030/031 登记；
5. **不提交 git**：运营验收本补丁 + #12 遗留用例全绿后，#12 与本补丁**合并一次提交**。

## 7. 验收用例（运营侧）

| # | 场景 | 通过标准 |
|---|------|---------|
| 1 | WCL 同步预览页点「添加为成员」 | 按钮 loading → 成功有提示/失败有中文错误；成功后该行状态变化 |
| 2 | 不处理任何未匹配角色直接点「确认写入考勤」 | 正常写入，不被阻塞 |
| 3 | 批量删除 2 个活动 | toast 出现后列表**立即**消失，不刷新浏览器 |
| 4 | 批量删成员/批量标记/取消活动/恢复成员 | toast 出现后界面立即反映，全部不需要手动刷新 |
| 5 | 连续刷新页面 5 次 | 账号信息、各模块数据每次完整加载；若有失败，页面有可见提示而非静默空白 |
| 6 | 离队成员操作列 | 无删除按钮，有"恢复"按钮；点恢复后成员回到活跃名单 |
| 7 | 筛选条"重置筛选" | 文案正确，点击后所有筛选条件清空 |
