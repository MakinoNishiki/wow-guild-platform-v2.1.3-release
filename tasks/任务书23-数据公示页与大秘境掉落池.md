## WP1：大秘境掉落池主数据 + 字典表匿名读开放（sql/16）

### 需求

1. **`game_bosses` 扩展副本归属**：加 `dungeon_id uuid null references game_dungeons(id)`；一个 BOSS 要么属团本（raid_id）要么属副本（dungeon_id），加 CHECK 约束二选一（raid_id 与 dungeon_id 恰有其一非空）；数据中心 BOSS 区块同步支持挂副本。
2. **新表 `dungeon_loot`**：
   - `id uuid pk default gen_random_uuid()`
   - `dungeon_id uuid not null references game_dungeons(id) on delete cascade`
   - `boss_id uuid null references game_bosses(id)`（可空 = 无法归属具体 BOSS 的整体池装备）
   - `item_name text not null`、`slot text`、`item_type text`、`official_item_id text`、`note text`、`effect text`、`primary_stats text[]`、`secondary_stats text[]`（REQ-054 字段体系，与 boss_loot 同义）
   - `created_at / updated_at timestamptz default now()`
   - 唯一约束 (dungeon_id, boss_id, item_name)——**注意 PG 的 NULLS DISTINCT 陷阱**：boss_id 可空时普通唯一约束对 NULL 不去重，用 `nulls not distinct`（PG15+）或 coalesce 表达式唯一索引，任选其一并在迁移文件注释说明
3. **匿名读开放（仅限字典表）**：对 game_seasons / game_raids / game_bosses / boss_loot / tier_sets / game_dungeons / dungeon_loot / game_classes / game_specs 增 anon 角色 SELECT 策略（既有 authenticated 策略保留，叠加不替换）；**不得触碰任何业务表/用户表的策略**。
4. **RLS 写防线**：dungeon_loot 写 = 仅超管（app_metadata.role='superadmin'），与其余主数据表一致；server.js 主数据代理分支把 dungeon_loot 加入超管表白名单（分支风格照既有 9 表，不改既有分支逻辑）。
5. **数据中心维护扩展**：新增「大秘境掉落」区块——按副本 → BOSS 分组 CRUD（BOSS 列可空 = 整体池条目），批量录入复用 boss_loot 的格式与校验，首两列为副本名/BOSS 名（BOSS 可留空）；BOSS 区块支持 dungeon_id 录入。仅超管可见可操作（现成守卫）。
6. 迁移纪律照旧：备份 → 执行 → `NOTIFY pgrst` → 文件头部注释附完整回滚语句（含 anon 策略撤销）；执行通道 = SSH + docker exec（同 sql/15，supabase_admin 角色）。

### WP1 验收

- sql/16 执行输出 + REST 复核：新表/新列可达、CHECK 约束生效（双挂/双空均拒绝）、唯一约束含 NULL 场景实测；
- **匿名读矩阵**：anon key 直连读 9+1 张字典表 200；anon 读 guilds / raid_members / guild_members / claim_requests / wishlists / loots / activity_attendance **必须全部 403 或空集**（逐表实测，一项不过即返工）；
- 超管经代理对 dungeon_loot 增改删 200；普通用户写 403（代理层 + RLS 层各验一次）；
- 数据中心 BOSS 挂副本 + 大秘境掉落区块 CRUD + 批量录入浏览器实测（含非法行报错行号）；
- verify-master-data.js 扩展断言并全绿；测试数据自清理复核为零。

## WP2：免登录公开页「数据公示」

### 需求

1. **独立公开页**（如 `data.html`，稳定 URL 可分享）：无登录态、无注册引导、无侧边栏；顶部品牌区（魔兽管家 logo + 「数据公示」标题 + 赛季切换下拉）；未登录直接可看，已登录用户访问同样正常。
2. **读取通道**：anon key 直连 PostgREST（WP1 已开匿名读）；不依赖登录、不经过代理；加载失败给友好重试界面，不得白屏。
3. **页面内容**（全部只读）：
   - **赛季切换**：下拉读 game_seasons，默认 is_current 赛季，切换即全页联动；
   - **团本掉落池**：团本 → BOSS → 装备三级浏览；装备卡片复用 REQ-054 体系（部位/类型/特效 #1eff00 游戏绿/主副属性标签）；
   - **大秘境掉落池**：与团本**明确分区**（独立区块 + 「大秘境」徽标，is_new 新本带标记）；副本内按 BOSS 分组展示，顶部提供「整体池 / 按 BOSS」视图切换（默认按 BOSS）；BOSS 未归属条目归入「整体池」组；
   - **套装一览**：赛季 × 职业 × 专精分行（set_name + 2 件/4 件效果），职业色点缀；
   - 筛选：部位/类型筛选 + 装备名关键词搜索（对团本与大秘境两区同时生效）。
4. **登录用户入口**：主应用侧边栏新增「数据公示」项（全角色可见，新开标签页打开公开页；图标贴合现有风格）。
5. **视觉与性能**：沿用暗色主题体系，公开页独立成版式（居中窄版，不套主应用框架）；静态引用带版本号查询串（#22 WP3-② 确立的机制沿用）；首屏直出，零阻塞弹窗。
6. 空态：无数据赛季显示「该赛季数据维护中」，分区空态独立互不影响。

- **隐身窗口（未登录）直开 URL**：三区块完整渲染、赛季切换联动、筛选搜索生效——这是核心验收路径；
