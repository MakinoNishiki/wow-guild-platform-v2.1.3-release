## 范围

### A 组：统计口径（P1，核心）

**BUG-014：Top5 出勤率统计错误**
- 现象：成员有"缺席/请假"记录，Top5 排行仍显示 100% 出勤率；仪表盘与考勤明细不一致。
- 要求：
  1. 先用脚本复现（创建活动 → 标记混合状态 → 读取统计接口/页面数据），拿到错误口径的证据；
  2. 定位计算逻辑：出勤率的分子分母定义是什么？"请假""替补"计入还是排除？"缺席"是否被错误地按出勤统计？Top5 与成员详情页是否两套算法；
  3. 统一口径并写进代码注释：**出勤率 = 出勤次数 ÷ 应到次数；应到 = 全部已标记记录；请假计入应到但不计入出勤；替补按出勤计**（若发现现有产品逻辑与此不同，列进报告待确认，不要擅自改口径）；
  4. 全站所有显示出勤率的位置（成员列表、Top5、统计报表、仪表盘）必须同源同算法。

### B 组：权限与功能补漏（P1）

**BUG-015：非 owner 成员缺"退出公会"入口**
- 在公会设置（或成员管理适当位置）为非 owner 成员提供"退出公会"按钮；
- 二次确认弹窗；退出后清除本地会话中的公会上下文，返回"创建/加入公会"页；
- owner 不显示该按钮（owner 退出 = 解散/转让，属另一需求，不做）。

**BUG-017：viewer 在心愿单模块仍显示批量删除勾选框**
- viewer 模式下隐藏全部勾选框与批量操作栏（与 BUG-012 权限门同一规则，属遗漏补点）。

**REQ-007：装备分配 ↔ 心愿单双向联动**
- 新增装备分配勾选"心愿单装备"保存时：若该成员心愿单中**无**此装备记录 → 自动创建一条心愿记录并直接标记"已获取"；若已有 → 标记"已获取"（维持现有行为）；
- 删除装备分配记录时：联动取消心愿单"已获取"标记（维持现有行为）；
- 自动创建的心愿记录：优先级取默认值，来源备注"装备分配联动"。

### C 组：性能与数据（P2）

**BUG-016：删除活动响应慢**
- 定位慢点（级联删除考勤 + reload 链放大？），给出优化：删除后单次 reload + 单次 render，不做全量多轮刷新；
- 若根因涉及批量代理往返，做能做的优化即可，残余记入技术债。
