# 任务书 #12：考勤专项（REQ-001/017/018/020/028/029/037/038/042 + BUG-023/024）

## 0. 设计依据（已与运营确认，不得擅自变更）

1. **REQ-020 活动状态模型**：活动状态分"正常/已取消"。**已取消活动的考勤不计入任何人的应到与出勤率**（没组起来的晚上不惩罚任何人）；可随时改回正常；
2. **REQ-028 冲突检测**：只警告不禁止；活动新增可选「团队标签」自由文本（如 1 团/2 团），**冲突只在同标签活动之间检测**（双方都无标签视为同组）；用户明知冲突仍创建的，时间冲突的活动在活动列表高亮显示；远期多团队正式模型已登记 REQ-041（观察池，本任务不做）；
3. **REQ-017**：考勤页支持勾选部分成员批量标记（现有"全部出席/缺席/替补/请假"四键保留）；活动列表支持多选批量删除，**二次确认弹窗必须列出待删活动名称**；
4. **REQ-042（新增）**：成员管理支持批量删除，同样二次确认 + 列出待删成员名 + 按钮防重复点击；删除成员需提示其关联考勤/装备记录保留（成员删除不级联删历史数据，考勤/装备记录中显示"已离队"样式）；
5. **REQ-018 筛选**：按成员（下拉）/按状态（出席/缺席/请假/替补多选）/按时间范围（近7天/近30天/本赛季/自定义）；筛选结果与出勤率小计实时联动；已取消活动默认不显示，提供"含已取消"开关；
6. **REQ-001**：任何活动（含已结束）随时可改任何成员状态，改完报表/出勤率即时重算；不做锁定机制（确认过的过度设计）；
7. **BUG-023**：考勤默认**列表视图**；用户手动切换后按"账号+公会"记忆（localStorage key 含 userId+guildId）；身份升降级不得影响视图偏好；
8. **BUG-024**：智能导入"确认导入"按钮 loading 态"导入中..."+ 防重复点击；
9. **REQ-038**：WCL 同步写入中，按钮旁显示"数据写入需要几秒，请勿关闭页面"；
10. **REQ-037**：WCL 同步成功后考勤区顶部挂常驻提示条："已从 WCL 导入 N 人考勤。日志以外的成员请手动标记（请假/替补），未标记的默认缺席。"该活动所有成员均有状态后自动消失。

## 1. 数据库变更（sql/08）

新建 `sql/08_activities_status_team_tag.sql`：

```sql
ALTER TABLE activities ADD COLUMN IF NOT EXISTS status text NOT NULL DEFAULT 'normal';
ALTER TABLE activities ADD COLUMN IF NOT EXISTS team_tag text;
-- 回滚：ALTER TABLE activities DROP COLUMN IF EXISTS status, DROP COLUMN IF EXISTS team_tag;
```

status 取值约束：'normal' / 'cancelled'（服务端校验白名单，非法值 400）。修改报告提醒运营到 Supabase SQL Editor 执行。

**鉴权注意**：activities 新增列后，authorizeProxyRequest 的行归属联查逻辑不得受影响；status/team_tag 写入仍走 owner/editor。

## 2. 统计口径改动（重点，动 getAttendanceStats）

- `getAttendanceStats()` 增加过滤：**status='cancelled' 的活动下的考勤记录，不计入应到、不计入出勤**；
- 全站所有用到出勤率的地方（成员排行/月度统计/Top5/报表）统一走该函数，禁止各自另写过滤；
- 已取消活动的记录在数据库中保留（改回正常即恢复统计）。

## 3. 功能实现明细

### 3.1 活动状态（REQ-020）
- 活动详情/编辑弹窗加"取消活动 / 恢复活动"切换（edit-only）；
- 列表中已取消活动灰显 + "已取消"徽标；
- 考勤区显示"活动已取消"水印，状态标记控件禁用；
- 取消/恢复均为写操作，走 cloudCrud 铁律（真实写库成功才提示）。

### 3.2 团队标签 + 冲突检测（REQ-028）
- 创建/编辑活动弹窗加"团队标签"输入框（可选，placeholder：如 1 团 / 2 团，留空则为默认团）；
- 保存时检测：同公会、同团队标签（含双空）、日期相同且时间段交叉的已有活动 → 黄色警告条"与活动《XXX》（HH:MM-HH:MM）时间冲突"，**不阻断保存**；
- 存在时间冲突的活动，在活动列表中加黄色左边条高亮 + 冲突图标（悬停提示冲突对象）。

### 3.3 批量标记（REQ-017-A）
- 考勤区勾选成员后，顶部出现批量条："已选 N 人：标记为 [出席/缺席/替补/请假]"，仅作用于勾选成员；
- 批量写遵守规范 1.2.2：批量写 → 单次 reload → 单次 render。

### 3.4 活动批量删除（REQ-017-B）
- 活动列表加复选框 + "批量删除"按钮（edit-only）；
- 二次确认弹窗**逐条列出待删活动名称+日期**，红色警告"删除后不可恢复"；
- 按钮防重复点击 + loading"删除中..."。

### 3.5 成员批量删除（REQ-042）
- 成员管理列表加复选框 + "批量删除"按钮（edit-only）；
- 二次确认列出待删成员名，提示"其历史考勤/装备记录将保留并标记为已离队"；
- 历史记录中已删成员显示灰色"已离队"样式，不出现在新活动考勤名单中；
- 按钮防重复 + loading。

### 3.6 考勤筛选（REQ-018）
- 筛选条：成员下拉 / 状态多选 / 时间范围（近7天/近30天/本赛季/自定义起止）；
- 出勤率小计随筛选实时重算（复用 getAttendanceStats，传入筛选后的记录集）；
- "含已取消"开关默认关。

### 3.7 考勤编辑（REQ-001）
- 验证并确保：已结束活动的考勤仍可编辑，编辑后所有统计即时重算；
- 若现状已支持，则在回归用例中补一条验证，不重复开发。

### 3.8 团本下拉（REQ-029）
- "团本名称"改为下拉 + 可手输兜底（输入过滤）；
- 静态清单（含 12.0/12.0.5/12.0.7）：尼鲁巴尔王宫、孢陨幽境等当前版本团本，清单做成 js/ 内常量数组，注释标明"主数据层 V2.2 上线后切换为数据库驱动（REQ-003/004）"；
- "最近使用"置顶（按公会记忆最近 3 个）。

### 3.9 三个提示类（REQ-037/038、BUG-024）
- 按第 0 节文案与规则实现；REQ-037 提示条样式用现有 toast/横幅体系，不新增组件风格。

### 3.10 视图偏好（BUG-023）
- 考勤默认列表视图；localStorage key 格式 `attendanceView:{userId}:{guildId}`；
- 排查并修复身份变化导致视图重置的根因（疑似 key 未含用户维度或身份切换时重置了偏好），修改报告写清根因。

## 4. 安全与规范红线

- 所有新写操作走 authorizeProxyRequest（owner/editor）；viewer 前端隐藏入口 + 服务端 403；
- 批量删除/批量标记遵循规范 1.2.2 批量条款；
- 弹窗防误关（规范第四章第 6 条）：批量删除确认弹窗、编辑弹窗有未保存内容时二次确认；
- 禁止假成功；所有新按钮 loading + 防重复。
