## 二、执行路径

### 方式 A（推荐，如果 Code 有 SSH 权限）

Code 通过 SSH 直连自建实例执行完整 sql/38：

```bash
# SSH 到自建实例
ssh <user>@101.35.124.22

# 执行 DDL + DML（单事务）
docker exec -i supabase-db psql -U supabase_admin -d postgres -f /path/to/38-s2-data-patch-worldboss-table.sql

# 或内联执行
docker exec supabase-db psql -U supabase_admin -c "$(cat 38-s2-data-patch-worldboss-table.sql)"
```

**注意：**

- 用 `supabase_admin` 角色（postgres 角色可能无 public schema CREATE 权限）
- psql -c 多语句为单事务，部分失败自动回滚
- 执行后 `\dt world_boss_loot` 确认表存在

### 方式 B（拆分执行）

如果 Code 无 SSH 权限：

**Part 1（DDL，需运营执行）：**

- 运营 SSH 到自建实例 → 执行 CREATE TABLE world_boss_loot + COMMENT + NOTIFY

**Part 2（DML，Code 执行）：**

- Code 用 service_role key 走 PostgREST 批量 INSERT boss_loot ×4 + dungeon_loot ×58
