## WP1：图标管线（脚本 + 本机工具操作，不涉及数据库）

### 需求

1. **fileID → PNG 批量导出**
   - 输入：decor_catalog 全部非空 icon_file_id（2021 个）。取数方式：anon key 直连 PostgREST 只读拉取（`GET /rest/v1/decor_catalog?select=record_id,icon_file_id&icon_file_id=not.is.null`，注意分页 limit/offset，默认单页上限 1000），或复用 #49 留档 decor_catalog.json（scripts/decor/out/，已在 Code 本机）。
   - **首选通道：wow.export 在线模式**（Marlamin/wow.export，GitHub 活跃维护，支持无客户端从暴雪公共 CDN 流式取文件、BLP 原生导出 PNG）。在 Code 本机（Windows）下载运行，无需游戏客户端、无需国服 API（国服 API 玄学不赌的裁定在案）。
   - **备选通道：wago.tools API**（按 FileDataID 取 CASC 文件字节流，可钉版本；BLP→PNG 需另配转换）。仅在 wow.export 在线模式跑不通时启用，启用前先报告。
   - 尺寸：侦察 wow.export 导出项后定案，倾向 128×128 PNG（图鉴卡片用，过大压一遍，过小不拉申）。
   - 命名：`{icon_file_id}.png`（纯数字名，映射零成本）。
2. **先侦察再定案（存放方案）**
   - 侦察项：①wow.export 在线模式批量导出可操作性（2021 件量级，是否支持列表批量）；②导出 PNG 总量体积预估；③存放方案两案对比——**案 A** git 入库 `assets/decor-icons/`（与 iconMap 先例一致，部署零依赖）；**案 B** Supabase Storage（若总量过大，>50MB 则报告运营定夺）。
   - 定案倾向：总量 ≤50MB 走案 A；超了先报告，不擅自改走 Storage。
   - 侦察结论先写进修改报告再动手批量导出。
3. **缺图标 41 件**
   - icon_file_id 为空的 41 件不做提取；产出一个统一占位图 `assets/decor-icons/_placeholder.png`（深色底+金色问号/箱子剪影，尺寸同上）。一期不做 3D 模型渲染。
4. **可复跑与增量**
   - 脚本记录已成功导出的 fileID 清单（如 scripts/decor/out/icons_manifest.json），重跑跳过已有件，下赛季新批次增量补图。
   - 导出失败件单独列清单（fileID + 原因），不静默吞。

### WP1 验收

- 图标总数 = 2021 张 `{fileID}.png` + 1 张占位图；失败清单贴出（目标 0 失败，有失败逐件说明）。
- 抽查 10 个 fileID：PNG 可打开、内容与名称对得上（对照 decor_catalog 三件基准：28350 门垫 / 27973 夜景窗 / 27043 壁画 + 随机 7 件）。
- 存放方案侦察结论与体积实测写入修改报告；总量超 50MB 而未报告的，打回。
- manifest 落 scripts/decor/out/（产物目录，gitignore 在案）；图标本体若走案 A 则入 git（commit 物料含文件清单与总体积）。

## WP2：sourceText 来源结构化（scripts/decor/parse_source.py + sql/31 增量迁移）

### 需求

1. **文法规格（顾问全量语料实测归纳，2062/2062 覆盖，直接采信）**

   **条目结构**：source_text 由 `|n|n` 分隔的若干「来源条目」组成（少数条目内含真实 `\r\n` 换行，解析按 `\r\n`/`\n`/`|n` 均兼容）；每个条目以色标键开头 `|cFFFFD200{键}{可选冒号}|r{值}`，同条目内后续字段同为色标键值对。

   **条目类型（首键）全清单**（出现次数在案）：

   | 首键 | 次数 | 形态 |
   |---|---|---|
   | 商人出售 / 商人 | 2015 / 30 | 商人名 + 地区（可多键多值）+ 可选阵营 + 价格 |
   | 专业技能 | 330 | 专业名+等级，如「德拉诺烹饪（80）」，无地区/价格 |
   | 任务 | 326 | 任务名 + 地区 |
   | 成就 | 184 | 成就名 + 分类（必带，如「分类：|r…」）+ 常伴随商人条目 |
   | 掉落 | 79 | 掉落者 + 可选地区 |
   | 商城 / 游戏商城 | 65 / 2 | **无冒号**独立 tag，如 `\|cFFFFD200商城\|r`，常伴随商人出售条目（世界商人） |
   | 宝藏 | 14 | 宝藏名 + 可选地区 |
   | 名望 | 6 | 名望要求说明 |
   | 事件 | 1 | 事件名（枯法大军训练） |
   | 节日说明 | 6 | **无冒号**说明性 tag：「只能在美酒节期间获得」×4、「可在美酒节开始前购买」×2 |

   **字段键**：地区： 2693（同条目可出现多次=多地区）；价格： 2003（金币形态 `100|TINTERFACE\MONEYFRAME\UI-GOLDICON.BLP:0|t` 或货币形态 `100|Hcurrency:2003|h|…|h`，二者可组合出现，如「2000 currency + 1000 金」）；阵营： 152（声望要求，形态「织梦者 - 崇拜」「龙鳞探险队 - 名望等级16」）。

   **基准三件**（复核锚点）：28350=商城+商人出售（世界商人，500 金）；27973=双商人双地区（丹恩夜影/烈风海岸 + 费奥蕊月行者/创始者之角，20×currency:3363）；27043=掉落（乌拉特克/烈毒之渊）。

2. **结构化输出 schema（定案倾向，开工前先报告确认）**
   - decor_catalog 新增一列 `sources jsonb`（数组），元素形如：
     ```json
     {"type": "vendor", "vendor": "“丹恩”夜影", "zones": ["烈风海岸"],
      "price": [{"currency_id": 3363, "amount": 20}], "reputation": null}
     ```
   - type 枚举：`vendor / quest / achievement / drop / profession / treasure / renown / event / shop / festival_note`。
   - 价格拆两件：金币 → `{"gold": 500}`；货币 → `{"currency_id": 3363, "amount": 20}`；组合价=数组多元素。
   - **schema 变更纪律（开发规范 2.3）**：执行方先按本规格写出 sql/31 草案（含回滚注释）贴进送审件，顾问确认后方可执行；表结构单一事实源 = sql/ 目录。
   - **source_text 原文列保留不动**，sources 是派生列。
3. **解析护栏（硬门）**
   - 解析覆盖率报告：1987 条非空逐条归类，类型分布计数与上文全清单对齐（允许件级多类型）；**无法归类的条目逐条贴出**（目标 0，有则报告运营定夺，不擅自吞并）。
   - 空 75 件：sources 落 `[]` 并在报告给出 entryType 分布（预期大头为 39 件房间条目）。
   - 价格解析：currency_id 与金额分离提取；金币/货币组合不丢件。
   - 幂等：UPDATE 派生列可重跑，不产生重复/漂移；loot 双表零触碰。
4. **产出物**
   - `scripts/decor/parse_source.py`（输入 decor_catalog.json 留档件或 anon 直连拉取，输出 sources 更新 SQL）；
   - `sql/31_task050_decor_sources.sql`（ADD COLUMN + 回滚注释；UPDATE 数据可与迁移同事务或紧随种子式批量 UPDATE，执行方定，报告里写理由）；
   - 迁移纪律沿用：备份 → SSH docker exec（supabase_admin）→ 单事务 → `NOTIFY pgrst, 'reload schema';` → 回滚注释 → REST 复核。

### WP2 验收

- 覆盖率报告：1987/1987 归类，无法归类清单 = 0（或逐条在案有定夺）。
- 三件基准的 sources 解析结果全字段贴出，与原文人工核对一致（重点核 27973 双商人不丢条目、675 类组合价「2000 currency + 1000 金」不丢件）。
- REST 复核：sources 非空计数 = 1987 − 无法归类数；空 75 件 sources=[]；抽 10 件 jsonb 可读。
- 幂等重跑一次，计数不变；boss_loot=269 / dungeon_loot=426 零触碰复核贴出。
