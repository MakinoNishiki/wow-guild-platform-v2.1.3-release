### 结论（逐锚点）

| 锚点 | 结论 | 采纳情况 |
|---|---|---|
| `EJ_IsValidInstanceDifficulty` 守卫模式 | 暴雪自家 EJ 界面在 `EJ_SetDifficulty` 前必过合法性闸：**:768**（`EncounterJournal_ResetDisplay`）与 **:3563-3564**（`AdventureJournal_Reward_OnMouseDown`）两处均为 `if ( EJ_IsValidInstanceDifficulty(difficultyID) ) then EJ_SetDifficulty(difficultyID) end`；难度下拉只列合法档（:579-604），官方注释明确该 API 校验 ≤64 的位掩码（我方档位 1/2/14/15/16/17/23/24 全在掩码内，无需 InstanceHasDifficultyID 补判） | 采纳：钉档+切档全路径补闸 |
| 单难度实例 | 难度控件显隐由 `EJ_GetInstanceInfo()` 第 9 返回值决定（:1181-1188 `UpdateDifficultyVisibility`）——世界 BOSS 型等单难度本存在为官方实证；换实例后难度不匹配的钳制在 C 侧，FrameXML 不可见 | 采纳：锚档改候选探测 |
| `EJ_GetEncounterInfo` 返回序 | 官方文档无（EJ_ 全系 legacy 未入 APIDocumentationGenerated，10.0.0–12.1.0 各 tag 同）；权威解构序来自暴雪自身 :3577：`local name, description, bossID, rootSectionID, link, journalInstanceID, dungeonEncounterID, mapID = EJ_GetEncounterInfo(self.encounterID)`——**第 3 返回值 = encounterID** | 采纳：无参读回取第 3 返回值比对（读不出=不明走旧行为，不错杀） |
| `EJ_IsLootListOutOfDate`（G1） | 官方文档无；全 12.x FrameXML 唯一调用点 :1005（`EJ_LOOT_DATA_RECIEVED` 事件内）。out-of-date 标志为 C 侧状态，Lua 侧无写点——**「恒 true」嫌疑 FrameXML 不可证亦不可否，只能真机取证**（顾问结论同） | 采纳：三段计数+段尾汇总仪器化，同版查证 |
| 旧本是否需 `EJ_SelectTier` 到原资料片 | FrameXML 实例列表为纯枚举（:1099-1130），无任何 Lua 侧过滤/合并/赛季感知——**该问题 FrameXML 不可答**；我方仓库实证（见五问③）：1.0.6 全量导出大米段含 5 个旧资料片本且件数正常，1.0.6 起代码只做 `EJ_SelectTier(当前 tier)` 一次 | 采纳实证：维持当前 tier 策略不动 |
| `EJ_SetDifficulty`/`EJ_GetDifficulty`/`EJ_ResetLootFilter` 文档 | 官方 APIDocumentationGenerated 均无（undocumented legacy C 全局）；`EJ_ResetLootFilter` 全 FrameXML 零调用点 | 申报在案 |

### 残留不确定点（如实申报）

- `EJ_GetEncounterInfo()` **无参**调用是否稳定返回当前选中态：暴雪全部调用点均带参（我方 :3577 引用只证第 3 返回值序，不证无参形态），wiki 亦无载——无参读回属安全超集用法。**退路备案（终审裁定，不阻塞）**：若无参形态翻车（**冒烟即现形：拉维/鲁阿夏尔 selectFail 三连**），改走 wiki 明载的 `EJ_GetEncounterInfoByIndex(index)` 第 3 返回值 == 目标 id 做读回（顺带白得实例选中校验）；读不出（nil）时按「不明」走旧行为，不会误杀。宁空不错配的 selectFail 占位语义已兜住下游，终审认可带险上真机。
- 大米段全灭的单一定因代码面无法一锤定音（候选机制三选，见五问①末）——1.0.18 对三条候选均落闸/落仪器，真机 V14-V16 一跑定案。

### ② 钉档链三件套

- **钉**：`EJ_SetDifficulty(diffID)`（pcall 包裹）；
- **快照读**：`EJ_GetDifficulty()` 回读比对（REQ-119① 快照黄字同源）；
- **枚举实际消费通道**：`C_EncounterJournal.GetLootInfoByIndex(li)`——返回稀疏表的 link 字段由 C++ 按当前手册难度生成（1.0.7 侦察结论在案），切档→重取 link→SetHyperlink 重扫为暴雪原生路径；
- **合法性闸**：1.0.17 及之前**不过** `EJ_IsValidInstanceDifficulty`——暴雪 Mainline :768/:3564 两处均先判合法再 SetDifficulty（逐字引用见调研依据表）。1.0.18 已补闸：钉档（`pinInstanceDifficulty`）与切档（`collectTiers.nextTier`）全路径，无效档不发 SetDifficulty，视同读回不符走既有 tierSkip/switchFail 处置。

### ③ 旧本（诸王之眠/塞塔里斯等）是否需 EJ_SelectTier 到对应资料片

**不需要，1.0.9 未做过、现在也不做（该行为 1.0.18 原样保留）。** 证据：仓库内 1.0.6 全量导出（`掉落导出.lua`，2026-08-08 真机产物）大米段含魔导师平台（TBC）/萨隆矿坑（WLK）/通天峰（WoD）/执政团之座（Legion）/艾杰斯亚学院（DF）五个旧资料片本，件数 22-37 全正常——赛季轮换旧本由暴雪挂在当前 tier 的地下城列表（FrameXML 列表路径纯枚举无过滤，佐证不构成反证）；1.0.6→1.0.17 代码均只 `EJ_SelectTier(EJ_GetCurrentTier())` 一次。

### ④ 「判空实例跳过」是否误伤团本两段

**机制上成立，且 1.0.17 的跳出口径把「毒」忠实转化成了「失踪」。** 判空跳过触发条件=全 BOSS 枚举重试后仍 0 件——而 0 件的根因（钉空档余毒/选中未生效/重建窗）在 1.0.17 前无闸无读回，跳过判定本身不背锅但掩盖了根因定位；且跳过实例在导出文件**无痕**（仅聊天红字，截图一丢即无对证）。1.0.18：跳过实例入段台账 `seenInstances` → gating 逐一点名 + `dump.skipped_instances` 字段留痕（红字之外第二通道，禁静默）。另：实例枚举 pcall 中断的同样入台账（原完全不记）。

### ⑤ 1.0.9→1.0.17 大米枚举路径全差分

| 版本 | 大米枚举路径差分 | 行为后果 |
|---|---|---|
| 1.0.9 | 同步 while 枚举；**不钉档**（全程吃 EJ 当前难度）；不过滤器；SelectEncounter 无 pcall 无读回；枚举+解析同链；0 件照样进 out（无空实例判定）；无去重 | 「不钉不过滤不校验」对所有实例天然免疫——用什么档吃什么档，225 件基线的时代背景 |
| 1.0.11 | 异步串行化+冷缓存就绪门 | 链形态变化，枚举口径不变 |
| 1.0.12 | **每实例钉 23+回读（最大行为差分）**；段首捕获/还原难度；伪实例过滤+空实例跳过（黄字）；DUNGEON_TIERS 档通道；REQ-119 快照 | 钉 23 对支持档的大米本无害（225 同锚 23 即此期产出），对不支持的条目即毒 |
| 1.0.13/1.0.14 | 段提交；collectTiers 异步+陈旧列表校验 | 枚举口径不变 |
| 1.0.16/1.0.17 | 过滤器清零（F1 官方重置接口）；whenLootListFresh 全路径（F2）；0 件重试 3 次红字（F3）；计数质量门（F4）；itemID 去重（F5） | 引入「重建窗」「钩子恒 true」新嫌疑面（G1） |

差分结论：1.0.9→1.0.17 大米路径的核心行为差分 = **钉档（1.0.12）+ 过滤器清零（1.0.16/17）+ 重建钩子（1.0.17）** 三件套；1.0.18 不改这三件套的既定正确性，只补它们各自缺的闸（合法性/读回/计数）。

## 三、逐条修复回执

### BUG-094（P0）大米全灭+至暗/潮缚失踪

- `isDifficultyValidForInstance(diffID)`（:334）：`EJ_IsValidInstanceDifficulty` pcall 封装，返回 nil=不明（走旧行为）、true/false=明确判定。
- `pinInstanceDifficulty(candidates)`（:346）：锚档候选探测——`RAID_ANCHOR_CANDIDATES={14,15,16,17}`、`DUNGEON_ANCHOR_CANDIDATES={23,2,1,24}`，无效档跳过（不发 SetDifficulty），首个钉得上（读回一致）的档胜出；全钉失败返 nil。单难度本（世界 BOSS 型）首选档无效时自动改钉合法档，不再被硬钉空档。
- 实例钉档接线（enumInstance）：快照注记三态——改钉「首选锚档 X 无效，改钉 Y」（单难度本属正常）/ 全钉失败红字注记（非正常）/ 首选即中无注记。
- `collectTiers.nextTier` 切档同闸（:588）：`invalid` 视同读回不符，大米 tierSkip / 团本 switchFail 处置不变。
- 判空跳过留痕：段台账 `seenInstances`（含伪实例/判空/中断三类），`dump.skipped_instances` 字段（仅非空产出，含段/实例名/原因）。

### BUG-095（P0）gating 第四条=期望实例集完整性校验

- `EXPECTED_INSTANCE_COUNT = { 团本=3, 大秘境=8 }`（:362，赛季常量，注释标明随赛季由运营/顾问更新；伪实例不计入）。
- 段报告通道：`exportInstances` done 回调加第二回参 `{ seen, abnormal, sanity }`，doExport 按段收 `segReports`。
- 终局 gating 五源归集：①段台账 0 件判空跳过 ②段实例数不足期望集（红字附在列名单）③WJDCLastCounts 基线具名实例本次缺席 ④导出 0 件（解析全灭等，吸收 1.0.17 F4 零件门）⑤BOSS 件数 sanity 异常——任一命中：**红字逐一点名 + `dump.meta.abnormal=true` + 拒写 WJDCLastCounts**；判空跳过实例本就不在 counts，天然不计入覆写集；无违规且非断链跑才覆写（1.0.13 既定口径不变）。

### BUG-096（P1）读回校验 + sanity 守卫 + G1 查证

- ①`encounterSelectReadback(encounterID)`（:628）：无参 `EJ_GetEncounterInfo` 第 3 返回值比对；读不出=nil 走旧行为。阶段一 `trySelect`：不符过重建钩子重选重读封顶 3 次，仍不符红字 + `selectFail` 空占位（**宁空不错配上一 BOSS 列表**）；阶段二选中态同加读回，不符视同设置失败跳过（`selectFail` 标记随 bossesOut 落导出文件）。
- ②`BOSS_ITEM_SANITY_MAX=40`（:359）：历史最大单 BOSS 18 件（1.0.6 全量 dump 逐 BOSS 校准：至暗之夜 8/梦境裂隙 18/虚影尖塔 16/执政团之座 10 等），超 40 判列表异常——红字 + 段 abnormal（gating 拒写基线），数据照录不销毁，不静默。
- ③G1 仪器化：`lootFreshStats` 三段计数（即时就绪/等待后就绪/超时放行）按段归零，超时红字每段封顶 3 次（防恒 true 刷屏），段尾黄字汇总「重建钩子统计（G1 查证）」——超时占比≈100% 即坐实恒 true 嫌疑（FrameXML 不可证，真机一跑定案）。

### 毒咒两行形态（顺批，判据不变）——匹配规则全文（终审必答）

- **匹配规则**：逐行剥码（`stripLineCodes`）后两级判定——①单行精确：`^毒咒%s*$`（1.0.9 既有口径，容许行尾空白）；②跨行：上一行剥码文本与本行剥码文本**拼接**后整体匹配 `史诗%s*毒咒%s*$`——即「难度行（以史诗收尾）↵毒咒行」两行形态判有。命中任一级即 `venomcurse="毒咒"`，不再继续匹配。
- **flavor 句排除（270165「"毒咒如影随形。"」）**：单行级要求整行恰为「毒咒」，flavor 句含额外文字不命中；跨行级要求**拼接串以「毒咒」收尾**（仅容许尾随空白），flavor 句以「。」收尾不命中——双级均免疫。
- **兑换物五件名行（毒咒神像/遗物/雕像/圣像/残骸）不误标**：物品名行为 tooltip 首行（无上一行，跨行级不可达）；且五件名均以「像/骸」等字收尾非「毒咒」，单行级非整行「毒咒」、跨行级拼接串不以「毒咒」收尾——双级均免疫。
- **采集通道（终案口径复核）**：**任档出现即采**（1.0.16 E2 定案，本版不动）——`collectTiers` 档扫循环内 `opts.venomcurse=true` 时每档 tooltip 均判毒咒（安全超集，防史诗档被跳档/陈旧拦截漏采），平面基础通道（parseItemDetail 双通道）同判；**effect 仍只存史诗档文本**（`tier.key == opts.effectTier` 才覆盖），本版零改动。大米段 `venomcurse=false`（M+ 免毒咒判定，REQ-118 既定）。
