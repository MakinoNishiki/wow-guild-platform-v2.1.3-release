# REQ-190 公会里程碑与战绩时间轴

2026-11-12。遵循《开发规范》与最新《问题与需求清单》。本文件记录运营补充的后续产品方向，属于公会公开主页/可分享战报的同一需求；未实现、未上线，不改变当前REQ-189拾取与分配收官顺序。

## 用户意图与产品位置

公会作为长期展示主体，沉淀各版本、赛季、团本及不同难度下的进度和重要时刻，供成员回顾、对外展示和后续招募使用。公会内多个固定团可保留团号，避免把不同团的进度拼成一个团的通关记录。独立于个人资料，不将私人角色或内部考勤、装备分配默认公开。

建议结构：公会主页 → 当前赛季进度卡 / 里程碑时间轴 / 历史赛季。时间轴重要节点包含首个有证据的首领击杀、某难度全通、后续核实的官方荣誉；普通、英雄、史诗分别统计，随机团不进入团队里程碑。每周重复击杀留在活动历史，默认不反复刷里程碑。

## 第一层：基于战斗日志的团队战绩

入口复用绑定WCL公会查找报告、粘贴报告链接、已确认的站内活动。不需要另装里程碑插件。报告上传并可被访问后才可能被本站发现，不能宣称击杀瞬间即实时获知。

流程：发现报告 → 核对是否本团活动 → 解析成功击杀、难度与时间 → 生成里程碑草稿 → 管理者核对并发布 → 公会主页展示，详情跳WCL对应战斗。已确认本团的活动直接复用确认结果；不要求重复认定活动。公开发布沿用REQ-190既定管理者选择原则，自动生成不等于自动公开。

示例文案（示意，非真实战绩）：

> 2026年11月12日 23:28（北京时间）
> 本公会一团击败史诗难度的乌拉特克。
> 附：WCL战斗链接、可选纪念截图和团长寄语。

截图与寄语为管理者补充材料，不能伪装成WCL自动核验结果；实际击杀时间与上传时间、本站发现时间分别保存，显示以击杀时间为准。

规则：
- 公会日志目录归属不证明队伍归属。复用REQ-180待确认报告/成员匹配流程，野团误传可忽略；不能凭未验证的成员比例自动公开。
- 按游戏区域/版本赛季/团本/难度/首领/站内公会及团号识别进度；WCL与游戏客户端难度编号独立映射，不能混用。
- 同次击杀多个成员上传、重复抓取、报告重传/修订不能生成重复节点。报告code+fight id标识来源，跨报告同次击杀另结合时间、首领、难度、队伍证据核对，不能只凭时间靠近就合并不同团。
- 历史不完整时只称“已收录最早击杀”，不自动声称公会真正首杀；补传更早证据可修订，并保留来源和修改记录。
- 全通只基于同一归属范围、难度及正确首领清单的有效击杀；不足的数据不推测补齐。多团合并视图须明确“公会各团合计”。
- 无权访问/私有/删除的报告不承诺公开可读；发布前核对公开范围。证据失效与重算应显式标注，不静默篡改已发布荣誉。

## 第二层：官方成就与荣誉（后续扩展）

将“日志证明的史诗击杀”“个人获得的成就”“公会官方成就”区分为不同证据，不直接互相等同。用户举例的“千钧一发”只作为后续荣誉方向，具体成就名称、适用首领、时限、区域和资格必须核对，不能看到史诗击杀就自动写“获得成就”。

成就数据或截图若可获得，应标明官方数据核验/管理者提供材料/待核验；公会成就人数门槛按具体成就和版本核查，不采用口述“一半以上”作为固定规则。国服英雄榜/API的实际可用性和权限未验证，第一版不依赖它，也不将个人成就自动授予整个公会。

## 已核对的现状与待验证项

- 本地server.js的WCL_REPORT_FIGHTS_QUERY已有report.startTime/endTime、fights.encounterID/name/kill/difficulty/startTime/endTime，可作为复用起点；该查询尚未带fight.id和完整的战斗参与者，后续按需补齐与既有名单接口复用。
- [WCL Report官方文档](https://www.warcraftlogs.com/v2-api-docs/warcraft/report.doc.html)说明报告起始时间及按难度/首领/击杀过滤战斗的能力，报告所属公会字段表示上传归属。2026-11-12官方文档直开403，检索索引可读取；未调用真实账号、未核对任何公会战绩。
- 具体击杀绝对时间拟由报告起始时间和战斗结束偏移组合；时间单位、跨午夜与时区用真实接口样本联验后确定，禁止将整份报告结束时间当作每个首领的击杀时间。
- [暴雪关于赛季末内容的说明](https://worldofwarcraft.blizzard.com/en-us/news/24244426/what-to-do-before-the-midnight-pre-expansion-content-update)对其对应团本的Cutting Edge明确限定下个团本开放前完成史诗击杀；只能说明成就存在额外条件，不能借此断言乌拉特克的具体成就规则。

## 排期与验收门槛

保持P2待排期。本轮只新增本文并更新REQ-190台账，无UI施工、数据库/接口变更、生产写入或Git提交。

正式排期后至少验证：正常击杀及未击杀、普通/英雄/史诗隔离、误传报告、跨午夜、延迟上传、同次击杀多份报告、历史补录、同公会多团、草稿/发布权限与撤回、私有日志及证据失效、缺少成就证据时不显示已获成就。届时先审计既有公会界面，再实现UI，不将本方向文档当作已交付页面。
