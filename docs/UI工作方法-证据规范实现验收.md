# UI 工作方法（证据 → 规范 → 实现 → 验收）

> 效力：**工作方法补充层，不产生新规则**。与《开发规范》《UI 设计规范 v2》《AGENTS.md》冲突时，一律以后者为准（冲突裁决见 §8）。
> 来源：基于《一个 Prompt，复刻前端 UI 设计系统》（Kryon）适配改写；已按项目口径裁剪（§7），原文中移动端/响应式/浅色主题/SSR/国际化/工程化目录等内容不适用本项目，不引入。
> 适用：魔兽管家全部前端任务（新功能、改版、复刻参考、UI 修复）的执行方法；开工前先读规范三件套，本文排第四。

---

## 一、证据三标（诚实标记，不许编造）

一切视觉与行为结论必须标注三档之一：

1. **已测量**：从线上实测、computed styles、源码、DB 实测、截图比对直接确认；
2. **有依据的推断**：多页面/多组件/多状态归纳出的规则，写明依据链；
3. **暂时假设**：材料不足为推进而采用的默认值，**必须显式标记**，不得伪装成事实。

- 证据不足时**停下报阻塞**，列出需要补充的材料——衔接补丁6 条款：环境无法复现/依赖外部结论时立即上报，禁止"先完工再坦白"。
- 禁止编造字体、断点、交互结果、兼容性、性能数据；线上无法访问的部分写清阻塞点。

## 二、四阶段门（每阶段验收后才进下一阶段）

| 阶段 | 产物 | 门槛 |
|---|---|---|
| 0 证据 | 证据与风险清单（现状实测、锚点行号、差异清单） | 顾问/运营确认差异定案 |
| 1 规范 | 组件注册/规范增补（v2 或专项规范，规格表唯一事实源）+ 改造前后 UI 图 | 评审通过才许动代码 |
| 2 实现 | 小步实现，每步 `node --check`/verify 绿 | 不顺手加功能、不顺手重构 |
| 3 验收 | verify 全绿 + 修改报告 + 版本串递增 | 顾问线上核对 + 运营签发 |

- **先分析后实现**：未完成证据与规范阶段，不写最终页面代码；
- **先复用后新建**：优先用项目已有组件、类名、CSS 变量、动画白名单；新建组件必须先注册规范；
- **先保真后抽象**：先确认现状真实规律，再抽象 tokens/组件，不为代码整齐改变既有视觉；
- **不用相似代替真实**：不擅自用通用模板/占位样式替代既有规格；必须替代时写明原因与风险；
- **不复制明显缺陷**：保持视觉风格的同时修复已确认缺陷（对比度不足、焦点不可见等），修复点写明。

## 三、状态矩阵（组件交付必填）

任何组件改动/新建必须覆盖并实测：default / hover / focus-visible / active（按下即反馈）/ selected / disabled / loading / error / empty / expanded。缺项写明理由。
- 与 v2 组件库状态规格对齐；按钮 `:active` 按下即反馈为最高优先级（v2 §1）；
- 长文本、空数据、加载中、网络失败四类边界必须实测，不许只交默认态截图。

## 四、Tokens 三层（映射到项目 CSS 变量）

- primitive（原始值：色板/字号/间距刻度）→ 现有 `:root` 变量层；
- semantic（语义角色：背景/表面/主文本/次文本/边框/状态色）→ `--bg-*`、`--text-*`、`--gold`、`--success` 等；
- component（组件级：chip 高度/圆角/padding/字号字重）→ v2 §4 规格表。
- 改 token 必查全站引用面；组件级规格改动以规格表为唯一事实源，verify 断言同步。

## 五、验收内置（写完代码之前先想怎么验）

分层验收（裁剪版，适配本项目）：

- **L0 结构**：DOM 语义、组件数量、类名钩子（verify 锚点）不漂移；
- **L1 几何**：容器/对齐线/间距/折行/溢出，两档视口（1366 基线 + 390 公示页回归）；
- **L2 视觉**：颜色/字体/字重/行高/圆角/阴影对照规格表；
- **L3 状态**：§三状态矩阵逐项实测；
- **L4 数据一致性**：页面数据 = 库内数据（对数口径），刷新/换浏览器无脏缓存。

执行双层：开发侧 verify 脚本全绿 + 顾问侧线上断言复测；失败项截图+复现步骤进修复队列，修复后自动化全量重跑。

## 六、四种运行模式（一次对话只干一件事）

1. **逆向分析模式**：只出证据清单/现状地图/差异/风险，不改代码（=开工审计）；
2. **实现模式**：按已确认规范施工，禁止擅自新增视觉规则；
3. **状态补全模式**：专查 loading/empty/error/disabled/focus 与边界数据；
4. **验收修复模式**：对照验收报告只修已确认偏差，不顺手扩大。
