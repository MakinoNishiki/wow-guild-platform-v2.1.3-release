# UI 设计参考（魔兽管家适用版）

> **定位**：审美参考文档，供任务书执行时遵循的"品味标准"。
> **优先级**：低于《开发规范》——两者冲突时以开发规范为准。
> **来源**：蒸馏自 Emil Kowalski 的 apple-design skill（Apple WWDC 设计原则的 Web 版转译）。
> **结构**：第 1~7 节为**当前桌面版执行标准**；第 8 节为**移动端/小程序储备篇**（封存状态，移动端立项时启用）。
> **适用范围**：魔兽管家全部前端界面。产品视觉基调为**深色 WoW 主题**（暗底 + 金色点缀），以下原则在该基调下执行。

---

## 1. 即时反馈（最高优先级）

用户操作的每一个瞬间都要有回应，"感觉死掉了"比"慢"更致命。

- **按下即反馈**：按钮在 `:active`（按下那一刻）就有视觉变化，不要等 click 触发、更不要等接口返回才动：
  ```css
  .btn:active { transform: scale(0.97); transition: transform 100ms ease-out; }
  ```
- **过程反馈优于结果反馈**：耗时操作（导入、同步、批量写、删除）进行中必须有进行态（loading 文案、按钮防重复），不允许"点了没反应，最后突然成功"。这与开发规范"禁止假成功"是同一枚硬币的两面：规范管"不许骗人"，本参考管"不许沉默"。
- **警惕输入路径上的一切延迟**：无必要的 debounce、setTimeout、 chained 动画等待，都是体验倒退。

## 2. 反馈的四种类型与确认克制

- 反馈分四类：**状态**（进行中）、**完成**（成功了）、**警告**（将出问题）、**错误**（已失败）。有意义的操作要确认完成，进行中的事要暴露状态，问题发生前要警告，输入错误要**就地校验**（字段旁提示），不要攒到点"保存"才弹一堆错。
- **确认弹窗只给真正不可逆的破坏性操作**（删除活动、删除成员）。到处弹确认会训练用户无脑点"确定"，真正的危险操作反而被秒点过去。（与开发规范"防误关二次确认"同原则：二次确认=未保存内容或不可逆删除，其他一律不弹。）
- 可逆操作提供**宽容**（能撤销、能改回来），比弹窗确认更高级。考勤改错了能再改，所以不要给考勤标记加确认弹窗。

## 3. 排版纪律

中文界面同样适用，核心是**层级靠"字重+字号+行距"组合，不是只靠字号**。

- **字距随字号变化**：大标题收紧（`letter-spacing: -0.02em` 左右），正文接近 0，小字/标签可微幅放宽。全站禁止一个 `letter-spacing` 值通吃。
- **行距与字号反比**：大标题行距紧（1.1~1.2），正文宽松（1.5~1.7），密集数据表格行距可再压（1.3~1.4），信息密度优先。
- **强调用字重**，不轻易加大字号——字重加存在感但不占空间，表格和列表里尤其如此。
- **间距单位用 rem/em**，不用写死的 px 堆叠，保证用户调大浏览器字号时布局不崩。
- 字体栈用系统字体优先（项目现有暗色主题字体栈保持不变），不为"好看"引入 Web 字体拖慢首屏。

## 4. 层级与材质（深色主题版）

- **浮层靠"更亮一档 + 模糊/阴影"表达层级**，不靠刺眼的描边：弹窗、下拉、toast 比底层亮一点、带柔和阴影；底层内容在弹窗出现时整体压暗（scrim），注意力自然聚焦。
- **避免浅色浮层叠浅色浮层**——两层都亮都模糊时文字可读性崩塌。深色主题下同理：浮层亮度差要拉开至少一档。
- **越大的浮层越"厚"**：全屏弹窗的阴影和背景压暗要重于小 tooltip。
- **半透明表面上的文字要提高对比度**：不要在中性灰底上用中性灰字（我们暗色主题最容易犯这个—— BUG-025 日期图标看不清就是同类问题：图标/文字与其背景的对比度必须一眼可辨）。
- **分割线能不用就不用**：优先用间距和留白分组；必须用时用低对比细线，不用亮线。

## 5. 动效原则（桌面端克制版）

- 动效只回答"**这个变化从哪来、到哪去**"：弹窗从触发元素方向出现/收回，列表项新增/删除有位置变化提示。动效是空间关系的说明书，不是装饰。
- **进出同路径**：从右侧滑入的面板就从右侧滑出；从按钮弹出的菜单收回按钮方向。
- **时长 150~250ms**，入场用 ease-out，离场用 ease-in，可逆过渡两边镜像。超过 300ms 的界面动效在桌面端就是慢。
- **只动 transform 和 opacity**（合成器友好），不动 width/height/top/left 引发布局抖动。
- **尊重系统"减少动态效果"设置**：
  ```css
  @media (prefers-reduced-motion: reduce) {
    * { transition-duration: 0.01ms !important; animation: none !important; }
  }
  ```

## 6. 设计八原则（种子期取舍版）

原八原则全量：目的、掌控、责任、熟悉、灵活、简洁、匠心、愉悦。种子期执行其中五条，其余随产品成熟补齐：

1. **目的**：每个功能都在花用户的时间和注意力，值才做，不值不做（对应我们的需求评审机制）。
2. **掌控**：用户永远知道"我在哪、能去哪、怎么退出"；危险操作给反悔路径；不锁死用户。
3. **熟悉**：长得一样的控件行为必须一样、位置必须一样（全站按钮/弹窗/徽标一致性，UI 专项的核心检查项）。只有证明更好时才允许打破惯例。
4. **简洁≠极简**：不是把东西藏起来，而是核心路径一眼可见、高级选项收进下一层。能加上下文变简单的就加（如 REQ-037 同步提示条）。
5. **匠心**：没有一个间距、对齐、配色是"随便的"。图标对不齐、滚动抖动、弹窗错位，用户读到的不是 bug 是"不上心"。

## 7. 本参考的禁用项（防止过度设计）

- 不引入动画库/弹簧物理库（Motion、Framer Motion 等）——项目零依赖红线；
- 不做拖拽手势、惯性滚动、橡皮筋回弹——桌面端数据工具无此场景；
- 不加音效/震动反馈；
- 不为"Apple 风"改变产品深色 WoW 主题基调——我们借的是原则，不是皮肤。
