## 结论

**国服原生蓝图、内容列表及缓存明细读取已实证；网页贴原生码生成清单仍未打通。** 现已核对196种装饰512件及其他类型，共526项；不能解读成512种家具或526件家具。主任务本地验证样本24字符可还原为18字节，标准Base64往返一致，zlib/gzip/raw deflate均未恢复清单；短码可能是引用标识只是推断，尚未证实完整二进制格式。游戏内查询链已核源码，运营回传数据与图鉴匹配详见 [明细核对摘要](evidence/req203-20261118/native-list-catalog-match.json)；该结果不能补足网页独立查询的缺口。

原生蓝图码、插件家具清单、网站作品仍是三份不同资料。WoWDB 官方工具说明及Dump Decor发布包能证明插件清单路径存在，不能据此替换运营要求的原生码流程。

## 已确认：原生蓝图在游戏内的查询结构

证据为客户端自带 API 文档的 [Gethe 源码镜像：HousingBlueprintUI](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/HousingBlueprintUIDocumentation.lua) 与 [内容结构定义](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/HousingBlueprintConstantsDocumentation.lua)。这是客户端原始文档镜像，不是暴雪托管的网页服务文档；本轮实际读取 raw 文件。

- `C_HousingBlueprint.RequestBlueprintContents(shareCode)` 的文档明确为异步请求，结果包含服务器动态数据，成功/失败通过事件返回；再次发起可取消之前请求。
- `HOUSING_BLUEPRINT_CONTENTS_RECEIVED` 返回一个 `contentInfo`，不是凭旧论坛描述假定的多个位置参数。
- `contentInfo` 含 `shareCode`、`contentGroups` 等；各项含 `contentType`、`recordID`、`total`、`numMissing`、`invalid`。所需总数使用 `total`，不能把采集者个人的 `numMissing` 当作所有访客的缺失量。
- 内容类型包括房型、房间、家具、染色、固定结构等，不能把所有类型相加称作家具件数。
- `GetFeatureAvailability`、`GetImportAvailability` 可用于检查游戏内功能可用性。文档还列出 `IsShareCodeValid`、`GetBlueprintTypeForCode`、`UpdateBlueprintStringFromInput`，但未公开它们的底层解析实现。

**证据界限：**已核文档证明游戏内存在带服务器数据的查询入口，以及可用于生成清单的字段；它本身不足以证明所有分享码都不可能离线解析。本轮没有找到、实现或验证原生码的独立解码器，也没有确认原生码固定前缀/长度。不要直接用 `DD2:` 的格式校验规则处理原生码。

- 不能用526−512−6的差值猜测其余内容具体属于房间、染料或房型；等取得实际组数据再定。

### 只读探针草案：复用已经打开的列表

最少人工准备为：在已保存蓝图中选中该蓝图，点“查看列表”并保持窗口打开。无需导入、替换布局、重载、退出游戏或新插件。主任务统一准备两段只读操作：从上述列表缓存提取 `{内容类型,recordID,total}`，再序列化到临时文本框供一次复制；本子任务不另发一套探针让运营重复尝试。

清单只读验证保留全部内容类型供核对，不导出分享码、房屋GUID或账户信息；不发送公会/团队消息，不调用任何房屋变更API。**本轮未执行，不能写成真机通过。** 主任务负责确认国服对象可读、完整文本可复制以及按类型汇总能回对截图数字。缓存不存在或受脚本限制时停止记录，不要求关闭保护；不能把聊天逐行抄录、截断输出或该人工调研操作包装成正式“网页直接解析”交付。

### 官方网页接口能否直接替代

直接读取官方开发者站使用的公开文档数据，核对全部方法名、路径、描述和参数：

- [Game Data APIs JSON](https://community.developer.battle.net/api/pages/content/documentation/world-of-warcraft/game-data-apis.json)：38个资源组、162个方法。
- [Profile APIs JSON](https://community.developer.battle.net/api/pages/content/documentation/world-of-warcraft/profile-apis.json)：20个资源组、44个方法。

上述本次快照对 `blueprint`、`shareCode/share_code`、`layout` 的检索没有匹配方法。准确结论是“**本次已核官方公开方法目录未列按原生蓝图码取清单的网页接口**”，不是断言所有内部、合作方或未来接口都不存在。

Profile目录有 `GET /profile/wow/character/{realmSlug}/{characterName}/house/house-{houseNumber}`，方法名为Character House Summary，默认命名空间 `profile-us`，`cnRegion:false`。它按服务器、角色与房屋编号查询住宅摘要；公开参考未给出响应结构，也未给出从 `shareCode` 映射到这组参数的方法。本轮没有鉴权调用它，不能证明其当前可用性、是否返回全部摆放家具或布局。即使将来能取得角色当前住宅，也须证明它与作者保存蓝图的时间和范围一致，才可作为该作品清单，不能默认替代蓝图快照。

Game Data目录另有家具、房间、固定结构的图鉴接口及社区接口，已列方法不等于蓝图解析服务。上述Housing相关方法均标记 `cnRegion:false`；[官方地区说明](https://community.developer.battle.net/documentation/guides/regionality-and-apis) 区分中国与国际服数据分区，不能用国际服可查询来替代国服实测。当前有依据继续验证的是游戏已加载清单的只读读取；“网站直接粘贴国服原生码即可完整生成清单”仍未打通。

### 新的一手证据：识别类型不等于拿到清单

客户端原始文档明确区分：`IsShareCodeValid` 只检查格式，`GetBlueprintTypeForCode` 返回蓝图范围；两者都不核验该码是否对应真实有效的蓝图。`UpdateBlueprintStringFromInput` 只定义输入、输出字符串，没有给出布局解码实现。完整内容仍由异步 `RequestBlueprintContents` 系列取得。[HousingBlueprintUI原始文档](https://github.com/Gethe/wow-ui-source/blob/297d7aaaa736f346b3e036f38ee088eaf7f8c07f/Interface/AddOns/Blizzard_APIDocumentationGenerated/HousingBlueprintUIDocumentation.lua)

因此，即便网页识别出整屋/房间/室内/室外，也不能据此宣称已经验证原码有效、恢复了家具列表，或能够调用与客户端等价的服务。公开Lua调用点与结构文档没有公开其底层服务协议；本轮没有用游戏协议或访问凭据尝试替代公开网页API。

### WoWDB没有给出“仅原生码生成清单”的确认

新核对的 [WoWDB自家更新日志](https://housing.wowdb.com/changelog/) 显示：2026-08-11增加给作品可选添加蓝图代码；2026-11-11增加每作品最多5个蓝图、自动识别蓝图类型，以及作品页独立蓝图区域。11月11日记录在该站自身页面的搜索快照及 [首页最新更新](https://housing.wowdb.com/) 均可见。本次直接打开更新日志的另一缓存快照仍止于10月26日，故保留这一时效差异，不把未见更新当作没有功能。

这些明确说明的是代码关联、类型识别和展示，没有说明只凭代码获取家具ID与用量。其2025-12-13已记录插件字符串同步、2026-01-13已有作品购物清单导出；两类功能与2026-08-11才加入的可选原生码是分开描述的。这个时间顺序仅证明“作品清单与原生码不能被想当然地视为同一数据来源”，不能证明该站目前绝无其他取数方式。

该站 [Decor Collection Sync](https://housing.wowdb.com/tools/decor-sync/) 仍明确介绍Dump Decor的拥有/摆放家具导出及导入作品；[公开作品示例](https://housing.wowdb.com/builds/73515/dk-inner-layout-73515/) 同时展示家具用量和两个蓝图复制入口，也未说明清单从这两个代码解析得来。本轮直接获取作品HTML/脚本遇到站点挑战页面，未继续越过；没有登录作者发布页或测试发布请求，所以登录后是否存在额外原生码解析能力仍是未知，不能作肯定或否定证明。
