2. 输入 `/wbprofile`，等待完成，再 `/reload`；代理读取保存文件，逐项区分可用/未知/待加载。
3. 与角色面板、赛季分数、团本周锁定、家宅具体条目对照；装备变更和第二角色另行采样，不能凭一次成功宣布全部通过。
4. 同步时机要分别对比未重载、重载、返回角色选择及正常退出；本切片没有常驻监听客户端，文件读取验证不能冒充自动同步交付。

### 第二轮：换装与重载保存

用户澄清是换装备而非换号。未重载时代理读取的文件与首轮基线字节一致；随后用户按采集并重载步骤操作后，文件哈希变化。新快照采集结束于本地时间 23:30:23，文件修改时间 23:32:20；角色身份相同，previous 快照与首轮解析数据完全一致。

仅主手槽 16 变化：物品 268198（321 装等）换成 237846（285 装等）；equipped 从 321.4375 变为 316.9375，overall 仍为 321.4375。两种装等字段不能混用。诊断错误为空。脱敏证据：`evidence/req093-20261116/equipment-change-summary.json`；原始快照仅本机私有留存。

此轮确认游戏可采集换装后的实际数据，用户重载后本地文件可读回新快照。未重载检查前的手动采集时间未独立观测，不能据此声称已完整证明所有保存时机；尚未验证正常登出、退出游戏和换角色，也没有交付常驻桌面同步器。

### 第三轮：返回角色选择界面保存

用户按“恢复装备、手动采集完成、不重载、返回角色选择”步骤回复完成后，代理读回更新文件。采集结束于 23:35:59，文件修改时间 23:36:03。主手由物品 237846（285 装等）恢复为 268198（321 装等）；equipped 从 316.9375 恢复 321.4375，overall 仍为 321.4375。身份未变化，previous 与第二轮快照完全一致，诊断为空。

结论：在本次用户执行正常登出的条件下，新快照已写盘并可读取；不要求每次必须 /reload。用户执行了游戏操作，代理验证的是落盘结果，未直接观测登出按钮交互。脱敏证据见 `evidence/req093-20261116/logout-summary.json`。此结果不等于无需采集即可同步，也不代表常驻桌面监听器已实现。

本轮证据：`evidence/req093-20261116/second-character-exit-summary.json`。确认第二角色快照身份独立，正常退出后新文件可读取。当前探针仅保留最近两份快照，并非完整多角色档案系统；完整客户端仍未实现。
