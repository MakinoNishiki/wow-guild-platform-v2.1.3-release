## 一、调研依据节（调研前置硬约束）

**097 主根定案证据链（FrameXML 一手源，Gethe/wow-ui-source live 分支拉取，存 `backup/_pytmp/EJ-mainline.lua`）：**

`Blizzard_EncounterJournal/Mainline/Blizzard_EncounterJournal.lua` 全文件仅 4 处 `GetLootInfoByIndex` 调用，唯一双参调用点 :217-231 逐字如下（要义）：

```lua
local numEncounters = EJ_GetNumEncountersForLootByIndex(self.index);
if ( numEncounters == 1 ) then
    self.boss:SetFormattedText(BOSS_INFO_STRING, EJ_GetEncounterInfo(itemInfo.encounterID));
elseif ( numEncounters == 2) then
    local itemInfoSecond = C_EncounterJournal.GetLootInfoByIndex(self.index, 2);
    local secondEncounterID = itemInfoSecond and itemInfoSecond.encounterID;
    ...拼「BOSS甲、BOSS乙」双归属展示文案
```

**第二参 = 该件装备多掉落归属 BOSS 的第 N 归属序**（仅当 `EJ_GetNumEncountersForLootByIndex==2` 时取第 2 归属拼展示文案），**不是「按 BOSS 序号取该 BOSS 掉落」的选择器**。1.0.19 送审引用的「Mainline :226 传字面 2」恰恰是对该语义的反证——当时解读反了。

由此 097 全特征获确定性解释：单归属件（绝大多数）N≥2 恒 nil → `li=1` 即终止 → 2 号位起枚举个位数 0；N=1 对任何件恒可用 → 1 号位全绿。纯参数语义错误、无状态依赖 → A/B 逐实例件数全等。冒烟三版（1.0.19/1.0.20/1.0.21）目标全是 1 号位 → 穿网。

**098 证据链**：`EJ_IsLootListOutOfDate` wiki 在册口径="whether the loot list is out of date **in relation to any filters**"（过滤器态），不跟踪 encounter 选中变更——1.0.17 F2 引入时的注释已在案。重试路径（阶段一 :902 旧码 / 阶段二 :617 旧码）均只 `C_Timer.After(0)` 原地重试、不重选 encounter——选中未生效时列表永不归位。

**至暗之夜件数佐证（Supabase 只读查询，anon 公开通道）**：DB `boss_loot` 已录至暗之夜 **4 首领各 8 件（索姆贝兰/普雷达萨斯/克拉格平/鲁阿夏尔，合计 32）**——12.1 EJ 四首领在册且各有掉落表，097 修复后至暗件数预期 ~32 而非 8（旧 8±2 系 12.0 客户端仅 1 encounter 时代口径）。**判据已按 32±4 落地 validator/步骤卡，标注待运营裁定**。
