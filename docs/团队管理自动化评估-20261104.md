# 团队管理自动化评估 · 2026-11-04

范围：角色认领、考勤与装备分配。评估阶段，未连接用户账号、未改生产。

| 场景 | 首选证据 | 产品动作 |
|---|---|---|
| 多角色认领 | WCL 用户 OAuth + 角色归属字段；国服正式服待实测 | 一次授权，匹配当前公会未认领角色，用户一键确认；沿用自由认领、审核与仅管理者分配 |
| 考勤 | 已绑定活动的 WCL 报告与参战记录 | 复用现有 WCL 同步预览和写入；保留人工标记，未匹配与无报告留人工处理 |
| 装备 | Collector 游戏内拾取流水；WCL 拾取事件另核覆盖 | 同场多件一并导入；用时间、首领、角色和物品标出候选；团长确认分配 |

WCL 用户端点和 OAuth 授权码流程已见官方文档。官方生成的 Character schema 记录 claimed 需要 view-user-profile；国服正式服是否支持完整列表、私有角色和逐项归属仍须授权账号实测。若只能逐角色查询，则从站内当前公会名单生成候选，用地区／服务器／角色名查询，再批量预览有 claimed 证据的角色。已有认领冲突或同名不自动覆盖；本次无需存长期 token，后续若做定时同步须先解决 #70-WP2 凭据隔离。

国服英雄榜支持登录查看账号角色，国服曾与 NGA 做官方授权绑定。公开角色链接可用于补齐身份资料；只能以授权接口确认账号归属。魔兽管家获得相同合作权限尚无证据。

Collector 保留自动采集职责，短期不扩大到考勤或认领。先用一场真实团本验证谁的拾取事件可见、是否漏记、重复导入是否幂等，以及拾取者和最终接收人不同时如何调整。只允许确认后创建分配记录。若 WCL 对国服同场拾取覆盖充分，默认用 WCL，Collector 作为补漏；否则 Collector 是装备事实的独立输入。勿要求每位团员安装。

建议先做 WCL 认领只读试验，后做 Collector 同场对账。#75 保留真机验收待办，现有插件先不改。

## 三环节流程与优先级

统一工作流：建立名单、成员认领角色 → 创建或找到本场活动、关联日志并确认考勤 → 导入拾取流水、确认最终分配。角色认领可在开打前完成，也可在团长处理未匹配角色时补做。每步显示当前状态和下一步入口，拾取可提前采集，团长不必等考勤全部完结才查看。

| 环节 | 已有功能 | 当前缺口 | 优先级 |
|---|---|---|---|
| 成员管理 | 手工添加、智能导入、WCL 报告导入角色、按角色认领、认领审核与管理者分配 | 从报告导入角色属于建名单，缺玩家一次确认多个角色的入口 | P1：先做 WCL 授权只读试验，再决定批量认领 |
| 考勤 | 手动建活动、WCL 公会绑定、报告同步、新报告预填、自动创建、参战预览、同步考勤、复盘和团本速览 | 公会报告归属不足以判定是否本团；新建与关联耦合，现有活动缺明显入口；详情多个 WCL 按钮 | P0：先挡误建；P1：统一报告操作与补链 |
| 装备分配 | 手工分配、装备库、心愿单匹配、Collector 拾取与去重导入 | 导入只是拾取流水，分配要再录入；缺场次匹配和最终接收人确认 | P2：先真机同场对账，再做分配草稿 |

### P0 自动发现与人工确认

代码 server.js 的 wclAutoCreateSweep 每小时扫描，启动后约 5 分钟先跑一轮。仅筛选已开启自动创建的绑定公会，过滤未知区域、七天前、已关联和同日同副本重复。没有检查日志里的参战者与团队名单是否相符；通过现有门槛后直接插入正常活动，但该任务本身不写考勤行。部署是否启用、具体公会开关状态未实查。

首期将扫描结果列为待确认，提供关联已有活动、创建活动、忽略。已发现报告时，给出副本时间、名单匹配数与未匹配角色；匹配用地区、服务器、角色名或已核实的稳定身份，同名歧义人工确认。时间、副本及团号可缩小候选范围。遇到同晚同副本多团、野团误传或拆分报告，保留候选和解释。不要用未经运营验证的统一人数阈值直接入账。后续在积累真实样本后再开放高置信自动关联。

### P1 统一活动详情的 WCL 入口

活动详情使用「战斗日志」。未关联时编辑者可添加；已关联时集中提供复盘原文、同步考勤预览和更换链接。只读成员可打开复盘。列表上的同步 WCL 报告属于发现公会报告，建议命名「查找新报告」，避免与本场同步混淆。

源码已有 showActivityModal(activity) 的回填、活动更新载荷及 cloud.js 的 wcl_url 和 wcl_report_code 写入；当前搜索只见 showActivityModal() 和预填调用，没有找到现有活动调用带 activity 参数的入口。将此作为入口缺口复现，不能据此确认生产写入一定成功。更换链接时保留人工标记，展示旧报告生成结果与新报告差异；确认后仅更新可追溯的旧同步记录，旧快照与新链接保持一致。不具备溯源的旧活动先提示人工核对。验证创建后补链、编辑／更换、保存失败可重试和 viewer 无写入。

### 简明站内引导草稿

1. **先建名单**。团长导入角色，团员到「我的认领」确认自己的角色。
2. **打完核考勤**。打开本场活动的「战斗日志」，选择已有报告或粘贴链接。核对参战名单后同步；列表里找不到本场时先「查找新报告」。
3. **最后确认装备去向**。在同一场次导入拾取记录，核对物品与最终接收人，再确认分配。代拿或未分配的物品留在草稿。

首期交付建议为 P0 安全闸 + P1 补链和集中入口的任务书；WCL 批量认领试验可以独立推进。待三个环节命名确定后，把以上三条放到各页面空态与当前步骤附近。此轮为源码评估，未修改产品或生产配置。
