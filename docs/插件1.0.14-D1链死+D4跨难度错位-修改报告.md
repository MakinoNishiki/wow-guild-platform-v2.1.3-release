## 一、D1 逐环核（四问正面回答）

**①C stack overflow 递归源**：`whenItemReady` 就绪路径**同步直调** `guarded()`——调用拓扑为
`stepItem → whenItemReady → guarded → pcall(fn) → stepItem → …`，每件物品叠 ~2 层 pcall C 边界且**栈永不中途展开**；
whenAllReady 的就绪确认链、finishBoss→nextBoss→stepItem 的跨 BOSS 链同样叠在同一栈上。
冷缓存一跑因 ContinueOnItemLoad 异步回调断链反而保命；**暖缓存跑（二跑起）全链同步化，连续就绪件百件量级即触 Lua C 调用深度上限 → C stack overflow**。这与现场「一跑好于二跑、跑越久越易断」的分布吻合。
**修复**：就绪路径改 `C_Timer.After(0, guarded)` 下一帧执行——每个回调独立浅栈（深度 ≤10 帧），递归源根治。代价：每件 +1 帧，全量约 +15~30s（相对 15–20 分钟总量可忽略）。

**②「SecureTypes nil」守卫缺在哪**：**我方代码面 grep 零命中（addon/ 全目录），SecureTypes 不是本插件符号**——疑似暴雪 EJ/Item mixin 内部路径被我们的调用时序触发。我方全部外部调用点守卫复查结论：EJ_SetDifficulty/GetDifficulty/SelectInstance/SelectEncounter/GetEncounterInfoByIndex/GetLootInfoByIndex、C_Item.*、Item:CreateFromItemID 均已 pcall 或 type 守卫；唯二直调例外 = 阶段一 while 循环顶的 `EJ_GetInstanceByIndex`（段级 pcall 兜底）与 doExport 的 `EJ_GetCurrentTier`（ejAvailable type 检查通过后直调）。**要定位需现场错误全文（红字整屏截图或 Swatter/BugSack 栈）——请运营下次复现时取证，本包不盲改**。

**③throw 之后「导出链继续」为何谎报**：`guarded()` 的 pcall 包住的是**含续推 `stepItem()` 的整个 fn**——续推途中（下游某件/某 BOSS）抛错被同一 pcall 捕获，文案照打「链继续」，但抛出点之后的帧全部夭折，链实际已死。**修复**：帧延迟化后每个回调栈浅、抛错面收窄到当件处理本身；文案诚实化改「导出链中断（已扫数据已按段落表不丢，1.0.13），请 /reload 后重跑并截图反馈顾问侧」。

**④回调续推是否真实发生**：**不真实**，机制同③——续推调用在被捕获的 fn 内部，throw 即断。1.0.14 后续推点在浅栈内（stepItem→whenItemReady→After 即返回），可抛错的面只剩单件解析体（本身已 pcall）。

## 二、D4 质询正面回答

**守卫比对键设计质询**：旧键 = `li` 序号同位重取 + `itemID` 比对——**只能检测错位、不能纠正**，且「同序号即同件」在档间列表件数/顺序不同时先天失效（守卫拦截=丢件，不找回）。**新键 = itemID 建索引**：切档后枚举当档全列表建 `map(itemID→info)`，我方物品按 id 查表取当档 link——档间顺序/件数差异天然免疫，`li` 序号字段随之退役（记录/透传/抹除三处已清）。

**逐档读回时序**：旧码 `EJ_SetDifficulty → EJ_GetDifficulty 读回通过 → 立即扫`——读回只证明**难度档位变量**已切，不证明**掉落列表**已重建；EJ 列表重建无同步保证。修复：读回通过后 `C_Timer.After(0)` 让一帧再枚举扫描。

**「01:28 二跑鲁阿夏尔 1/7→3/3、索姆贝兰 1/7→4/4 是否证明 EJ 列表切档异步未就绪是主因」——是**，机制链闭合：
1. **波动方向**：同 BOSS 同客户端跨跑带档率 1/7↔3/3 漂移——数据源真缺应稳定复现，只有时序竞争会波动；
2. **二跑更快更易撞**：暖缓存让切档→起读的间隔更短，更容易撞进列表未重建窗口（与 D1 暖缓存爆栈同一根时序放大器）；
3. **1.0.12 就绪门改变了切档前时序基线**，使竞争窗口暴露面变化。
佐证在案：run1 异常集中烈毒之渊 3/5/6 号位连续段。修复三件套=帧延迟 + encounterID 陈旧校验（枚举采样，整表属其他 BOSS=上一选中态残留，帧延迟重试至多 2 次，仍陈旧记 `staleSkip` 跳该档续扫，不跨 BOSS 蔓延）+ itemID 索引化。stats 口径 `absent`（当档列表无此件）取代 `idMismatch`；分案报错文案同步更新（陈旧跳档/缺 link/全缺席/0 档值 四路径分开）。
