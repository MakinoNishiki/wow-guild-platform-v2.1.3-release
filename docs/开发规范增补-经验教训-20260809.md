## 二、根因归纳

1. **修复副作用零审计**：动手前不盘点"这次改动会碰到哪些既有行为"，只盯着目标缺陷。
2. **不确定不送审**：对实现方式没把握时直接上手改，赌对了过关、赌错了返工——期望成本远高于先确认。
3. **断言只验正向、只验逻辑、只验目标点**：样式生效与否、动画逆向、邻接元素，全在断言视野外。
4. **数据前提静默**：断言依赖的库内样本变化无人察觉，绿灯失去意义。

## 三、新增强制规范（即日生效）

### §1 修复副作用审计（最高优先级）
任何修复/补丁动手前，必须先输出一张**副作用审计单**，随完工报告一并交付：
- 本次改动触及的约束清单：宽度 / 高度 / 排版 / 图层(z-index) / 动画时序 / 数据样本前提 / 其他（逐项列）。
- 每项写明：此改动**可能影响哪些既有行为**，以及对应的验证方式（断言编号或目检点）。
- **任何一项拿不准 → 先停手，把不确定点送审顾问+运营确认后再改。禁止"先改了再说"。**

### §2 视觉规则运行时断言
凡新增/修改样式规则，verify 必须含 `getComputedStyle` **生效值**断言（如 cursor/opacity/border-style 实测值），禁止只断言类名/结构存在。"类加上了" ≠ "样式生效了"（坑 1、2）。

### §3 动画/交互双向连帧
凡方向性交互（展开/收回、开启/关闭、浮出/渐隐），verify 必须**双向**连帧测量（正向三帧 + 逆向三帧），且双向观感一致（同 duration、同缓动、无分段卡顿）。只验正向视为未验（坑 3、6）。

### §4 数据样本前提声明
verify 中断言若依赖库内特定数据样本（如"未溢出特效卡存在"），报告中必须**声明样本数量**；样本为 0 时断言状态标「无样本」并在报告中显著提示，禁止静默放宽或通过（坑 7）。

### §5 注释与字符串安全
CSS/JS 注释内容禁止出现半角闭合序列（`*/`），统一用全角 ＊ 或改写措辞；新增 lint 级断言：构建前扫描样式表注释配对完整性（坑 1）。

### §6 版本串纪律（重申）
同一版本串不得对应两次改动；改动 js/css/html 必递增；跳号必须在报告中说明原因。
