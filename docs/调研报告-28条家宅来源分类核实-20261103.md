# 28 条家宅来源分类核实（第一轮）

## 结论

28 条均已对照当前真机扫描原文逐项核实，不能把它们全部作为“缺少映射键”一键修复。

| 分组 | 件数 | 本轮结论 |
|---|---:|---|
| A：明确来源标签别名 | 6 | 3 条“要塞任务”可归 `quest`；3 条“活动＋宝藏”可归 `event`＋`treasure`，保留名称、宝箱与地区 |
| B：类型有依据，但必须保留获取链上下文 | 13 | 6 条周常任务、4 条麦卡贡活动、2 条成就＋物品＋商人、1 条货运与接收；分类建议明确，不代表全部奖励机制已实测 |
| C：仍需机制或价格证据 | 9 | 7 条含“采集”、普通佩佩 25546、异常价格画作 2523；不猜分类或改价 |
| 合计 | 28 | A＋B 的 19 条是后续可实施候选；C 的 9 条不能宣称已核清全部机制 |

其中“物品”是获取链上下文，不自动等于怪物掉落；“工作”在本条指货运活动的工作上下文，不等于专业制造；“采集”也不能直接等同 `profession`。六件阿曼尼家具原文明确存在 `drop`、`treasure` 两条路径，但第三条“采集”路径尚未核清，不能因两条已知路径就认定整条来源完整。

本轮读取了项目开发规范、活台账及 research skill。逐条依据是当前客户端导出的原始 `source_text`，不是公司旧聊天或旧网站攻略：

- [当前 2335 条目录](../data/task083/catalog-current-2335.json)：本文表格中的 record_id、item_id、名称及原文。
- [28 条待处理审计清单](../data/task083/catalog-refresh-audit.json)：`source_pending`。
- [真机采集证据](../data/task083/scan-evidence-20261102.json)：客户端 **12.1.5 / build 70688**，插件 **0.2.1**，run_id **20261102-224408**，2335 条、唯一 2335、失败 0；输入 SHA256 为 `db26e15ba0c115f74462c26aa7c69d27d3a71d2ea615fbdd24bafe495b040e23`。
- [插件采集实现](../addon/WoWButlerDecor/WoWButlerDecor.lua)：直接调用 `C_HousingCatalog.GetCatalogEntryInfo`，白名单保留 `sourceText`，本轮不重新解释或替换扫描值。

暴雪客户端 API 文档中的 `HousingCatalogEntryInfo.sourceText` 定义为该条目的具体获取来源描述，并提示阵营可能影响返回的来源。因此当前扫描是此客户端环境下的目录来源证据，不能扩张成已经证明全阵营、所有阶段完全一致。[客户端 API 文档镜像](https://raw.githubusercontent.com/Gethe/wow-ui-source/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/HousingCatalogUIDocumentation.lua#L539)。此链接是暴雪客户端文档的公开镜像，`live` 会变化，并非本机 build 70688 的固定版本；它只解释字段合同，逐件内容仍以本地扫描为准。

信心分两层：**分类高**表示当前客户端明示类型或同义标签；**机制未核**表示未取得当前版本的实际任务奖励、容器掉落表、商人物品或采集交互证据。分类高不等于获得途径已真机试取。

## 对后续实现的约束与建议

现有 [解析器](../scripts/decor/parse_source.py) 的 `normalize` 会为 vendor/quest/drop/treasure 重新构造字段；单独附加 `source_item` 等字段可能被丢弃。[详情渲染](../js/decorData.js) 在 `sources` 非空时只渲染结构化来源，原始 `source_text` 不再作为完整兜底显示。因此“数据库仍存原文”不足以证明用户仍能看见物品、工作和未解释片段。

后续可分两步实施：

1. 先处理 A 组 6 条明确别名，逐条比对任务名称、宝箱、地区仍完整显示；来源数组存在多个元素，不等于已经证明是互相独立的获取途径。
2. B 组 13 条先确定如何利用现有字段表达上下文，并验证规范化与详情展示均保留。不得仅增加未知字段、丢弃“物品/工作”行，或为凑满分类强造 `drop`。C 组继续保留原文与异常队列，在一手证据补齐前不全量放行。

后续重点证据清单：七条采集的实际对象/技能/交互与家具奖励；普通佩佩的来源类型；画作的商人实价与疑问标记；六条周常及四条麦卡贡的具体任务/物品奖励关系；两条前置物品到家具的实际关系；路灯“法定休假”的奖励触发。可由代理准备本地读取与比对，确需游戏操作时再给运营最少步骤。本轮没有实际获取这些家具，没有声明真机取物或真浏览器测试通过。
