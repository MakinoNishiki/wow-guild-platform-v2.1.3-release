# REQ-185 账号关联与批量认领交付

候选资源版本20261106.130。引用开发规范、REQ185已确认方案和design-plans/req185-wcl-claims.md。未提交、未推送、未部署生产。

## 实现

用户中心→我的认领：读取WCL关联状态，发起本人授权，返回后确认关联，再勾选当前公会角色认领。回调不直接写关联，不自动建成员或认领；沿用原认领列表、职业图标及三档规则。解除WCL关联保留已有角色认领。

服务端固定WCL_USER_REDIRECT_URI、JWT绑定会话、浏览器HttpOnly/SameSite Cookie、十分钟单次授权和短期候选；仅view-user-profile，不存长期令牌。严格CN/同名/同服匹配，缺信息/歧义/占用不自动处理。SQL43双向唯一约束，用户只读本人、写入经专用端点。

批量确认逐行重新核查当前权限和名单；认领使用user_id=is.null条件更新并确认返回行。审核申请重复或响应丢失后核对本人pending，不能把他人的申请当成功。关联确认短期重试返回既有结果，解绑撤销证据。按开发规范1.2.2登记服务端批处理，客户端统一重载，无本地乐观假认领。

## 验收边界与发布准备

REQ184曾完成运营本人真实WCL授权并回传11个CN角色，证明接口可用；不能将其等同本批正式入口已完成真人WCL联验。本批正式浏览器保存链路使用合成WCL账号，未改运营真实认领。

生产发布仍需授权执行SQL43、配置正式HTTPS回调WCL_USER_REDIRECT_URI、在WCL后台追加相同完整地址、部署服务端和前端；lib/目录必须随server.js发布，静态白名单不会公开它。回调建议https://wow.ddctl.com/api/wcl/user/callback（需核验此域实际API路由落到同一服务实例），不盲目填入。缺配置入口禁用，缺表明确报错，不能声称已上线。

上线验收：本人授权→确认关联→核对候选→选一个确属自己的未认领角色→刷新确认；审核公会只产生申请；解绑后原认领仍在。需要运营验收及单独生产发布许可。

## 已知限制

授权/候选保存在单进程短期内存，重启或十分钟过期需重新授权；多副本部署需先解决会话共享。仅匹配当前公会活跃名单，不自动导入其他角色，不自动跟随转服改名。当前职业图标复用已匹配站内成员职业，不把WCL数字职业ID套用暴雪ID。无长期角色同步。
