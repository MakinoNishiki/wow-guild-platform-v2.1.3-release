# PC 客户端：国服数据渠道与能力边界调研

日期：2026-11-16。性质：只读调研，不是功能交付或真机验收。未读取凭据、未访问生产数据库、未修改网站或插件代码。对应既有 REQ-093 客户端方向的补充研究；不据此扩大本期开发范围。

## 一、国服不能直接套用海外 Web API 方案

需要区分三件事：游戏内插件能读什么；本机客户端能接收什么；服务器能通过官方或第三方 Web API 查询什么。安装 PC 客户端不会自动获得国服战网接口权限，也不会让网页缓存成为实时游戏数据。

**国服确有英雄榜，也存在官方合作的数据展示渠道。**国服官方于 2025-01-02 宣布英雄榜 Beta 上线，已支持角色信息、属性配装等；公告中仍列作未来计划的功能，不能当作当日已交付。2025-09-10 官方 NGA 合作公告进一步说明，绑定后可在 NGA 展示选定角色的官方英雄榜信息，包括装备物品等级与成就点数。[国服英雄榜公告](https://wow.blizzard.cn/news/20634739/index.html)、[NGA 绑定官方公告](https://wow.blizzard.cn/news/20250910/40565_1258595.html)。

这证明渠道存在，**不证明魔兽管家可以直接申请相同接口，也不证明海外 Battle.net 客户端凭据可以直接访问国服。**本轮未取得足以确认国服第三方开发者自助接入条件、角色字段范围、授权作用域与速率限制的官方开放文档；相关事项仍待接入方确认。国际站区域文档入口本轮重定向后无法读取，未将第三方镜像或旧论坛问题当作当前接入依据：[官方区域文档入口](https://develop.battle.net/documentation/guides/regionality-and-apis)。

## 二、第三方渠道的证据与限制

### WCL：本项目已有国服角色归属样本

项目既有核查记录显示：2026-11-05 用户本人完成真实授权后提供接口正文，返回 11 个角色，全部 `region.slug=CN`、`claimed=true`，角色名、服务器、ID 与 canonicalID 均有值。这是一个账号的有效样本，不是全战网角色覆盖证明，也不是本轮独立重测。原始账号标识不重复入库。[项目既有核查记录](./WCL账号授权只读验证-接口核查-20261105.md)。

WCL 官方 SDK 将 `gameData` 描述为已有的角色游戏数据缓存，例如装备；不能据此承诺刚换装备即可同步。`claimed` 表示当前 WCL 用户认领该角色，不能扩大解释为战网实名验证。[WCL 官方 SDK Character](https://rpglogs.github.io/RPGLogsApiSdk/types/Character.html)。

产品建议：复用 WCL 作为已有认领证据和已上传战报的来源，区分战报时装备、英雄榜缓存装备与当前插件快照。仅凭缺少战报不能判断角色从未击杀；仅凭某份公会报告不能自动认定所有参战者都是本公会成员。这些是数据解释边界，不是本轮新增实现。

### Raider.IO：当前接口结构包含 CN，但不能默认直接接入

本轮直接读取官方 Swagger：`/api/v1/characters/profile` 的 `region` 枚举包含 `cn`（同处说明文字漏列 CN，以结构枚举记证据）；可请求装备、团本进度、赛季大秘境分数。服务说明数据来自官方 API、Live Tracking 及社区贡献，并不保证完整性或及时性。本轮未请求具体国服角色，因此“参数支持 CN”不等于所有国服角色、所有字段已实测可用。[Raider.IO 官方 API 规格](https://raider.io/swagger.json)。

该规格还要求公开产品标注来源链接，禁止构建竞争服务或转售数据，商业使用需联系许可；魔兽管家的功能存在潜在重叠，接入前应确认许可范围，不能直接列为确定的数据依赖。公开接口有速率限制，不能承诺任意高频实时刷新。[同一官方规格的使用条款](https://raider.io/swagger.json)。

Raider.IO 帮助中心仍保留“中国 API 于 2016 年停用”的旧说明，同时列有中国用户申请日志上传的渠道。不能从旧说明推出“中国所有数据渠道至今都不可用”。[Raider.IO 中国社区说明](https://support.raider.io/kb/chinese-community)。

## 三、本轮结论与下一步核对范围

| 渠道 | 已有证据 | 尚不能承诺 |
| --- | --- | --- |
| 国服官方英雄榜 | 官方页面及 NGA 合作展示存在 | 本项目可自助取得开放 API、所有字段实时更新 |
| WCL 用户授权 | 项目已有 11 个 CN 认领角色样本 | 全部战网角色、隐藏角色覆盖、实时装备、完整赛季进度 |
| Raider.IO Web API | 官方结构支持 CN 及相关字段 | 本项目许可、具体国服角色完整性、刷新时延 |
| 游戏插件 → PC 客户端 | 属于不同于 Web API 的本地采集路线 | 仅启动游戏就自动读取所有未登录角色、任意游戏内部数据 |

后续只读样本验证应记录地区、游戏版本、角色标识、数据来源、采集时间和同步时间；分别对照游戏当前装备、赛季分数、普通/英雄/史诗进度。不把周锁定进度当赛季累计，不把账号/战团成就当单角色击杀，也不把个人进度当公会进度。

## 四、游戏内字段能力矩阵

以下基于暴雪随客户端提供的 UI/API 定义（Gethe 仓库镜像）及插件作者源码核查。镜像 `live` 是滚动分支，不代表本机国服当前 build；`Environment=All` 也不是“中国区已实测”的证明。本轮没有运行游戏内采集，没有验证所有字段在国服当前版本的返回值。

| 用户想要的信息 | 能力判断 | 证据与实现边界 |
| --- | --- | --- |
| 角色名称、服务器、种族、性别/体型、职业、等级、专精 | 有游戏内采集依据 | 自己进入角色后读取 Unit 系列与专精 API；不能由“启动进程”推导正在使用哪个角色，也不能默认取得所有未登录小号的最新状态。性别字段是游戏角色数据。见 [Unit API 定义](https://raw.githubusercontent.com/Gethe/wow-ui-source/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua)。 |
| 当前装等与角色面板 | 可形成快照 | 暴雪面板调用 GetAverageItemLevel，分别处理平均/已装备/PvP 装等；产品应明确显示已装备装等。战斗临时增益与静态装备面板需区分。见 [PaperDollFrame 源码](https://raw.githubusercontent.com/Gethe/wow-ui-source/live/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/PaperDollFrame.lua)。 |
| 每个槽位的装备、实际装等、宝石等 | 可形成装备快照，字段完整性待真机核对 | C_Item.GetCurrentItemLevel、GetDetailedItemLevelInfo、GetItemGem、GetItemStats 等有定义；完整物品链接要保留，不能仅用基础 itemID 对应的字典装等替代实际装备。空值等待加载，不能用 0 假装成功。见 [Item API 定义](https://raw.githubusercontent.com/Gethe/wow-ui-source/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ItemDocumentation.lua)。 |
| 换装后更新 | 游戏内有事件；PC 端秒级同步尚无已验证方案 | 暴雪 UI 监听 PLAYER_EQUIPMENT_CHANGED / PLAYER_AVG_ITEM_LEVEL_UPDATE；这只证明插件能知道变化，不证明外部程序已经收到变化。 |
| 家宅已拥有、库存、已摆放 | 有个人状态字段依据 | HousingCatalogEntryInfo 有 totalNumStored、remainingRedeemable、totalNumPlaced。它们分别涉及存储、待实例化存储、跨房屋已摆放数量；先逐件核对再计算。当前库存不能直接代表“历史曾解锁”。见 [HousingCatalog API 定义](https://raw.githubusercontent.com/Gethe/wow-ui-source/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/HousingCatalogUIDocumentation.lua)。 |
| 家宅收集率、缺件清单 | 可设计，百分比口径须另定 | 以去重装饰种类计算，不按副本数量计算；需要明确国服可获取范围、变体、房间/户型是否排除、当前拥有还是历史解锁。GetDecorTotalOwnedCount 是存储件数，不能直接除以网站全量目录条数当收集率。账号/战团共享内容不重复归到每个角色。 |
| 本赛季大秘境分数、各本最佳表现 | 有明确接口依据 | C_PlayerInfo.GetPlayerMythicPlusRatingSummary 返回 currentSeasonScore 及地图表现；C_MythicPlus.GetSeasonBestForMap 返回限时内/超时最佳。官方分数与第三方排名分开，不默认具备全服排名或完整历史。见 [PlayerInfo API](https://raw.githubusercontent.com/Gethe/wow-ui-source/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/PlayerInfoDocumentation.lua)、[MythicPlus API](https://raw.githubusercontent.com/Gethe/wow-ui-source/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/MythicPlusInfoDocumentation.lua)。 |
| 本周团本进度 | 可读取锁定信息 | SavedInstances 实现使用 GetSavedInstanceInfo 等读取副本锁定与重置；这是周期性记录。见 [SavedInstances 作者源码](https://github.com/SavedInstances/SavedInstances/blob/master/SavedInstances/Core/Core.lua)。 |
| 普通 8/8、英雄 8/8、史诗 7/8 的累计战绩 | 可作为产品目标，不能只依赖周锁定 | 按赛季/团本/难度/首领组织已确认击杀；可接 WCL 已上传报告，或后续验证角色级统计和允许接入的英雄榜来源。不能把新一周的空 CD 视作从未击杀，也不能把未上传日志视为 0/8。首次使用能补回多少历史尚待验证；历史角色统计若无击杀日期，也不能冒充完整赛季时间轴。 |

本项目已有 `addon/WoWButlerDecor/WoWButlerDecor.lua`，调用上述目录接口，但当前导出白名单主动剔除玩家状态，属于目录采集器，不是个人收藏同步器。台账记录的国服 build70688、2335 条目录扫描成功只能证明当时目录通道成功，不能替代个人库存/已摆放字段验收。Collector README 也明确目前没有自动上传程序；不能把已有拾取导出能力描述为已完成 PC 同步。

## 五、自动同步与实时同步的边界

可行的第一版路径（产品建议，未实现）：

```text
进入角色 → 插件采集角色/装备/收藏快照
                        ↓ 游戏重载或正常登出保存
                  PC 客户端自动接收并上传
                        ↓
                同一账号的桌面端与网页端展示

战斗日志 → PC 持续读取 → 战斗/击杀事件更新（另一种数据来源）
```

- SavedVariables 通常在正常登出或重载 UI 时写盘；定时改 Lua 内存不等于定时写文件。客户端监听文件只能接收已保存的数据。[插件作者关于保存时机的说明](https://github.com/Anduin-Webworks/Time-Logger#crash-recovery)。
- Raider.IO 自己也区分“登出后角色扫描”和基于战斗日志的 Live Tracking。[Raider.IO 产品说明](https://raider.io/addon)。因此可以实现用户不用手动找文件/上传文件的自动接收，但尚不能承诺换一件装备 PC 就在一秒内显示，或家宅摆件变化由战斗日志完整传出。
- 提供按钮复制快照可作为即时手动同步；这条路径不依赖文件已经保存，但仍需要用户操作。现有 Collector 的复制导出即属于这类路径。
- 客户端启动游戏不自动授予战网权限；本地采集以当前实际登录角色为主，其他角色显示已采集快照及更新时间。仅有本地文件不能作为角色归属的权威证明，更不能自动升级公会权限；既有 WCL 认领证据单独保留。
- 对外展示采用独立隐私选择：允许客户端采集、允许同步本人云端档案、允许向公会/公开主页展示是不同设置。个人共享收藏也不能当作单角色或公会资产。
- 每项数据记录来源、游戏 build、地区、采集时间、上传时间；加载失败/无权限/未采集显示未知或待同步，不能覆写成 0。游戏内保护/秘密值按当前版本限制处理，不尝试绕过；静态资料优先在脱战且加载完成后采集。

## 六、进入客户端开发前的最小国服验证

这是一份后续验证清单，本轮未安装新插件、未要求用户中断游戏，也未改变当前研发排期。

1. **角色身份和装备**：同一角色进入世界，核对名字/服/种族/职业/专精/性别字段；与角色面板逐槽位比对装等。更换一件装备，检查游戏内快照变化；分别对比未重载、重载、正常登出三个时点的文件内容。验证实际保存时机，而非只看事件触发。
2. **家宅**：选择已拥有未摆放、已摆放、同类多件、未拥有四种装饰；核对库存和放置数，切换小号确认共享范围。存在变体时确认是否去重，确认当前拥有与历史解锁能否区分。
3. **大秘境**：与游戏内赛季总分和各本最佳层数/限时状态逐项比较，等待异步数据加载；新赛季与无记录状态不伪造为故障或历史清零。
4. **团本**：按普通/英雄/史诗分别比对周锁定与已知累计击杀；用确有历史但本周未打的角色验证差异。WCL/英雄榜来源缺失时保留未知，公会里程碑另行确认归属。
5. **第二角色与隐私**：切换角色后两份记录不串号；退出后自动接收；未经公开授权的档案仍只对本人可见。个人角色归属验证继续独立于本地快照采集。

通过这些验证后，才把能力标为“国服实测可用”，再确定桌面客户端第一期范围。调研结论支持完整 PC 产品承载个人档案、收藏、团队与未来社交；其界面与账号可共用网站服务，数据采集与同步能力按上面的边界单独验收。

本轮交付仅此调研记录：没有功能代码、数据库或游戏目录改动，没有部署、SQL 执行或 Git 提交。
