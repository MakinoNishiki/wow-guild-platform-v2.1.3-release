# 魔兽管家 UI 设计规范 v2

> 地位：全站 UI 唯一基准。优先级：开发规范 > 本规范 > 历史 DESIGN.md / ui-design.md（二者原则已吸收进本规范，冲突以本规范为准）。
> 生效方式：任何涉及前端 UI 的任务书/补丁，施工前必须逐条对照本规范；**规范没有的组件/形态，先补规范再动工**（见 §10 设计评审闸）。
> 版本：v2.0（2026-08-06）｜ 依据：DESIGN.md + ui-design.md（Apple 原则蒸馏版）+ 任务书 #13 补遗/#22/#23 系列实战沉淀。

## 1. 设计气质

暗色史诗奇幻（暗夜城堡 + 金色符文）。灵感源自 WoW 游戏内界面；**借原则不借皮肤**，不追任何第三方风格（含 Apple 风）。

## 3. 字体与排版

- 字体栈：系统栈 `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei"`，禁 Web 字体；
- 尺度：标题 18/600｜正文 13–14｜统计数字 24/700｜侧边栏标题 16/700 金｜副标 11｜移动导航 10；
- 层级靠**字重+字号+行距组合**；强调用字重不轻易加字号；
- 字距：大标题 -0.02em、正文≈0、小标签可微放宽——禁止全站一个值通吃；
- 行距与字号反比：大标题 1.1–1.2 / 正文 1.5–1.7 / 数据表 1.3–1.4；
- 间距单位 rem/em，禁写死 px 堆叠。

## 4. 组件规范

### 4.1 按钮（四级，唯一体系）
主（btn-primary 金）/ 次（btn-secondary 描边）/ 危险（btn-danger 红）/ 文字（btn-text）。同页同级同尺寸；按下即 :active 缩放反馈（transform scale(0.97) 100ms）；耗时操作必带 loading + 防重复。

### 4.2 徽标/标签（.tag 体系）
语义色板：成功/警告/危险/信息/弱化；20px 高不换行（#22-WP1 定稿）；职业 tag = 官方职业图标 + 职业色底 + 文字（iconMap 单一来源）；**同类信息全站同一 tag 样式**。 金星变体（2026-08-07，#28）：属性优势标识——tag 右上角金色五角星（SVG 自绘，零依赖）+ 边框加粗 --gold，仅限装备副属性高值场景，不扩展用途。

### 4.3 Chip（筛选项，唯一形态）
高 24px 恒定｜左右 padding 10px｜圆角 12px｜12px/500。默认：深底+1px 描边+次级文字；选中：主题色描边+文字+10% 主题色底。组头 56px 左对齐 12px 次级色（2026-08-07 BUG-055 运营拍板：左对齐取代右对齐；组头/排除杂项行/搜索框行左缘同一条竖线）；组内间距 6px、子类间 1px 竖分隔线（16px 高）。用途扩展（2026-08-07，#25）：chip 同形态用于表单内多选/单选（星期、目标、福利等），尺寸与状态样式不变。

### 4.4 卡片
--bg-card 底 + 1px 边框；悬停边框提亮+阴影扩散；**默认统一尺寸**——长内容卡不得撑高兄弟卡（展开用覆盖层/自身 z-index 抬升，禁挤压网格）；可展开卡加边框高亮引导。优选变体（2026-08-07，#25）：卡片常态 --gold 1px 描边 + 角部「优选」.tag-gold，完整度类场景专用，与悬停提亮叠加不冲突。

### 4.5 表格
文本左/数字右/状态居中；斑马纹+悬停行反馈；数字列右对齐；表头与数据区分度；宽表 min-width + 容器横滚 + 表头吸顶（BUG-040 机制）；单元格内容垂直居中。

### 4.6 弹窗
`.modal-overlay`（scrim rgba(0,0,0,.6) + backdrop blur）+ `.modal` 内层（不透明底，**禁用未注册类名**——#24-补丁 透明弹窗即孤儿类事故）；大弹窗阴影/压暗重于小浮层；防误关=未保存内容才二次确认；z-index 走 modalStack 栈，禁写死。

### 4.7 表单与下拉
输入框/下拉统一 uc-input/uc-select 体系；**禁用原生 datalist**（过滤行为误导用户，#24-补丁2 已根除）；自定义下拉=暗色浮层+过滤+键盘可用；校验就地（字段旁提示），弃用原生 alert；日期输入中文遮罩（REQ-052 机制）。

### 4.8 筛选条（详见 §5）
chip 唯一形态、四组各行、同基线、模板排序——以《公示页筛选系统设计规范》为子规范（本规范 §5 全文并入，见下）。

### 4.9 空态 / Toast / 通知
空态必须有文案+引导动作（禁白屏）；Toast 四态（状态/完成/警告/错误），成功要确认、进行中要暴露、错误要中文人话；通知走 notifications 表 + 未读角标。

### 4.10 进度条（2026-08-07 增补，#25）

容器高 6px、圆角 3px、底色 --bg-tertiary；填充 --gold（常态）/ --success（达成态，如完整度 100%）；过渡只动 width/transform，200ms ease-out；配副标 11px 说明文字。卡片内迷你进度条同族（高 4px）。

### 4.11 属性色板与视图 tab 族（2026-08-07 增补，#28）

装备卡片主属性 tag 专用色：力量 #ff6b6b / 敏捷 #40c057 / 智力 #4dabf7——与语义色板（--danger/--success/--blue-highlight）及特效绿 #1eff00 区分使用，禁混用；副属性 tag 保持灰系现状。视图切换 tab 族（公示页）：沿用「按BOSS/整体池」toggle 形态扩展（全部/团本/秘境/套装），同族同规格。

## 5. 筛选系统子规范（并入《公示页筛选系统设计规范》v2.0）

结构（v2.0，2026-08-08 起）：首行 = 搜索框（置顶加宽）+「重置筛选」按钮（不放任何 chip）；小类别自第二行起，每组 = 区头标题 + chips——主属性（多选）/副属性（多选）/来源（单选：全部│团本/大秘境/副本任务/专业制造，值域赛季数据驱动、无数据 chip 不出现）；部位/类型细粒度筛选取消；杂项数据层排除零渲染，「排除杂项」开关整块删除；赛季切换全重置；筛选与结果严格一致为硬验收（删杂项后基线 343，按施工时实测重锚）。细则全文见 docs/公示页筛选系统设计规范.md（**v2.0（2026-08）取代 v1.0**，v1.0 四组各行/模板分组/排除杂项开关/搜索置底全部废止）。

## 6. 动效

只回答「从哪来、到哪去」；进出同路径；150–250ms（桌面超 300ms 即慢）；入场 ease-out / 离场 ease-in；只动 transform/opacity；尊重 prefers-reduced-motion。 筛选/搜索触发卡片重渲染：允许入场 fade+轻微上浮（150–250ms ease-out，只动 transform/opacity）；出场动画不做（2026-08-07，#28）。

## 7. 反馈铁律（来自 ui-design.md，升格）

1. 按下即反馈，不等接口；2. 过程反馈优先于结果反馈（禁止沉默）；3. 确认弹窗只给不可逆操作；4. 可逆操作给宽容（可改回）不给弹窗；5. 输入路径零无谓延迟。

## 8. 布局与响应式

桌面：侧边栏 200px + 主内容 flex；≤768px：底部 Tab 导航 + 表格卡片化 + 弹窗全屏；1366×768 与 1920×1080 为两档必测基准。

**移动端审计口径（2026-08-07 增补）**：本项目桌面优先（上述两档为必测基准），移动端/小程序封存、未立项。外部通用 UI 审计清单（improve-ui / web-design-guidelines 等）中的 mobile / responsive / touch 类发现，默认标记「已知取舍-封存」，不计入问题清单、不转任务书；仅当该发现同时改善桌面体验（如热区尺寸、对比度、字号可读性）时，按普通桌面项采纳——例：任务书#23-补丁4 的 24×24px 折叠热区源自触控规范，桌面端同样受益，已采纳入库。移动端正式立项启封时本条废止。

## 9. 设计禁忌（合并版）

不亮/白底；圆角≤8px（chip 12px 为例外，已注册）；禁鲜艳渐变；禁卡通图标；禁动画库/拖拽手势/音效震动；禁未注册组件类名进生产。

## 10. 设计评审闸（流程加固，运营拍板生效）

**任何涉及前端 UI 的任务书/补丁，立项前先过闸：**
1. 顾问侧起草/修订设计点 → 对照本规范给出「符合规范 §X」或「需新增规范条款」标注；
2. 新组件/新形态 → 先补写进本规范（运营确认），再进任务书；
3. Kimi Code 施工时若发现任务书与本规范冲突 → 停工报告，不自行发挥；
4. 运营侧如用外部 UI skill/工具产出方案（如 Kimi Code 本地装的 UI skills），同样先汇入本规范评审，再落地——**规范是唯一的闸门，工具是产线**。
