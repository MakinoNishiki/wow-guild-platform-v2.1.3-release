# REQ-181 隔离测试环境

2026-11-05。引用《开发规范》《问题与需求清单》。运营授权先只读检查，随后明确授权在现有服务器搭建独立测试环境。用途是解除 REQ-180 真实数据库联验的环境阻塞；不是生产发布。

## 已落地

- 服务器目录 `/opt/wowbutler-test`，Compose 项目 `wowbutler-test`。
- 4 个容器：独立 PostgreSQL、GoTrue 登录服务、PostgREST、Kong 网关。镜像版本复用生产现有版本；没有拉取最新版或调整生产配置。
- 独立数据库卷、配置卷、网络、数据库密码、JWT 密钥与 API key。新测试凭据只保存在服务器受限目录，不进仓库或报告；SSH 登录密码没有保存。
- 数据库/Auth/REST 仅接内部网络；网关另接测试 ingress 网络，唯一宿主端口为 `127.0.0.1:18000`。没有给公网新增监听端口，没有连接生产 Docker 网络或挂载生产数据卷。
- 内存上限：DB 512MiB、Auth 128MiB、REST 192MiB、网关 256MiB，合计 1088MiB。各容器禁止额外使用 swap，CPU 总上限 2.05 核，日志轮转 5MB×2。`restart=no`，按需启动，服务器重启不会自动启动测试栈。
- 生产只读导出 `public`、`auth` 结构和权限；复制 `auth.schema_migrations` 迁移元数据及 11 张游戏字典。没有复制真实用户、会话、公会、角色、考勤、装备分配记录或生产密钥。
- 字典白名单：game_patches、game_seasons、game_raids、game_bosses、game_classes、game_specs、game_dungeons、boss_loot、dungeon_loot、tier_sets、tier_set_pieces。家宅目录等不属于本次团队管理测试范围，未复制。
- 没有配置真实邮件服务；测试注册自动确认。测试实例不是生产安全配置模板，不应直接开放到公网。

## 实测结果

基础设施 API 联验 26 项通过，证据在 `docs/evidence/test-environment-20261105/verification.json`：

1. 检查项目标签、网络、卷、端口、资源限制；public 表数/RLS 策略数/约束数与生产一致。
2. Auth 健康与公开职业字典正常，职业 13 条。
3. 真实注册两个虚构账号，创建测试公会及 owner 关系。
4. owner 可读；另一账号读不到该公会，也不能修改。
5. 服务端权限写入后，通过 owner 登录态独立回读确认更新。
6. 删除测试公会和账号，检查用户与核心业务表合计为零。
7. 对比搭建前后的生产 DB/Auth/REST/Kong 容器 ID、启动时间与运行状态，未重建或重启。

另已实际停止四个测试容器，再启动并通过 API 读回 13 个职业；虚构测试账号为零，确认数据卷持久化。测试结束停止测试栈，保留配置和卷，后续由代理按需启动。

运行时采样：测试栈约 174MiB；宿主可用内存约 1748MiB，磁盘此前剩余约 30GB。短时轻量测试不能代替峰值容量评估；与生产仍共享物理主机，禁止压测、大批量导入或无人值守长期运行。

初始化曾因旧 roles.sql 引用未启用的 webhooks 角色失败；只修正测试初始化文件后继续。Docker 内部网络不能直接发布端口，网关追加独立 ingress 网络，数据库等保持内部隔离。两项调整已收录搭建脚本。

## 后续使用（代理代办）

启动前检查可用内存，建议至少 1.5GB，并确认端口没有其他服务占用。在服务器执行：

```sh
sudo docker compose -p wowbutler-test -f /opt/wowbutler-test/compose.json up -d
```

本机通过已验证主机密钥的 SSH 隧道连接，不开放公网 API：

```sh
ssh -N -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -L 127.0.0.1:18000:127.0.0.1:18000 ubuntu@101.35.124.22
```

测试结束停止容器，保留卷和字典：

```sh
sudo docker compose -p wowbutler-test -f /opt/wowbutler-test/compose.json stop
```

禁止使用生产 `.env` 启动测试应用，禁止直接运行会默认读取生产配置的旧联验脚本。后续测试应用需显式接入此实例，并校验目标；浏览器使用独立测试会话，避免混淆生产登录态。

仓库 `scripts/setup-isolated-supabase.py` 是首次创建脚本，目录已存在即拒绝执行，不作为重置工具。服务器副本为 `/opt/wowbutler-test/bin/setup.py`。`scripts/verify-isolated-supabase.py` / 服务器 `bin/verify.py` 强制固定测试目标，并在空业务库创建和清理虚构数据；已存在验收数据时应先核对，不强制清空。合并后的首次搭建脚本仅做语法检查，实际搭建及中间修正过程如上；没有为验证脚本再次删除重建环境。
