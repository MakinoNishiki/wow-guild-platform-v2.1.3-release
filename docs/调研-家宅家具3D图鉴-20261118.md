# REQ-205：家宅家具 3D 图鉴调研

日期：2026-11-18。状态：调研完成，候选待运营安排；未进入产品开发或部署。关联：TASK-084 静态模型缩略图、REQ-203 家宅分享。

## 结论

可以在现有家宅图鉴的家具详情内嵌入 3D 浏览区域，支持鼠标拖动旋转、滚轮缩放、重置视角，同时保留来源、价格和加入方案单。浏览者不需要安装游戏插件、电脑客户端或运行游戏。模型由我们预先准备，网页加载浏览器可读的模型文件。

本项目已有可复用基础：TASK-084 留下 26 个 GLB 模型、游戏资产 ID 映射及离线转换脚本。它们可以作为代表性试点输入；此前通过的是静态缩略图，本次只检查文件和技术资料，**没有完成真浏览器拖拽、缩放试点，也没有验证全部家具可用**。

建议候选首期聚焦“单件家具的外形浏览”。整屋布置、家具摆放编辑、动态粒子效果、染色和游戏内操作不在本次候选范围。3D 浏览与蓝图短码解析是两个独立能力：已有模型不代表网页能够取得短码对应的家具清单，也不需要因此增加发布者的游戏内操作。

## 需要保留的模型质量边界

原缩略图流程遇到过植物模型纹理单元缺失，并在导出时增加容错。预览端隐藏了部分无贴图网格、特定混合模式的小面片，以及心能水晶的部分动态效果网格；植物另设透明裁切和双面显示。这是静态展示的已知处理，不等于所有角度都与游戏一致。

因此新查看器不能直接照搬“PNG 能生成”作为模型合格标准。尤其需要检查模型背面/底面、叶片边缘、透明排序、发光层、朝向与包围盒。缺少材质或效果的条目应继续显示已有图片，或明确标注只展示静态外形；不能用“全家具 3D 已支持”描述现状。

模型映射应以目录 `record_id` 为业务入口，指向经过核验的模型资源及其游戏版本；`asset_id` 是游戏资产引用，不是网页 URL，更不能用 `icon_file_id` 替代模型 ID。

## 可选技术路线

| 路线 | 可实现的交互 | 本项目适配判断 |
|---|---|---|
| 自托管 GLB + `<model-viewer>` | 相机旋转、缩放、居中、加载占位等 | 普通单件展示接入较直接；旧模型的特殊材质处理需要先固化到模型或验证其可控性 |
| 自托管 GLB + three.js / GLTFLoader / OrbitControls | 旋转、缩放、平移、复位，材质/镜头/渲染生命周期可自行控制 | 与现有离线工具相近，便于处理魔兽特殊材质；需自行实现加载提示、可访问操作与资源释放 |
| WoWDB 第三方嵌入 | 已确认其站内有 3D 查看入口；公开文档支持物品/清单卡片嵌入 | 不能据此认定存在可供我们嵌入的独立 3D API；跨站加载、可用性及样式控制也尚未验证，不作为已打通方案 |

`model-viewer` 官方支持通过 `camera-controls` 开启交互，允许相机目标与缩放行为配置；可放入现有 DOM，无须打开独立页面。其加载示例提供 GLB、占位图及失败回退。引入这一浏览器组件不等于让用户安装游戏插件。[相机与交互文档](https://modelviewer.dev/examples/stagingandcameras/)，[模型加载文档](https://modelviewer.dev/examples/loading/)

three.js 的 GLTFLoader 提供 glTF 2.0 装载；OrbitControls 支持左键旋转、滚轮缩放、平移和复位。关闭详情后仍需显式管理几何、材质、贴图、事件和渲染循环；GLTFLoader 文档特别提示图片位图释放问题。[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)，[OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)

WoWDB 自身物品页显示“View 3D Model”；其 Embed Builder 文档列出的却是 Items/ItemSet、Grid/List、主题和缩略图配置。本轮没有核实到独立 3D 嵌入接口，不能把这两者混为一谈。[WoWDB 物品页](https://housing.wowdb.com/decor/31617/greatfeather-pepe-31617/)，[官方嵌入工具说明](https://housing.wowdb.com/tools/embed/)

路线建议：先用现有代表模型比较两种自托管查看器的实际材质表现，再决定运行库；不在调研阶段同时引入两套库。无论哪一种，新浏览器运行依赖都须按《开发规范》4.1 进行依赖评审；此处是技术候选，不是已经批准安装或上线。

## 资产准备及国服访问

现有转换基于 wow.export 0.2.14 的固定源码提交 `caf2bb0006930e151cd3810fba0f7d55e2e4b562`，已有本机 CASC→M2 解析→GLB 的脚本和来源记录。转换由维护端提前进行，用户浏览端仅请求审核后的 GLB，不扫描玩家电脑，也不访问游戏进程。[固定版本 M2 导出器源码](https://github.com/Marlamin/wow.export/blob/caf2bb0006930e151cd3810fba0f7d55e2e4b562/src/js/3D/exporters/M2Exporter.js)

wow.export 和 three.js 代码使用 MIT 许可，应保留对应许可声明；model-viewer 官方标注 Apache 2.0。工具代码许可与游戏模型素材的使用依据是两件事，应延续现有资源来源记录，不能将开源工具许可当成游戏素材许可。[wow.export 许可](https://raw.githubusercontent.com/Marlamin/wow.export/caf2bb0006930e151cd3810fba0f7d55e2e4b562/LICENSE)，[three.js 许可](https://raw.githubusercontent.com/mrdoob/three.js/dev/LICENSE)，[model-viewer 官网](https://modelviewer.dev/)

国服用户浏览标准 GLB 不需要国服英雄榜接口。主要访问风险在模型、运行库和可选解码器的网络来源：model-viewer 的 Draco/KTX2 默认解码资源来自 Google CDN；若采用这些压缩格式，应预先配置为可控的同源资源。现有 26 个 GLB 未声明这些扩展，不需要为了试点提前增加压缩解码链。[官方加载说明](https://modelviewer.dev/examples/loading/)

`server.js` 当前公开静态目录为 `assets/css/js`，MIME 表还没有 GLB/glTF 专项。实施时应在公开模型目录内发布经过检查的资源，补相应类型、缓存与版本策略；不可把 `scripts/decor/out` 整个目录开放。若将来另用对象存储，再验证跨域配置。首期可用模型清单文件承接已核验条目，不必仅为原型新增数据库表；完整数据管理方案留待具体实施设计。

## 建议的嵌入体验与验收门槛

在既有详情的媒体区域提供“图片 / 3D”切换。列表继续使用现有缩略图，用户进入详情并选择 3D 后才加载；一次只保留一个可见模型。区域内可拖动、缩放、恢复默认视角，显示简短操作提示；没有模型或加载失败时仍可看图片、来源和价格、加入方案单。该建议不新增独立网页或整屋编辑器。

后续如果运营安排进入实施，应一并验收以下内容：

1. **模型真实性**：普通桌椅、小摆件、植被透明材质、发光模型逐类检查完整旋转，明确哪些效果不支持；不能仅截图正面。
2. **交互与原链路**：实际拖动旋转、滚轮缩放、复位；关闭后回到原家具与筛选位置；来源、价格、方案单按钮仍可用。
3. **响应与负载**：在 1366/1920 桌面浏览器、普通显卡环境记录首开耗时与交互表现；慢网/失败可重试。现阶段无帧率或秒开承诺。
4. **生命周期**：快速切换家具、反复打开关闭、切换页面后不出现旧模型串位、后台持续渲染或 WebGL 资源增长。
5. **回退与输入**：WebGL 不可用、模型缺失时保留图鉴功能；提供按钮与键盘可用的基础操作，不只依赖鼠标；滚轮缩放不无故占用整个页面滚动。

实施前仍须按项目 UI 规范审计目标详情页，并评审运行库与资源发布方式。本轮没有修改页面、引入依赖、执行 SQL、部署资源、启动游戏或上传用户蓝图；只有只读研究与本文档交付。
