# 公会块功能与推进顺序

2026-11-25。公会招募卡保存已随现有公会档案任务 REQ-212 实现并完成隔离验证，待上线及运营验收。以下记录公会已有功能、待验事项和建议顺序。公会自定义权限的开发顺位待运营确定，个人档案等新版反馈。

## 一张招募卡怎样才算交付

会长从「公会档案 → 公会资料」进入，填好本团每周哪几晚活动、缺什么专精、如何联系招募负责人，保存后关闭页面。下次回到同一个公会，原来的时间和需求还在，只需改动变化的项目。团员打开同一入口能读到会长最近保存的内容。

上一轮正式页接入了已有的公会资料。会长能保存富文本介绍、装备分配制度、规则说明、认领方式及认领人显示设置。招募卡的新字段当时单列为交互评审，已经做好职业专精选项、排班、语音工具和赛季首领联动，但填写结果只在当前页面有效。两部分同属 #212，交接时遗漏了把“保存后其他人看得到”列作整体验收门槛。

| 资料 | 从哪里来 | 保存和阅读时的约定 |
| --- | --- | --- |
| 公会名、服务器、介绍、全公会分配制度 | 现有公会资料 | 在招募卡中引用。会长在档案改介绍后，卡上应读到新版。全公会制度只维护一次。 |
| 玩法与目标、职业及专精缺口、固定活动日与起止时间、语音、团队约定 | 会长在已评审的表单中选择 | 保存于当前公会的招募资料。固定排班只说明通常何时打团；实际出席仍取自当场考勤。 |
| 自报团本进度 | 会长选赛季、副本、难度和首领 | 标注「管理者自报」。有战报佐证时可追溯战报；自报不计入已核实击杀和成就。 |
| 微信、QQ、战网等联系方式 | 会长填写招募负责人的联络方式 | 现任公会成员可查看全部已填联络方式。将来由会长主动发布后，游客只看公开版，联系方式默认由双方私下交换，也可明确选为在公开卡展示。 |

**存储方式已确认。** 全站共用一张按公会关联的招募卡表。新公会初始没有卡，第一次保存才新增一条，以后修改同一条。修订号用于提醒两处编辑发生冲突，避免旧页面把新排班覆盖。招募卡引用公会介绍。读取时核实现任会籍，所有已填联络方式都可由本会团员查阅，游客和外会账号无权读取。产品只有一个档案入口，不需要会长管理第二套档案。

**本项验收**：会长首次填写并保存 → 刷新后回读 → 修改一个活动时段再保存 → 换团员账号核对新版、完整联络方式及只读状态 → 切到另一公会确认不会串卡。另查旧公会首次打开为空、取消或保存失败能保留应保留的内容、两处同时修改有提示。

## 按公会实际事务盘点

| 公会事务 | 现有功能与状态 | 与其他模块的关系 |
| --- | --- | --- |
| 建会与会籍 | 创建、邀请码入会、切换、退出、成员身份管理已有入口。现用会长、编辑、团员三级权限。 | 账号标识用户，公会会籍决定该用户在这家公会能做什么。同一个账号可以在两家公会担任不同身份。 |
| 公会资料与招募卡 | 基础资料页已上线。内部招募卡已接入同一资料页，完成会长保存与团员回读的隔离验证，待发布。 | 复用公会身份、介绍与分配制度。对外招人、双方私下交换联系方式及玩家求组属于后续 REQ-082。 |
| 成员、角色与认领 | 有成员名册、职业专精、角色认领与审核、主小号关联、离队与历史保留。按团员考勤的主线已验收。 | 个人管理「我的角色」，公会管理「哪几个角色算同一位团员」。同一人同场用两个角色只计一次出席。 |
| 活动、考勤与 WCL | 有活动与团号、名单、出席状态、取消活动、公会 WCL 绑定及日志同步。 | 排班说明约定，考勤记录实际出席，WCL 提供参战证据。战报引用具体活动。 |
| 心愿、拾取与装备分配 | 心愿单、拾取导入、核对后转分配、无人需求与批量处理均有实现。单件转分配主线已验；多人采集、晚捡、交易等按 #199 等新团本周期统一验。 | 心愿用来辅助分配；拾取人、交易对象和最终获得者分别保留。普通团员可交拾取，正式去向由有权者确认。 |
| 战报、录像、里程碑与成就 | #190 已提供公会战报入口、草稿、发布、撤回、首杀录像和人工核对的成就。真实公会活动的发布与撤回待运营验。 | 击杀对应具体 WCL 战斗；公开视频随战报发布。未来的「编辑录像」授权与发布权可分别配置。 |
| 仪表盘、统计与数据管理 | 仪表盘提供总览，统计报表读团队出勤等记录，数据管理有备份与导出。含团员关系或团员考勤的备份目前只支持导出留存。 | 统计复用考勤、成员等业务记录。站点访问量与游戏字典归平台数据中心，副本掉落等公共图鉴可供公会引用。 |

## 建议的交付顺序

| 顺序 | 工作 | 可以认定完成的结果 |
| --- | --- | --- |
| 1 · 待上线和验收 | #212 公会资料与内部招募卡 | 会长在同一档案填写、保存、重开，换团员账号可看到全部已填联系方式。 |
| 2 · 既有验收 | 收齐 #190 真实战报和 #199 团队收官证据 | 可在同一场活动观察多人拾取、晚捡、交易，活动后另核发布战报、录像和成就。具体场景没发生就留待补验，不阻塞可独立进行的公会工作。 |
| 3 · 建议先定边界 | 在公会阶段列清每个操作由谁执行，再决定自定义角色何时开发 | 确认编辑招募资料、提交拾取、确认分配、编辑录像和发布战报的授权界限。只涉及公会职务的部分可集中做；涉及个人联系方式、角色展示的部分等个人隐私方案。 |
| 4 · 等运营反馈 | 公会工作集中收口后再进入个人档案 | 沿用个人已有的账号和角色归属，按新版工单确定展示与隐私范围。 |

第 3 项是对原先“个人展示与隐私之后开发自定义角色”的调整建议，目前只明确归属和依赖。本轮已批准的开发项只有第 1 项。固定团双向招募、WCL 全赛季自动进度、公会荣誉图片审核各有独立条件，保留原状态。
