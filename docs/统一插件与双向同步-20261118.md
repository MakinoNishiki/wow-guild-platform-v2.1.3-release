## 玩家在同一个面板里做什么

| 场景 | 游戏内操作与结果 | 网站和桌面端的作用 |
|---|---|---|
| 家宅作者 | 网站登录后署名，填写作品名、粘贴游戏原生码，设置代码可见性即可发布。愿意提供明细时，选中对应版本的图纸，核对家具数量后附到作品 | 作品可先发后补清单。仅展示也可附清单，公开数据只提供分类、家具和用量。附单须对应这份布局，不拿整个账号的收藏或当前另一套住房代替 |
| 照着作品装修 | 面板打开已带入的作品，看需要、可用、还差多少。比如需 12 丛草、可用 5 丛，显示缺 7 丛。悬浮可查地点、商人、条件和各途径的参考价，点一下追踪 | 在站内复制公开蓝图或主动加入追踪，可由本人关联的桌面端带入游戏。复制记录与主动追踪分开，公开作品不暴露读者的历史和库存。未知库存显示“待核实”，已摆放、可兑换单列；未附清单时只展示作品与代码公开状态 |
| 家具收藏 | 想看整体进度时按家具种类看已收集/未收集，想补一套装修时按件数看缺件。游戏发出家具数据变化后刷新，重新打开面板可校对。收藏率须先确定分母及版本 | 图鉴已有获取资料。个人进度只展示本人选择同步的资料和采集时间。3D 网页拖拽仍按 REQ-205 单列 |
| 个人档案 | 看当前角色穿戴装等和大秘境总分，换装后读取最新游戏数据。游戏内查询自己的当前角色可独立使用 | 桌面端按角色和采集时间汇总各次档案。国服已核实第二角色这两项数值，团本周锁定与赛季累计进度仍需分别验证 |
| 团前点名 | 选择本场活动，读当前团队名单，按公会确认的角色关联匹配团员。团员换小号仍只记一次出席。未匹配留待核对，缺席、请假、迟到和替补由有权者确认 | 提前载入本公会活动、关联关系、已确认的历史出勤摘要。低出勤提醒仅供有权组织者参考，标明时间范围、出勤场数/应到场数、数据截至时间；无样本显示“暂无记录”。沿用站内同一统计口径，阈值与周期待排期确定 |
| 活动中的装备 | 沿用拾取、延迟拾取和交易证据。团长可先登记待分配，再确认最终获得者或无人需求。游戏面板可按日期回看已带入的历史和本场待同步记录 | 公会成员可提交观察。有管理权限者确认考勤和最终分配，服务器在接收时复核权限。多人记录同一掉落时沿用现有匹配，保留各来源，分别记录拾取人和最终获得者 |

统一入口拟用“魔兽管家”面板和斜杠命令，国服中文命令与现有插件共存须实测。当前家宅目录采集用 `/wbd`，团本拾取用 `/wbc`，主数据导出用 `/wjdc`。个人档案的 `/wbprofile` 是研究工具。整合时保留原入口和已存记录，复用网站既有 WCL 考勤，不把主数据导出当作新的考勤来源。

## 两端何时看见同一条记录

1. **当场可见。** 名单、装备或家具变化，插件在当前游戏版本允许读取这些数据时更新本地面板。游戏内点追踪、点赞或确认分配可先留下本地记录，并显示“待同步”。动作有唯一编号，点赞、取消追踪等记录目标状态。
2. **网站到游戏。** 登录桌面端，按已选账号、公会下载允许带入的蓝图、清单和历史记录，显示更新时间。建议使用预先安装的只读数据文件，与游戏保存待传操作的文件分开。文件准备好后，进入角色或重载界面再读取。国服尚未验证本站下行，不能承诺已经开着的面板会马上收到网站消息。已复制的公开码无法收回，后续同步须重新检查作品可见性。
3. **游戏到网站。** 一场活动可连续记录，期间无需每个首领后重载。游戏把数据保存到本地后，已登录的桌面端可读取并提交。服务端根据当前身份、权限和记录版本给出成功或冲突回执。桌面端可立即显示回执，游戏在下次载入回执时更新。断网后保留队列，同一记录重试不多算；两端同时编辑考勤或分配须提示核对。
4. **首次使用与换号。** 网站账户与游戏资料明确配对，只带所需显示名、作品和有权查看的公会数据。桌面端持有登录态，插件仅展示当前范围。换账号或公会时隔离旧快照及待传动作。即使桌面端未运行，游戏内本场记录仍可继续，保留最近同步时间。

## 可行性依据与真机验收

- Housing Codex 作者已展示游戏内已收集/未收集筛选、收藏进度、获取途径、地图商人和内嵌 3D 预览。WoWDB 的 Dump Decor 可导出拥有与摆放数据，其网站要求粘贴导出串或上传文件。两者支持不同环节的可行性。[Housing Codex 作者说明](https://github.com/Daeveren/HousingCodexLive) · [WoWDB 导入说明](https://housing.wowdb.com/tools/decor-sync/)
- 外部更新在重载后进入游戏有成熟先例。本站国服实测已观察到重载、返回选角、正常退出后能读出更新的插件文件。这些是上行取数证据，网站回传至国服游戏面板仍待测试。[WeakAuras Companion 作者说明](https://github.com/WeakAuras/WeakAuras-Companion/blob/main/README.md) · [国服档案记录](REQ-093-国服个人档案真机验证-20261116.md)
- 家宅正式验收应使用两个账号。作者仅凭蓝图发布，再补清单并切换代码可见性。浏览者在无库存、已有部分家具、数据过期三种情况下核对所需数量及来源。用同一家具做一次真实获得与摆放，分别核实库存、已收集种类和缺件变化。[国服图纸及清单记录](REQ-203-原生蓝图真机核对-20261118.md)
- 团队正式验收应在同一场活动中覆盖小号换人、晚进组待核、多人观察同件、代拿后交易、无人需求。对照游戏即时显示及网站最终记录，核实一人一次出席、每次分配一次，并验证同步前撤销管理权限、断线重试和并发修改。
- 双向验收需记录网站修改时刻、桌面收到时刻、游戏可见时刻，以及反向操作的服务端回执。仅在本地显示成功或仅验证文件更新都不算跨端通过。本轮交付为开发规范与范围更新，未发布插件、客户端或线上功能。
