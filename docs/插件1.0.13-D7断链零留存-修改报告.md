## 一、诊断确认（顾问诊断正确，照单采纳）

`WJDCDump = dump` 只在 `doExport` 终局（全段落跑完）执行一次；链死/中途中断时内存中 `WJDCDump` 仍是登录时从 SavedVariables 读入的上跑旧表，/reload 写盘即旧数据原样写回——整跑采集全丢。D7 建议的两条路（按段提交 / 断链哨兵触发落盘）取**按段提交（segment-commit）**：覆盖一切中断形态（含异步链死这种哨兵也未必能在场的形态），且实现最小。

## 二、改动点（仅 `WoWButlerExporter.lua` 一处逻辑改动，1.0.12→1.0.13）

1. **`exportInstances` 加第 7 参 `onProgress`**：实例收尾分支（`nextBoss` 内 `not b` 处）追加 `if onProgress then pcall(onProgress, out) end`——每实例跑完即回调；`out` 为活表，后续实例追加原地生效。pcall 包裹：落表回调自身抛错不炸采集链。
2. **`doExport` 新增 `commitPartial()`**：置 `dump.meta.partial = true` 并 `WJDCDump = dump`；两段的 `seg.run` 各挂 onProgress（团本写 `dump.raids`、大米写 `dump.dungeons` 后 commitPartial）。
3. **终局提交清标记**：全段落跑完 `dump.meta.partial = anyAborted and true or nil` 后 `WJDCDump = dump`——完整跑无 partial 键（nil 不落盘），段级 pcall 中断过的跑保留 `partial = true`（新增 `anyAborted` 跟踪，段中断红字处置位同步置位）。
4. **`WJDCLastCounts` 口径不变**：仍只在完整跑终局覆写——断链跑不污染计数对比基线（REQ-119② 语义守恒）。

行为效果：链死/中途中断后 /reload，存档文件含**已扫完全部实例**的数据 + `meta.partial = true` 断链标记；中断产物可直接发顾问侧（已扫段落可用），标记供顾问侧识别非完整跑。
