## 二、A 部分——写入链路补 id（治未来）

`lootSave()` payload 新增 `character_id`：分配人下拉值为成员名，按**当前公会活跃成员**（status!=='离队'）解析 id——活跃成员公会内名字唯一（REQ-002 partial 唯一索引），解析无歧义，且不会误绑同名离队行。解析不到（自定义名/未选分配人）：编辑态保留 `oldLoot.character_id` 不丢、新建写 null，均不阻断保存。分配人选择 UI 流程零变化（option value 仍为名字），用户无感。编辑既有分配保存时同链路透传补 id。

## 三、解析改造——id 优先 + B 回退（渲染层）

- `character_id` 非空：按 id 在成员表（含离队）精确定位——在队职业色 chip、离队「（已离队）」；id 定位不到（已彻底删除）→「（已删除）」。同名零碰撞。
- id 为空（存量 4 行）：名字匹配成员表**放行离队命中**（唯一改动点 = 去掉 `status!=='离队'` 过滤）→ 按真实状态显示；未命中 → 垃圾桶名单 →「（已删除）」；再未命中 →「（已离队）」（沿用现兜底）。
- 已知限制（运营在案不追求两全）：同名一删一留的存量 NULL 行，显示方向以在册成员为准。
