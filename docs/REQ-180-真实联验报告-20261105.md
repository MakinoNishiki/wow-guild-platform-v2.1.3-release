## 环境与证据边界

- 使用 REQ-181 的独立数据库、登录、REST API、密钥及数据卷。生产 Supabase 没有写入测试记录。
- 原生产服务端代理固定使用 HTTPS；测试启动器在本机创建临时 TLS 转发入口（只监听回环地址），通过 SSH 隧道连接测试 API。没有修改产品代理逻辑，也没有关闭 Node 对 WCL 的证书校验。
- 浏览器运行实际产品 index.html、app.js、cloud.js；没有替换 CloudSync、cloudCrud、数据库返回或 WCL 报告内容。页面保存经过实际 server.js 鉴权代理；使用独立查询回读真实测试库，而非只看 toast/appData。
- WCL 使用现有应用的只读公开报告接口，应用凭据经已授权 SSH 的受限管道仅进入测试进程内存；未复制生产 Supabase 密钥，未将凭据、token 或浏览器登录状态写入仓库。临时配置导出程序已移除。
- 两份真实报告分别为 `7wYFJH9RyxzBnVXv`、`9NJKk27xDAv3wBrb`。第一份实读 20 个角色、9 场首领战；候选核对另读 `JB6KtbLjGfPgnT4a`。
- 临时测试账号、公会为虚构；为核验 WCL 同名匹配，临时从公开报告选取 3 个角色导入测试名单，完成后删除。没有复制生产用户账号或生产业务记录。
- **仅失败场景使用明确注入的 HTTP 502**：补链 PATCH 失败、同步第二条考勤写入失败、更换报告快照 PATCH 失败。其余请求真实执行，失败前已写入的第一条记录也真实存在于测试库。不能将此称为真实 WCL 故障演练或数据库事务回滚测试。

## 页面与操作实测

| 页面/入口 | 真实动作 | 数据库及界面结果 |
|---|---|---|
| 登录入口 | 使用临时账号点击登录 | 加载测试公会及编辑权限 |
| 成员管理－智能导入 | 默认 WCL → 粘贴真实报告 → 读取 → 勾选3人 → 确认导入 | 预览阶段零写；确认后3角色落库，无自动认领、无活动生成 |
| 考勤记录－创建活动 | 填团本名、保存 | 创建1活动及3条缺席占位记录 |

| 战斗日志－预览并同步 | 读取真实报告，确认时让第二条写失败，再重试 | 第1条已写入，第2条未写；预览保留；重试后无重复，人工迟到保留 |

| 更换预览－确认 | 首次快照保存故障注入，再重试 | 失败保留预览/旧链接；重试后新链接落库，旧快照进入history，考勤逐行守恒 |
| 刷新页面 | 重新加载真实数据库 | 新链接和人工迟到状态一致 |

## 本轮修正及回归

更换报告失败后，确认按钮原先在 finally 无条件恢复成「确认写入考勤」。现按当前操作恢复「确认更换并保留已有考勤」，避免重试时文案与操作不符；审计记录在 `design-plans/req180-team-workflow.md`。资源串同步到 `.127`，更新日志追加说明。未改职业色、图标或页面布局。

新增 `scripts/run-isolated-req180.cjs`、`scripts/verify-req180-real.cjs`：强制检查测试环境标记、回环地址与测试 service JWT issuer；不默认读仓库 `.env`；运行时复制入口及服务端到不含 `.env` 的临时目录。配置仅通过受保护 stdin 管道输入，不可将配置 JSON 输出到聊天/日志或存进仓库。运行前需启动测试栈及带保活参数的 SSH 隧道；测试结束删除临时账号、公会与浏览器会话。

试跑中修正了验证脚本的登录入口定位、空态重复按钮定位及请求等待方式；最终查找报告断言等待具体 HTTP 响应和完成状态，避免把前一次状态作为后一次结果。以上均为测试脚本修正，不作为产品 BUG 宣传。

源码复核：后台自动建活动调度与端点已移除；元数据编辑不携带 attendees；同步仍走原批处理写入入口及 cloudCrud 快照更新；公会切换、取消活动、重复报告和人工未保存状态守卫保留。JS语法及diff检查通过。
