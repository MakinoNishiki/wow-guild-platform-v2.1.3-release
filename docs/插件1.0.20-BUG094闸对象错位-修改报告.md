## 一、根因与差分说明（顾问必答：1.0.17 raw 钉 17 成功 → 1.0.18 闸后失败，差在哪一环）

**差分锁定在「判定对象」一环——闸引入了对实例选中态的隐式依赖，而该状态从不复位、无读回。**

| 环节 | 1.0.17（raw 钉档） | 1.0.18/1.0.19（闸后钉档） |
|---|---|---|
| 钉档前校验 | 无——`pcall(EJ_SetDifficulty, 17)` 直接发 | `EJ_IsValidInstanceDifficulty(17)` 先判 |
| 判定的依赖对象 | `EJ_SetDifficulty`/`EJ_GetDifficulty` 是**全局难度档**的写+回显，与当前选中哪个实例无关——选中态错了照钉照过 | `EJ_IsValidInstanceDifficulty` 以**当前选中实例**为判定对象（暴雪 :768 用法语境=UI 已选中实例后）；选中对象错则判定对象错 |
| 选中态保障 | 阶段二 `pcall(EJ_SelectInstance)` 无读回——但 raw 链路对此不敏感（见上行），属隐性幸运 | 同无读回——但闸对此**致命敏感**：1.0.19 冒烟鲁阿夏尔判 IsValid(17)=false（判定对象非至暗之夜），钉档被跳过 |
| 失败形态 | 无（8/8 全带档） | RAID_TIERS 首档 lfr/17 闸否 → 视同读回不符走 switchFail → `finish()` 终止余档 → **0/8 带档**；且闸否原实现**静默**（不发 SetDifficulty、不留任何日志），红字只说「读回失败」不说「闸判否」 |
| 件数为何不受牵连 | — | 1.0.19 显式枚举 `GetLootInfoByIndex(li, bossIndex)` 不依赖选中态做归因——**件数全对、档值全丢**，现形特征与「闸判错对象」精确互证 |

一句话：1.0.17 的钉档通道是「全局写+回显」，对选中态脱敏；1.0.18 的闸是「实例态判定+条件写」，把从未受控的实例选中态变成了关键路径依赖——**闸本身方向正确（防硬钉空档），缺的是判定对象的选中保障**。1.0.20 把该依赖收编：判前先保证选中成立，判否必留痕。

**残留不确定点（如实申报）**：`EJ_IsValidInstanceDifficulty` 的判定对象语义为 C 侧行为，FrameXML 不可直证（:768 用法语境+现形特征互证为间接证据链）；无参 `EJ_GetInstanceInfo()` 第 1 返回值=当前选中实例名为 wiki 明载。若三要素红字显示「当前实例=至暗之夜 且 IsValid=false」，则嫌疑翻转为「该 API 对 12.x 新本 lfr 档判定口径变化」——取证件已埋好，一跑定案。
