# 家宅社区入住信息：可行性调研

## 2026-11-21 国服复核

本轮已获运营确认进行数据核查。从本机国服正式服 12.1.5.70961 安装文件直接读取原生找房界面及接口声明。找房器请求所选社区，响应包含社区标识、地图和地块列表。地块有编号、位置、所有者类型（无、陌生人、好友、自己），价格和所有者名可能为空。社区居民列表与地块列表各有用途，不能用居民人数代替已占地块数。[对应版本的原生找房界面](https://github.com/Gethe/wow-ui-source/blob/ab5cb850a3f65e742959e379c4689353a2f4549f/Interface/AddOns/Blizzard_HousingHouseFinder/Blizzard_HousingHouseFinder.lua)

在游戏里，有回包时可按返回的地块列表统计有主、无主以及总地块数。是否可购买需要在地块基石处查询，还可能涉及预留和搬离。联盟、部落地图可以分别展示为创始者之角、烈风海岸。本轮未在登录状态取一组社区回包，未验证任何具体社区的实时空地数。[国服家宅地图说明](https://wow.blizzard.cn/news/24221516/index.html)

重新核对暴雪官方文档，三个社区网页查询与角色住宅查询均标为 `cnRegion:false`。现有依据支持游戏内查看返回的社区，尚无可供网站定时刷新国服全社区空地的已验证入口。[社区接口](https://community.developer.battle.net/api/pages/content/documentation/world-of-warcraft/game-data-apis.json) · [角色住宅接口](https://community.developer.battle.net/api/pages/content/documentation/world-of-warcraft/profile-apis.json)

以下为首次调研记录。

## 当前结论

有两类已核实的数据入口：暴雪公开宣布过家宅网页API；客户端自带界面也有社区和地块查询接口。因而“社区资料与入住分布”有技术依据，不能笼统说没有接口或必须安装插件。

但是，官方参考文档中这三个社区方法均标记`cnRegion:false`，不能按已支持国服来规划。本次没有取得国服网页接口的成功响应，也没有游戏真机样本；**目前不能承诺国服全社区自动枚举、完整入住数或实时刷新**。已公布接口、当前服务可用、国服可接入、返回字段足够，是四项不同的验证。

## 一手来源与证据边界

### 官方网页接口公告

暴雪开发者在2025-12-19的[New Housing APIs!](https://us.forums.blizzard.com/en/blizzard/t/new-housing-apis/56815)首帖宣布正式服家宅接口，包括：

- 社区地图索引：`/data/wow/neighborhood-map/index`
- 指定社区地图：`/data/wow/neighborhood-map/{neighborhoodMapId}`
- 指定社区：`/data/wow/neighborhood-map/{neighborhoodMapId}/neighborhood/{neighborhoodId}`
- 角色住宅：`/profile/wow/character/{realmSlug}/{characterName}/house/{houseId}`

上述公告证明存在公开网页接口的发布依据；本轮实际读取首帖。它没有承诺本项目可使用国服服务，也没有明确全量社区发现、入住统计字段和刷新频率。不能把“地图索引”直接当“全部社区实例索引”。

[当前开发者参考入口](https://community.developer.battle.net/documentation/world-of-warcraft/game-data-apis)为动态页面。随后成功读取其[官方文档JSON](https://community.developer.battle.net/api/pages/content/documentation/world-of-warcraft/game-data-apis.json)，确认Neighborhood API下三个GET方法、地图/社区ID参数，以及全部方法的`cnRegion:false`和默认命名空间`dynamic-us`。本次只取公开文档，未使用凭据请求业务数据。

文档JSON没有这些接口的响应结构，不能把客户端的地块字段直接当作网页返回字段。[官方地区说明](https://community.developer.battle.net/documentation/guides/regionality-and-apis)将中国与其他地区划为不同分区；即使国际服测试成功，也不证明国服数据可读。`cnRegion:false`说明不能按公开文档已支持国服来承诺；不将其夸大为不存在任何国服合作接口。

同帖普通用户关于角色住宅接口停用的评论未获官方状态核实，不作为本报告确定结论。也不把角色住宅端点的状态套用到社区端点。

以下为客户端原始文件的Gethe镜像，固定提交`297d7aaaa736f346b3e036f38ee088eaf7f8c07f`；它不是暴雪网页服务文档，也不等同已核对国服安装版本：

## 可以继续验证的能力

| 用户想看什么 | 已有依据 | 尚缺验证 |
|---|---|---|
| 社区名称与地图 | 客户端有社区GUID、名称、位置名和地图ID；网页有地图/社区端点 | 国服成功响应，地图中文名与联盟/部落地图对应关系 |
| 入住数与总地块数 | 客户端地块列表含占用类型，可作为统计原料 | 列表是否完整；网页是否返回同等数据；预约/搬出等状态如何表示 |
| 每块地的位置与房屋信息 | 客户端有plotID与二维位置，部分房屋字段可空 | 地块和房屋实体区分；地图坐标范围；未加载/权限受限场景 |
| 定时更新已知社区 | 若国服网页端点可用，可由服务器按配额调度 | 认证资格、地区、返回缓存时间、限流和错误重试 |
| 全服所有社区持续更新 | 官方公告中没有已核实的全量枚举承诺 | 社区发现方式、覆盖范围、分页/请求预算及国服接入；目前不承诺 |

“入住20/50”只能在确认本次快照完整后显示。数字50来自用户举例，不写死为实际容量。缺数据用“尚未取得/数据不完整”，不填0；无拥有者不自动代表可购买，还需区分预留、权限及其他游戏条件。

社区身份应优先采用经验证的地区、地图和社区稳定标识。不能只用服务器名称加社区名称作唯一键，也不能未经验证把客户端GUID与网页端neighborhoodId当成相同编码。地图主题、角色阵营和访问/购买权限分开记录。

## 更新方式的选择顺序

1. **先确认国服官方渠道是否开放。** 现有国际开发者文档标记不支持中国区，当前不能作为可直接落地的国服数据源。若后续国服渠道得到确认且字段足够，网站后台可定期更新已知社区；用户浏览不需要插件，也不要求游戏一直开着。具体刷新间隔等实际服务配额与更新速度明确后再定，不先承诺每分钟实时。
2. **游戏内采集只作为条件备选。** 若网页接口国服不可用，客户端可见数据或许能形成社区快照；但还需解决从游戏到网站的传输。插件内收到事件不等于网站收到数据，浏览器刷新也不会自动读取游戏内存。是否接受这一流程要由运营决定，不默认为本期发布门槛。
3. **有新观察才更新状态。** 若采用快照，展示最后采集时间、来源与完整性；定时刷新页面只能读取已有记录，不能把旧快照标作实时。长期无人采集时明确显示过期。

后续展示可结合已公开的装修作品和作者自愿公开的到访地址。社区统计、在线人数、网站作品数分别计算，不把“入住多”直接当“装修热门”，也不默认公开采集到的全部居民姓名或住宅内部布局。

## 后续最小验证（未执行）

先核国服官方服务的可用入口、开发者资格与真实响应；不要求用户现在登录游戏。网页路线不足时，再由运营选择进入一个已知社区或原生“寻找家宅”，核对同一社区名称、地图、地块总数与占用数，并记录游戏版本和采集时间。仅查看，不购买、不搬家、不修改社区。对比两次实际变化之后，才判断更新延迟和计数口径。

研究结果仍需运营决定是否排期；REQ-203的原生蓝图样本验证继续，不等待该候选立项。
