# 任务书 #214 · 公会招募多选与成员权限

## 交互评审

打开[离线招募卡样例](../design-plans/req214-guild-review/index.html)，可以看到战士、武僧、德鲁伊的三档需求。点「会长填写」，在同一条战士需求里勾选坦克、输出和对应专精，再点「招募卡预览」。离线样例刷新后重置。

公会大厅依次显示「公会资料 → 成员权限 → 公会战报」。点击中间的国王棋子可查看成员身份，会长可以继续点击「管理角色与权限」或成员行的「分配角色」。[实际侧栏与权限页面](evidence/req214-20261125/roles/permissions-entry.png)

## 设计与数据

| 运营截图中的问题 | 改动与取舍 |
| --- | --- |
| 一条战士需求原先只能填写一个专精，同一缺口要用多行表达 | 一条按职业、需求度组织，职责与专精均可多选。按职责缩小专精范围，取消一种职责只清除属于它的选择。仅选择专精时，阅读版自动推导职责。同一职业若各专精的紧迫程度不同，仍可分行设置。 |
| 高、中需求原先使用相同的文字颜色 | 高为暖红三格、中为金黄两格、低为蓝灰一格。编辑器与阅读卡片均保留文字和图形提示。[三档并排对照](evidence/req214-20261125/priority-levels.png) |
| 成员权限在长篇简介与招募卡下方，截图中需滚动到页底 | 将同一个权限面板移入公会大厅独立页面。左侧采用现有 20px 暗铁金边国王棋子。「成员权限」管理账号身份，「团队管理 → 成员管理」维护游戏角色名册。 |

招募卡使用原有存储。单选继续使用旧格式，多选记录职责和专精列表，原卡可继续打开、编辑和保存。本次无需 SQL。

### 本轮看稿调整

- 操作截图中，收起的需求度菜单会截断「高」或「中」，打开后各档又跟随当前档颜色。编辑器与招募卡现在共用窄幅刻度，菜单中的每一档使用自己的颜色，并为文字和箭头分别留出空间。
- 新选的职责在该职业下只有一个专精时自动带上。先选战士再选坦克会勾选防护；先选治疗再选武僧会勾选织雾。战士输出有两个专精，保留手选。撤掉一个职责会清掉对应专精，保留其他职责的选择。旧卡从原数据回读，打开时不会被补写。
- 根据箭头标注，将原第三项「成员权限」上移至第二项，「公会战报」顺延至第三项。两个入口使用原有图标、地址和授权。
