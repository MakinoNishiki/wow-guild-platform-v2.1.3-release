# REQ-191 多人提交拾取：交付与验收

2026-11-13；代码基线5fe21f1，资源候选20261113.136，Collector仓库候选1.0.5。状态：本块实现与自测完成，待运营验收；未提交、未推送、未部署。

## 用户能看到的变化

1. 同公会所有成员都能在「装备分配 → 拾取记录 → 导入拾取」提交。可选择已有活动；没选或信息不足，保留待核对。
2. 同来源重传不重复新增。不同采集者提交同次拾取，关键证据完整且只有一个匹配候选时归并，列表显示来源数；同人同物品真实多件、身份或难度不同不强行合并。
3. 会长和管理员可以核对拾取事实、手动合并重复、更正所属活动、忽略误录。忽略默认隐藏，勾选「显示已忽略」可查看；证据仍保留，识别为同一事件的再次上传不会恢复误录。
4. 普通成员只能提交，不能因此获得核对或装备分配权。这里的「确认拾取」不代表确认最终获得者。

## 数据与匹配边界

SQL45新增观察来源表，扩展现有拾取状态，给现有分配表添加唯一来源关联约束。原始采集证据保留于payload；同来源ID/事件ID若内容不一致报冲突，不覆盖。服务端用登录人身份与当前公会成员资格，数据库事务再次核对并串行处理并发。

自动归并要求同公会/活动、角色服务器/区域、首领场次、副本难度、物品ID/完整链接/装等、单件数量吻合，时间差在2秒内、唯一候选且同来源没有另一条事件。逐字完整链接采用保守策略；不能保证不同客户端的所有合法文本格式都会自动合并。匹配是辅助，不证明来源真实；疑似多件保留待核对，管理者确认。

旧数据保留legacy状态，不自动批量修改装等或猜测服务器。旧来源不足时无法保证与后来的完整记录自动匹配，仍需人工核对。新建数量大于1的观察保留待核对，不直接转分配。

## 运营验收项

| 操作 | 预期 |
|---|---|
| 普通成员打开拾取列表并提交 | 有导入入口；无核对/分配管理权 |
| 同一份记录再次提交 | 提示重复，列表不翻倍 |
| 两个采集者上传同活动同次拾取 | 证据完整时一条记录多个来源；不完整时待核对 |
| 管理者核对并忽略误录 | 默认隐藏；显示已忽略可查；同事件重传不恢复 |
| 管理者选错活动后更正 | 改到正确活动，回到待核对；刷新一致 |
| 同人同物品确有两件 | 不因时间接近丢件；歧义留待核对 |
