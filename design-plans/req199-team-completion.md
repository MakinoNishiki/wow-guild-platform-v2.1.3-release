# REQ-199 团队收官 UI 审计与实现基线

引用《开发规范》《UI工作方法-证据规范实现验收》《DESIGN.md》。用户已授权整包实现和统一验收。审计阶段使用 improve-ui，后续实现沿用 better-ui 与项目组件。

## Design language
保持现有暗色表格、金色主要操作、原生表单和模态框。复用 toolbar、data-table、form-input、btn 与错误提示；不新增动画或框架。桌面优先/移动端封存属于 UI 规范 §8/§9 已知取舍。

## Findings
|问题|证据|改法|范围|置信度|
|---|---|---|---|---|
|导入预览只显示拾取行，没有清单差异信息|app.js lootDropImportRenderPreview 源码已核查|预览前增加观察清单核对，未知明确说明；差异不阻止有效行提交|导入弹窗|高|
|多件装备逐一开窗重复操作|lootDropsRenderTable / lootAllocationOpen 仅单件入口，源码已核查|当前筛选多选、批量核对、逐件选择去向后统一保存，失败逐行保留|拾取表及新批量弹窗|高|
|最终获得者无交易证据可参考|lootAllocationOpen 只展示拾取来源，源码已核查|表单展示成功/取消/未知交易及双方；不自动选择获得者|分配弹窗|高|

## Improve first
先完成证据口径与保存，再接预览及批量表单。批量弹窗宽度 min(1120px, calc(100vw - 32px))，独立正文滚动；每行保留装备、状态、获得者、首领和结果，共用活动/方式；获取者默认空。错误就地呈现，保存中禁编辑和关闭，成功项锁定，失败项可重试。未保存关闭确认；切公会中止提交。

验收：1366/1920 几何、键盘焦点、按钮 hover/active、空态/加载/异常/部分成功/刷新；实际隔离数据库 CRUD 与权限核对，不以模拟游戏事件代替真机。
