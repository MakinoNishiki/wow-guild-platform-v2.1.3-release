# 公会角色与权限评审

REQ-191 本机交互稿。三个默认身份为创建者（会长）、管理者（公会编辑）和普通用户（团员）。创建者还可以按公会分工增加角色。所有账号和游戏角色都是示例，配置保存在当前浏览器。[打开权限配置](index.html) · [直接查看成员徽记](index.html#members)

## 最短评审路径

1. 「权限配置 → 角色管理 → 创建角色」，输入「考勤员」，选一个棋子，点「创建并配置权限」。默认棋子为车。
2. 左侧点「角色与考勤」，开启「维护活动和考勤」。点「分配给成员」，保留示例账号「山间来客」，点「保存分配」。
3. 名册自动打开。看「公会身份」列。山脊和晨露都应在「考勤员」前显示选中的棋子，刷新仍可见。会长前是王，公会编辑前是马，团员前是兵。自建角色可选王、后、车、象、马、兵，选图只改变徽记。[名册实景](role-badges-20px.png) · [运营提供的六种棋子名称](chess-piece-reference.png)

本稿有 21 项操作，其中 17 项业务授权可以独立切换。新角色的这 17 项初始全关，由创建者按工作需要开启。另有 4 项固定规则：只有创建者可配置角色和分派成员，本会成员可读内部卡，已发布战报按公开状态可读。创建者本人不参与分配。其他身份均可在「模拟操作身份」体验只读配置。已有评审配置保留角色名、授权和账号分配。旧稿中保存的纹章和军阶样式会切换为棋子。

「重点对照」保留上次评审默认值：公会编辑可编辑内部招募卡，禁止绑定或解绑公会 WCL。线上现有规则见下表。「编辑名称与徽记」可同时更新权限表和名册中的称呼，并为自建角色更换棋子；「恢复默认配置」须二次确认，会清除本机新增角色并恢复示例账号分配。后续若实施正式授权，可沿用公会、账号、认领关系及历史业务记录，将相应权限接入业务入口和服务端；本机演示数据只供评审。

## 审计与规则依据

改稿前已从现有权限页和示例名册核对以下差异。视觉语言保留暗铁底、金色选中态、图文徽记与既有角色筛选；桌面优先属于《魔兽管家 UI 设计规范 v2》§8 已知取舍。代码入口见[评审页面](index.html)、[权限和名册渲染](preview.js)、[页面样式](style.css)。

| 已测量的问题 | 依据 | 本次处理 |
| --- | --- | --- |
| 角色管理只有改名与恢复，表头与对照按钮固定写「三种」。 | 原稿的角色工具、对照表和模拟身份列表均只读三个固定身份；台账已排期创建「考勤员」。 | 增加创建者可见的创建入口，创建后直接查看自己的权限列并分配给成员。 |

| 用户回到成员名册仍可能看到纹章或军阶。 | 旧稿从浏览器回读整页样式，角色筛选只显示文字。 | 按身份绑定棋形，表格身份列、角色筛选和权限表头均在名称前显示同一枚棋子。 |

## 本地浏览器验证

Chrome 158.0.8127.37，1366 × 768 和 1920 × 1080。通过「创建角色 → 考勤员 → 创建并配置权限 → 维护活动和考勤 → 分配给成员 → 山间来客 → 保存分配」点验。刷新名册后，山脊、晨露均显示 20 像素棋车和「考勤员」，未认领的林间微光显示空位；回权限表查看「查找新的 WCL 报告」仍为禁止。管理者、团员和自建角色均看不到创建与分配入口，权限开关禁用。重复、空白、17 字名称均被拦截，取消放弃可继续编辑。复验也覆盖旧配置回读、恢复默认分配、单独开录像并保持发布权限、六种棋形、旧款式迁移和角色名改名联动。在「编辑名称与徽记」中把考勤员改用王后，保存并刷新后，同一账号认领的两个角色都显示王后，考勤授权仍开启。[浏览器复验](verify.cjs)
