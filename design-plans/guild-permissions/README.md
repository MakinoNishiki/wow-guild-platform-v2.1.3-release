# 公会角色与权限评审

REQ-191 的本地交互评审稿。打开[权限配置](index.html)或[成员管理预览](index.html#members)即可使用。默认身份是创建者（会长）、管理者（公会编辑）、普通用户（团员）。设置存于本浏览器，本稿仅使用示例角色与账号。

## 评审路径

1. 先看「重点对照」前两行。公会编辑默认能编辑内部招募卡，不能绑定或解绑公会 WCL。当前线上两项仍分别为“仅会长可编辑”和“会长与公会编辑可绑定”。点行名可展开说明。
2. 在「团员」列开启「编辑单次击杀录像」，核对同列「发布战报」仍为禁止。顶端「模拟操作身份」切换操作人，表格上方的角色筛选只改变查看范围。管理者和普通用户可看配置，仅创建者可改。
3. 从「编辑角色名称」将公会编辑改为「副团长」。到「成员管理预览」可看到示例账号的新称呼和「管理者」基础身份。重复名、全空白和超过 16 个字符会被提示。可刷新回读，或由创建者恢复默认配置。
4. 在成员管理切换「公会纹章／远征军阶」，看 20 像素徽记在真实字号旁的效果。同一账号的两个游戏角色显示同一身份，未认领角色显示空位。此开关用于比较美术方案。[名册徽记并排对照](role-badges-20px.png)

本稿包含 21 项：17 项业务操作可以按角色开关；角色配置与基础身份分派保留给创建者，内部卡按会籍可读，已发布战报按公开状态可读。日志来源绑定与查找新报告相互独立；编辑录像、发布战报、撤回战报也分别处理。线上实施时需要将正式业务入口、服务端和数据访问权限一起接入，沿用原公会和账号的会籍关系。

## 审计与规则依据

正式资料页的「成员权限」逐人展示当前身份。上一稿已能对照操作，但角色名写死、授权列只给结论，名册里也看不到对应徽记。本轮在同一对照表加入独立开关，沿用暗铁底、金色选中态和公会横幅；两套徽记均为本地原创，搭配文字和可辨认的轮廓。桌面优先沿用《魔兽管家 UI 设计规范 v2》§8。[正式页面](../../index.html) · [名册渲染](../../js/app.js)

以下是本轮改稿前核对的正式规则，供对照新稿。

| 范围 | 核对结果与代码位置 |
| --- | --- |
