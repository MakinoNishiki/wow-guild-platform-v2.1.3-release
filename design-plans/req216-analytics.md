# REQ-216 访问统计的事件与来源

入口为公会档案 → 数据中心 → 访问统计。对照运营截图、`DESIGN.md`、现有统计卡片及数据库查询，确认两处问题。

| 位置 | 已核对的现状 | 本次调整 |
| --- | --- | --- |
| 事件排行 | 行名直接显示采集标识。页面已有中文的导航排行，同一次浏览在两处的表述不一致。 | 按采集动作显示中文名称，保留原始标识供核对。 |
| 来源域 TOP10 | 柱条展示查询区间的 PV 和 UV，顶部粒度只影响访问趋势，看不到单个来源的变化。 | 默认保留排行。在同一卡片展开时间明细，选来源，用顶部已查询的小时、天、周或月查看 PV 和 UV。沿用现有表格及深色金边控件。 |

来源范围与排行一致，取选定页面、日期范围内浏览量最高的十个来源。北京时间分段，周一为每周起点。整段和各时段的访客数分别去重。没有浏览的时段显示零，旧版接口缺少明细时提示暂不可用。

## 查看与验证

[本地交互稿](req216-analytics/index.html)使用隔离数据库生成的样本，与站内看板共用来源与事件的显示代码。选择「天」，展开「按时间查看」，选择 ngabbs.com 后用「较早」回看。[改动前](req216-analytics/before.png) · [改动后](req216-analytics/after.png)

- Chrome 打开本机应用的「数据中心 → 访问统计」，使用测试管理员身份和隔离库响应，实点自定义日期、查询、按时间查看、来源切换及翻页。四种粒度均已验证。同次查询内切换来源与翻页均为零额外请求。浏览器使用纽约时区时，自定义日期仍按北京时间查询。
- PostgreSQL 从上一版函数升级并重复执行 SQL 61。原排行、区间总数及趋势与升级前一致，另验跨日回访、同账号多访客标识、前十名、页面筛选、零浏览时段和普通用户无执行权限。仅有操作事件的区间仍展示事件榜。
- 页面显示名与服务端允许采集的 15 个事件逐项对照。新前端遇到旧接口仍可展示原有合计，并提示明细暂未就绪。
